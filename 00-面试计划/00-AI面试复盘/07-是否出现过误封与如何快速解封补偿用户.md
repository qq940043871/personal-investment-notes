# 07 · 是否出现过误封，如何处理的？怎么快速解封并补偿用户

> **性质**：AI 面试复盘沉淀件（一问一文件）。2026-11-26 收录，按真实项目经历口径撰写。
> **原题**：是否出现过误封的情况，是如何处理的？怎么快速解封并补偿用户？

> **证据等级（先分清再说）**
> - 【实证·现状】**项目里没有自动封禁机制**——现状只有 `HandlerController` 20 道校验的逐道拒绝、`RiskProcessor` 拦截、一键熔断 `SysPara["40310"]`，没有任何"封 N 分钟/拉黑主体/自动解封"的运行时动作；全库也**查不到一次误封事故记录**。唯一称得上"快速恢复"的实证是**配置化回退**：每道校验都有「全局开关 + 协议级 Map」，可以按协议关掉某道校验；`RiskProcessor` 也是 `Security.Risk.enable` 开关控制。审计流 `1018_APP_LOG` 可回查谁在何时被哪道校验拒了。
> - 【设计态】11 号文档 §6.4 处置阶梯（告警→限流 429→临时封禁 **15 分钟自动解封**→黑名单**人工解封 + 申诉通道**）、§6.5 误伤防护（白名单豁免、新阈值灰度观察期、双信号才封、429 可读文案、大客户同步通知值班）、§9.3 midmon 看板"误伤申诉数 > 0 即复盘"、阈值按实测分布校准——**全是方案与规范，不是现状实现**。
> - 【通用·外部方案】用户主动触达、服务信用分补偿、补偿券/优先通道、逐笔对账纠正——**本人项目没有误封补偿流程**，库里"补偿"一词全部指 Saga 事务补偿与 Agent 副作用补偿，与误封无关，不许偷换。

---

## 0. 一句话口径（先背这句）

> 先拆问题前提：我们**没有自动封禁**，所以没有"误封后怎么解封"这类事故——真要问我见过吗，答案是没见过，因为没有能自动封的东西。真实会发生的是**误拦**：配置开关配错、协议级 Map 漏配、风控规则误判，把合法客户挡在门外。这种我们靠**配置回退**恢复——按协议关掉那道校验，秒级生效，不需要"解封"。至于用户补偿，项目里没有专门的误封补偿流程；体系上设计的是申诉通道 + 人工解封 + 误伤数 > 0 即复盘，主动触达和信用补偿属于通用方案，我不会说成自己做过。

---

## 1. 第一步：先拆穿"封"这个前提（这题最大的坑）

面试官问"有没有误封过"，真正想听的不是故事，是**你知不知道自己系统里到底有没有"封"这个动作**。

| 层级 | 有没有"封" | 具体是什么 |
|------|-----------|-----------|
| 【实证·现状】 | **没有自动封禁** | 请求被拒是**当场拒绝**（`HandlerException` + 拒绝码），不是"先放进来再封号"；`RiskProcessor.process()` 返回 false 也只是拦这次请求；`40310` 一键熔断是全站开关，不是针对主体的封禁 |
| 【设计态】 | 规划了四档 | 告警 → 429 限流 → 临时封禁 15 分钟自动解封 → 黑名单人工解封 + 申诉通道（11 号 §6.4） |
| 【通用方案】 | 常见产品形态 | IP 封禁、账号封禁、设备指纹封禁、验证码二次验证 |

> **答法**：被问"你们误封过吗"——"没有自动封禁，所以没有封禁误伤这类事故。我们现阶段的误伤风险在**误拦**上，就是合法请求被校验规则挡掉。这个我有处理办法，但跟'解封'是两件事。" 这句话直接把问题的地基掀了，比硬编一个误封故事安全一万倍。

---

## 2. 真正会发生的是"误拦"（实证）

现状能导致合法用户被挡的三类原因：

| 原因 | 表现 | 证据 |
|------|------|------|
| 配置开关/协议级 Map 漏配或配错 | 某协议被某道校验挡住，其他协议正常 | 每道校验「全局开关 + 协议级 Map」，可回查配置 |
| `RiskProcessor` 规则误判 | `该请求已被拦截！`，合法高频撞上规则 | `Security.Risk.enable` 开关 + 四维规则 |
| **前端/调用方变更未同步契约** | 参数校验失败率突增 | midmon 契约健康度看板的典型判读——**这是最常见的一类，先查自己人，别当成攻击** |

> 第三类是"误拦"的头号来源：字段名改了、类型变了没同步契约，看起来像扫描器在乱打，实际是自家前端发版。**上来就加封禁力度，封的是真客户。**

---

## 3. 快速恢复：配置回退（实证）≠ 自动解封（设计态）

| 手段 | 【实证·现状】 | 【设计态】 |
|------|-------------|-----------|
| 单点恢复 | **关掉那道校验的全局开关，或在协议级 Map 里摘掉该协议**——秒级生效，不用发版、不用重启 | — |
| 主体恢复 | 无自动封禁，主体层面无需解封 | 临时封禁 15 分钟自动解封；黑名单人工解封 + 操作审计留痕 |
| 全局止血 | `SysPara["40310"]=1` 一键熔断（发版维护用） | midmon 三级预警 + 自动熔断 |
| 定位依据 | `1018_APP_LOG` 审计流（谁/何时/什么协议/结果/IP），能反查是被哪道校验拒的 | 误伤申诉数 > 0 即复盘 |
| 告警文案 | `HandlerException` + 统一错误码信封 | 429 + "系统繁忙，请稍后重试"（可读文案，不返 500 或空白） |

> **面试话术**：被追"你们怎么快速解封"——"严格说没有'解封'这个动作，因为没有自动封禁。我们恢复误拦靠的是**配置回退**：每道校验有全局开关和协议级 Map，发现误拦就把那道校验对该协议关掉，秒级生效。这比'封了再解'利索得多——**能不封，就不需要解**。"

---

## 4. 补偿用户：项目里没有专门流程（诚实拆分）

这是全题最薄的一块，也是最容易翻车的一块——**全库"补偿"一词都是 Saga 事务补偿 / Agent 副作用补偿，跟"误封用户补偿"毫无关系**。

| 层面 | 状态 | 能说什么 |
|------|------|---------|
| 误封补偿流程 | 【实证】不存在 | 没有自动封禁 → 没有误封补偿流程；不编 |
| 申诉通道 | 【设计态】 | 11 号 §6.4 黑名单人工解封 + 申诉通道；§9.3 误伤申诉数 > 0 即复盘 |
| 受影响请求补救 | 【实证·有限】 | 请求是当场拒绝的，**没有产生业务副作用**，所以不存在"回滚已执行业务"的问题；重复提交有 Greencard 幂等卡（≤4 次复用）保证重试不重复发卡 |
| 主动触达 / 信用补偿 | 【通用方案】 | 客服主动通知、服务信用分、补偿券/优先通道——外部产品做法，本人项目无实战 |

> **关键论点**：我们现状是**前置拒绝**，坏请求在进业务层之前就被挡了，**没有产生需要补偿的业务状态**——这是"拒绝要早"带来的额外红利。真正需要补偿的是"放进去之后才发现问题"的场景（Saga 事务补偿），那是另一套机制，别跟误封混为一谈。

---

## 5. 防误伤怎么做（设计态，讲清是方案）

11 号 §6.5 的误伤防护五条，面试时按"体系上我们规划"的语气讲：

- **白名单豁免**：内部服务互调、健康检查拨测、监控探针、办公出口 IP 不参与自动封禁（注意是**豁免自动处置**，不是免检免审计）；
- **灰度观察期**：新阈值上线先只告警不拦截，跑满一个业务周期（含高峰）再切拦截；
- **双维度校验**：至少两个信号同时成立才封，单信号只告警 + 计信誉分；
- **可读文案**：被限流返 429 + "系统繁忙，请稍后重试"，不返 500 或空白；
- **大客户保护**：机构客户触发限流必须同步通知值班，不能静默降速影响交易。

> 一句话点透：**防误伤比防攻击更难**——攻击让你丢钱，误伤让你丢客户，而且误伤的投诉会第一时间到大老板耳朵里。

---

## 6. 项目版 90 秒速答

> 先说前提：我们系统里**没有自动封禁**，所以没有"误封后解封"这类事故——这个我得老实讲，不能给你编一个。现状是前置拒绝：20 道校验逐道拒，`RiskProcessor` 拦截，`40310` 一键熔断是全站开关，都不是针对主体的封号。
>
> 真会发生的是**误拦**，最常见的是前端或调用方改了字段没同步契约，参数校验失败率突增，看着像攻击其实是自己人。这种我们的恢复办法是**配置回退**——每道校验有全局开关加协议级 Map，按协议关掉那道校验就秒级恢复，不用发版不用重启；`1018_APP_LOG` 能回查是谁在什么时候被哪道校验拒的。严格说没有"解封"这个动作，因为根本没封——**能不封，就不需要解**。
>
> 补偿这块项目里没有专门流程，但有个结构性的好处：我们是前置拒绝，请求在进业务层之前就被挡了，**没产生需要补偿的业务状态**。设计上规划的是申诉通道加人工解封、误伤申诉数大于零即复盘、双信号才封、新阈值先灰度观察一个业务周期。主动触达和信用补偿是通用产品做法，我没做过，不会说成战绩。

## 7. 追问预案（带证据等级）

| 追问 | 回答要点 |
|------|---------|
| 你们真有自动封禁吗？ | 【实证】没有；只有当场拒绝 + 一键熔断，封禁阶梯是设计态 |
| 那"误封"是不是就没发生过？ | 是，因为没有能自动封的机制；误拦发生过，靠配置回退解决 |
| 配置回退会不会把坏人一起放了？ | 会，所以是止损优先：先恢复合法客户，再查规则；全局/协议两级粒度控制爆炸半径 |
| 15 分钟自动解封上线了吗？ | 【设计态】没有；11 号 §6.4 方案，不是现状 |
| 误伤的怎么补偿？ | 【实证】前置拒绝无业务副作用，不存在回滚；【设计态】申诉通道 + 人工解封；【通用】主动触达本人无实战 |
| 怎么知道是不是误伤？ | 【实证】`1018_APP_LOG` 回查 + 契约健康度看板判读；【设计态】双信号校验、申诉数 > 0 即复盘 |
| 前端改字段导致大面积 400 怎么办？ | 【实证】按协议关掉参数校验那道校验先恢复，再同步契约；**别当攻击封人** |
| 大客户被误拦了怎么处理？ | 【设计态】机构客户触发限流同步通知值班；【实证】配置回退按协议粒度恢复 |

## 二、异构架构与 C 撮合（最高频）

| # | 问题 | 回答要点 | 出处 |
|:--:|---|---|---|
| B1 | 你们的撮合系统怎么设计的？ | C 撮合引擎（单线程内存撮合、O(logN) 排序树）+ Java 桥接 SDK（协议封装/连接管理/熔断限流）；C 保延迟确定性，Java 保业务编排灵活性 | 06 §1.2 / §1.3 |
| B2 | 为什么不全部用 Java 微服务？ | GC 停顿 + JVM 预热让撮合延迟不可控；这是用可维护性换确定性的明确取舍 | 02 §4 / §10 Q11 |
| B3 | Java 和 C 怎么通信？ | TCP Socket + 自定义二进制协议；Java 侧桥接 SDK 管连接池/超时/熔断/重试；撮合结果**异步落库** | 06 §1.3 |
| B4 | 你怎么管一个你不熟的 C 模块？ | 不读 C 代码也能控局：接口契约 + DS 熔断限流管住爆炸半径 + 桥接层日志指标（飞行员不必会修发动机，但要读懂仪表盘） | 02 §10 Q12 / 06 §4 |
| B5 | DS 数据中心和交易核心什么关系？ | DS = Java 桥接 / 防腐层（ACL），把 C 的二进制协议翻译成 Java 能消费的接口与领域事件；异构复杂度全部收敛在 DS | 06 §1.3 |
| B6 | 为什么用 Hessian 不用 JSON？ | 撮合是高频二进制交互，Hessian 序列化/解析开销远低于文本协议，跨语言友好、体积小 | 02 §10 Q8 / 06 §2.3 |
| B7 | 多模式交易的撮合一致性怎么保证？ | Java 侧规则配置引擎把挂牌/竞价/询价/基差规则翻译成 C 引擎标准指令序列，新增模式不改 C 代码 | 02 §10 Q14 |
| B8 | 这种异构架构的竞争优势在哪？ | 别人会 Spring Cloud，我经历过"为什么有些东西不能用 Java 做"；并管过 C 团队 + Java 团队的异构协作 | 02 §2 / 06 §0 |

## 三、分层细节追问（一层一坑）

| # | 问题 | 回答要点 | 出处 |
|:--:|---|---|---|
| C1 | 为什么分三类终端？ | B2B 客户差异极大：中小企业要"快速下单"，机构要"资金风险 + 数据决策"，混在一起必臃肿 | 02 §9 |
| C2 | 网关用什么技术？ | midservice1/2/3 自研 Java Web（鉴权/限流/租户路由/请求日志）+ midmon 自建监控面板，多实例部署 | 05 §0.1 / §1.1 |
| C3 | 网关挂了怎么办？ | 三道防线：多实例 + 健康检查自动剔除 → midmon 触发熔断限流降级 → 静态兜底页 + 关键读降级到缓存 | 02 §10 Q3 / 05 §2.5 |
| C4 | MySQL 怎么保证一致？ | 业务库共用一个 MySQL 实例、按领域垂直分 schema；部署上一主一从读写分离：主从复制 + 半同步 + 应用层幂等兜底 | 02 §10 Q15 |
| C5 | MinIO 存了什么？ | 合同 PDF、仓单扫描件、质检报告、发票影像——全是履约凭证；另有文件服务统一管上传下载与权限 | 02 §9 |
| C6 | 外部接口超时怎么处理？ | 统一 SDK 管限流 / 重试 / 熔断 / 超时，调用异步化（异步回调 + 状态机）+ 日终对账兜底 + 失败转人工 | 02 §10 Q18 / 05 §2.5 |
| C7 | 创新挂牌和自由竞价的区别？ | 挂牌 = 明盘报价、先到先得；竞价 = 价格优先、时间优先撮合 | 02 §10 Q14 |
| C8 | 缓存服务怎么设计的？ | 独立 Java 服务封装 Redis；Canal 监听 binlog 实时刷新；专门加速网页读请求（读多写少），实质是卸 DB 压力 | 02 §10 Q16–Q17 |
| C9 | 多租户数据隔离怎么做的？ | 网关做租户路由（不同客户打到对应隔离空间 / 数据隔离域） | 05 §0.1 / 02 §9 |
| C10 | 可观测性怎么做的？ | midmon 多实例可观测：指标带实例标签、按 traceId 去重；慢协议看 P95 不看平均，告警落四元组（接口 + 实例 + 租户 + 下游） | 05 §0.1 / §1.1（midmon） |

## 四、Socket 长连接接入（由 2 分钟话术反推的题面）

| # | 问题 | 回答要点 | 出处 |
|:--:|---|---|---|
| D1 | 异构系统 Socket 长连接怎么分层设计？ | 三层：传输层可靠投递 / 连接层断线自愈 / 一致性走最终一致 + 对账 | 02 §10 Q9 / 06 §2.3 |
| D2 | 怎么保证消息不丢不重？ | 唯一 msgId + 接收方先落地再回 ACK + 指数退避重发 + Redis SETNX 去重 | 02 §10 Q9 / 06 §2.3 |
| D3 | 断线怎么自愈？ | Netty IdleStateHandler 双向心跳；指数退避 + 随机抖动重连防惊群；按 Redis 里的 offset 断点续传 | 02 §10 Q9 / 06 §2.3 |
| D4 | 为什么不做强一致？ | 异构系统强一致代价太高；ACK + 幂等解决 99.9%，定时对账 + 日终全量对账兜底 0.1% | 06 §1.1 / §2.4 |
| D5 | 对端挂了怎么办？ | 熔断降级 + 消息暂存待发队列 + 恢复后回放；服务无状态化（状态存 Redis）可水平扩展 | 02 §10 Q10 |

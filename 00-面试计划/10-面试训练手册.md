## 1. 心态：只准备三个主场

### 1.1 先破三个心魔

| 焦虑 | 为什么不用怕 |
|---|---|
| 会问没听过的技术？ | 面的是技术 **Leader** 不是技术**专家**；考的是决策力、治理能力、业务理解、团队管理 |
| 问到盲区怎么办？ | 面试是双向选择；敢说"这块我不深，但我有另一种思路"比硬撑强 100 倍 |
| 要准备的太多 | 只需练熟三个主场，其余是客场，客场**不求赢、不丢分** |

### 1.2 三个主场（必须脱口而出）

| 主场 | 为什么稀缺 | 必须背下来 |
|---|---|---|
| **驾驭异构架构** | 90% 的 Java 经理只会 Spring Boot 全家桶 | 四层架构 / 双核驱动（C 撮合 + DS 防腐层）/ C↔Java 走 TCP 自定义二进制、Java↔Java 走 Hessian |
| **技术+业务双修** | 大多数技术经理讲不清业务全链路 | 五大业务模块 / 客户价值三层（效率·风险·增长）/ 五道壁垒 |
| **技术操盘手** | 从救火队长转成建机制的人 | 靠制度管人、台账管债、流程管风险；On-call 轮值 / 技术债台账 / 复盘不追责 |

**主场三的故事（90 秒）**：接手时是救火队长 → 建 On-call 轮值（逼系统暴露真问题）+ 建技术债台账（把隐性坑显性化）+ 推复盘不追责 → 半年救火时间大幅下降，冬储整季零 P0。

### 1.3 客场生存法则（约 30% 的题）

| 题型 | 策略 |
|---|---|
| 知识盲区 | "这块我不深，但类似场景的核心考量是 X 和 Y" + 平移思路 |
| 假设开放题 | 套已有框架：先分层 → 再定边界 → 再讲 trade-off |
| 行为面试 | 永远 PEARL，讲真实发生过的事 |
| 压力题 | 真实弱点 + 已在做的改进，不说假弱点 |

**把客场拉回主场**：问 A/B 测试 → "我们没做 A/B。但多租户下我们用规则引擎 + 场景化配置做个性化——光合同交收就分先合同后款/先款后合同，100+ 客户各有计费与风控阈值，5 分钟改规则生效，底层逻辑是一样的。"

### 1.4 差异化武器库（随时可调用）

| 武器 | 引爆时机 | 一句话 |
|---|---|---|
| DS 防腐层 | 聊架构/微服务 | "C+Java 异构，中间靠 DS 数据中心做防腐" |
| TCP 自定义报文 | 聊协议/性能 | "C 和 Java 之间没用通用协议，自己定了二进制报文" |
| 三年零差错 | 聊质量/稳定 | "大宗交易容错率是零——三年没有一笔资金差错" |
| 交收场景化引擎 | 聊扩展性/多租户 | "参数要爆炸，我把它收敛成交收场景，运营按场景选、不裸调参数" |
| 冬储零 P0 | 聊高并发/大促 | "冬储流量涨 5-10 倍，第二年整季零 P0" |

## 2. 叙事：前 5 分钟定生死

### 2.1 第一击｜30 秒定位（四锚点自检）

| 锚点 | 口径 | 要点 |
|---|---|---|
| 年限结构 | 13 年 = 前 2 年金融级清算 + 后 11 年本司 | 自己先说破，别等面试官算账 |
| 团队规模 | 20 人 = 3 C 内核 / 6 Java 中台 / 5 Vue 前端 / 5 测试 | 结构必须脱口而出 |
| 汇报对象 | 向总经理汇报 | 一句带过 |
| 目标岗位 | 技术专家 / 架构师 / 技术管理 | **决定前三句怎么挑** |

> 逐字稿唯一权威版本：`02-项目叙事-B2B.md` §0（30 秒版 / 3 分钟版）。

### 2.2 第二击｜2 分钟架构速写（边画边讲）

接入层（PC+移动+大屏三端）→ 网关层（自研 Java Web，鉴权/限流/路由）→ 业务中台（管理系统 10+ 模块 + DS 数据中心桥接 + C 撮合引擎）→ 数据层（MySQL 主从 + MinIO + Kafka）→ 外侧 9+ 外部系统（银行/仓储/物流/CTRM/税务/企查查/签章/短信/证书）。

### 2.3 第三击｜反抛一个问题

> "您可能好奇 C 撮合引擎和 Java 之间怎么通信——我们没用通用协议，是 TCP 自定义二进制报文。您想先听这部分设计，还是先看业务层？"

### 2.4 三个必杀问题（都按三层答）

| 问题 | 三层答法 |
|---|---|
| **为什么 C 撮合不迁 Java？** | ①技术事实：单线程内存撮合、无 GC 停顿、纳秒级且确定；②决策：不是不能迁，是不值得——迁移要重验全部撮合逻辑，测试成本巨大收益为零；③管理：正因为我不懂 C 代码，我才更盯它的可观测性，建 DS 防腐层——**我管的是引擎健康，不是 C 代码** |
| **和找钢网/1688 的本质区别？** | ①重度垂直而非通用平台：一个订单几百万、履约链条极长；②壁垒不是技术是**数据 + 集成深度**：定价模型、100+ 客户磨出的配置化规则、9+ 外部系统的技术适配与商务关系，是时间垒的 |
| **你最大的失败？** | 第一年冬储撮合挂了 5 分钟——不是技术问题，是我没做容量规划与应急预案；学到的是"建体系"而非"修 bug"；之后建冬储 SOP + On-call + 技术债台账，第二年零 P0 |

### 2.5 收尾钩子（提问即自我总结）

- "团队现在最大的技术债是什么？如果我来，前 3 个月你最想让我解决什么？"
- "技术团队和业务团队的协作模式是怎样的？我建过一套跨团队契约治理机制，这里需要吗？"
- 终极钩子："今天聊下来，我感觉你们在（某方面）是个挑战。上一家公司遇到过类似情况，我们的解法是（一句）。需要的话我可以就这个方向再准备。"

## 3. 三套框架（全库唯一定义处，其他文件只引用）

### 3.1 PEARL（默认主框架，所有经历/深挖题都用它）

| 字母 | 含义 | 打法 |
|---|---|---|
| **P**roblem | 问题 | 带数字："冬储期日均 1000 笔暴增到 8000 笔" |
| **E**vidence | 有多严重 | "撮合 CPU 冲到 92%，差点崩，交易挂起 5 分钟" |
| **A**lternatives | 比过哪些方案 | "加机器（不管用）/ 拆服务（风险大）/ 分层降级（可行）" |
| **R**easoning | 为什么这么选 | "C 是单线程的，加机器没用，只能把非关键链路降级" |
| **L**esson | 沉淀 | "建了冬储预案 SOP，第二年零 P0" |

> 比 STAR 锋利在：E 给真实感、A 给决策思维、R 给 trade-off、L 给复盘力。

### 3.2 BOUNDARY（答"我不熟的模块"）

| 步 | 动作 | 示例 |
|---|---|---|
| **B**oundary | 坦诚边界 | "撮合算法不是我的深度区，我负责它与 Java 层的协作边界" |
| **O**wnership | 说清责任 | "但它的可观测性、协议契约、故障演练是我的 Owner 职责" |
| **M**echanism | 给机制 | "建了 DS 防腐层统一收口二进制协议，并补齐指标告警" |
| **R**esult | 可量化结果 | "协议变更从改 N 处降到改 1 处" |

> 模板句："这不是我的深度领域，但我通过 **XX 机制** 保障了它与整体的协同——我是这个模块的**接口 Owner**，不是**代码 Owner**。"

### 3.3 SCOPE（答技术选型/trade-off）

Situation 场景 → Constraint 约束 → Options 备选 → Pick 选了什么为什么 → Effect 结果与收获。

**分工**：经历类/深挖类 → PEARL；不熟模块 → BOUNDARY；选型题 → SCOPE。

## 4. 自证：业务五层 × 技术四维

### 4.1 业务理解力五层（每深一层，竞争力指数级上升）

| 层 | 能力 | 你的证据 |
|---|---|---|
| L1 | 知道流程 | 七环：询价、看货、签约、付款、履约、结算、融资 |
| L2 | 知道痛点 | "比价差两分钟价就没了；合同晚三天，400 万的单子飞了" |
| L3 | 知道赚钱逻辑 | 客户所在行业里靠什么赚钱、在哪流血（详见 `04` §4） |
| L4 | 知道角色 KPI | 销售总监看溢价率、财务看账期、风控看敞口、仓管看货权 |
| L5 | 能预判演进 | 五个客户殊途同归走向"交易+物流+金融"产业互联网 |

> **L4/L5 是分水岭**：L1-L3 高级工程师也有；主动展示 L4/L5 直接拉开身位。
> 金句："给贸易商卖生存，给国企卖溢价，给政府卖监管，给平台卖信用——同一套系统，四种价值主张，我是从这个表倒推功能优先级的。"

### 4.2 技术把控力：三个架构代表作（每条按"业务问题→备选→取舍→代价"）

| 代表作 | 业务问题 | 取舍 | 代价 |
|---|---|---|---|
| **合同域与履约域解耦** | 合同变更极频繁（补充协议/增减量/调交期是日常），状态耦合就是每次变更一次数据迁移事故 | 域解耦 + 事件联动，合同留版本链、履约独立演进 | 读写路径变长，跨域一致性只能靠事件 + 对账 |
| **双轨履约引擎** | 交收节奏没有行业标准：先合同后款 vs 先款后合同，国企要强顺序、贸易商要灵活并行 | 顺序轨用状态机换确定性，自由轨用事件驱动换灵活性，共用底层任务数据结构 | 自由轨异常补偿复杂，用规则引擎配置化而非硬编码 |
| **支付渠道适配器** | 平台不能碰资金池（二清红线），各客户银行/持牌通道又不同 | 统一适配器接口 + 渠道插件化，资金预检用 2PC 思路 | 渠道差异要在适配层抹平，对账逻辑每渠道一份 |

### 4.3 四个高概率 Trade-off（张口就来）

| 追问 | 一句话 |
|---|---|
| 为什么不用分布式事务跨域保一致？ | 跨域走事件 + 每日对账；大额资金宁可慢不可锁——但**资金预检这一跳**反而用 2PC，钱不能有中间态 |
| 为什么不用 Activiti/Flowable？ | 工作流擅长"人审批"，大宗履约核心是"货款票三轨状态推进"，人工节点只占三成 |
| 为什么原型阶段不上组件化？ | 1300 页原型诉求是"快验证业务模型"，静态 HTML 双击就能演示；但边界我清楚，正做组件收敛与契约先行 |
| 套保为什么自研不买？ | 敞口计算与现货合同强耦合（点价量/在途量/已点未发/期货头寸要实时轧差），通用风控软件拿不到一手数据 |

### 4.4 工程治理两个真故事（一句话版）

- **接口资产化**：870 个请求、244 个文件夹的手工 Postman 集合 → 写 Python 工具一键重建。"接口文档漂移是协作的第一隐性成本，我把它从负债变成资产。"
- **ICC 重构**：参数从本地配置文件迁到 HTTP 按 deviceId 实时获取，设计本地缓存兜底 + 分环境灰度。"任何去中心化方案必须先设计降级路径，否则是把稳定性问题换成可用性问题。"

### 4.5 技术债三分类（管理成熟度的直接证据）

- **流血债**（影响正确性/资金安全）→ 本迭代必须还
- **放血债**（拖慢交付）→ 排进季度，用"每新增一页放大多少成本"量化给老板
- **美容债**（风格不统一）→ 顺手还，不立项

> 金句："技术经理的价值不是消灭所有技术债，是让团队知道哪些债在吃利息、哪些债可以先欠着。"

### 4.6 杀手锏：业务语言 → 技术方案翻译表

| 客户原话 | 业务实质 | 技术翻译 |
|---|---|---|
| 价格天天变，报价跟不上 | 期现联动定价，人工调价滞后行情 | 跟盘调价规则引擎 + 四种定价模式（固定/浮动/基差点价/公式） |
| 钱打过去了，对方不认账 | 到账不可见，信任死结 | 收付款单 + 资金池核销记账 + 到账状态同步卡履约状态机 |
| 点了价又怕行情反着走 | 基差交易的敞口风险 | 敞口实时轧差 + 期货头寸绑定 + 限额分级预警 |
| 这货到底是谁的 | 货权不清，一女二嫁 | 电子仓单 + 货权流转留痕 + 质检报告扫码溯源 |
| 合同改了八版，谁说得清 | 版本混乱引发扯皮 | 合同版本链（原合同 + N 补充协议）+ 全程留痕 |
| 月底对账对到吐血 | 四流割裂，手工核验 | 单据自动勾稽，合同额/实付/已结算/待结算差异标红 |
| 领导要看数据，我攒一周报表 | 数据散在各子系统 | 决策驾驶仓，四流数据一屏透视 |
| 老供应商靠谱，新面孔不敢碰 | 陌生人交易信任成本高 | 履约率/成交记录/评价的信用档案体系 |

> 用法：任何业务问题都按"客户说 X → 实质是 Y → 我们用 Z"，三段同时在证业务理解与技术水平。

### 4.7 高光问答五连（结论先给）

| 问 | 结论 |
|---|---|
| 怎么定位技术经理？ | 三个词：**翻译**（业务语言↔架构/成本）、**拍板**（两条路都对时选可回退的）、**兜底**（先恢复业务再复盘，不甩锅） |
| 需求急但架构不允许？ | 先问"急的是结果还是功能"；给分层方案（80% 先上线 + 技术代价记账）；**妥协可以，但必须被记录、被定价** |
| 怎么让团队懂业务？ | 新人下现场 / 需求评审讲钱 / 业务术语表进代码（仓单就叫仓单，不叫 inventory_doc） |
| 举一个业务判断救了技术方案的例子？ | 双轨引擎：纯流程引擎的技术方案被我否掉——**履约节奏不存在行业标准**，这判断来自看客户干活，不是技术博客 |
| AI 要不要 all in？ | 场景成熟度决定投入度：智能推荐/单据识别/风控辅助用 AI，资金操作与合同生效只提示不决策——**用 AI 的前提是知道它何时不可靠** |

### 4.8 人设一致性（全程一个信号：懂业务的决策者）

自我介绍=业务导向的技术管理者 → 讲产品=客户价值不是功能清单 → 讲架构=每个设计先说业务动因 → 被追问=trade-off 张口就来 → 讲管理=机制化不是口号 → 讲未来=业务趋势+技术预判合一 → 反问=准高管视角。

**成果归属口径**：整体用"我们团队/我们承建"；具体模块用"我负责/我拍板"。主动暴露有规划的技术债 = 有判断力。

### 4.9 研发管理自证（先给机制，再甩证据）

| 方向 | 一句话口径 |
|---|---|
| 年度规划 | 架构重构**降交付成本** / 安全合规**过准入门槛**（对标等保三级）/ 稳定性**守大额交易底线**（重大故障 ≤1 次/年、首页 <1.5s、核心并发 ≥1000/s）/ AI **要增量效率** |
| 规范体系 | 需求-设计-开发-测试-发布-移交全流程强制评审，有表有记录有闭环 |
| 项目管理 | 需求池/已评审/开发中三态看板 + 排期表，进开发必过评审，上线必过 QA 与发布评审 |
| 团队赋能 | 常态化技术分享 + 排障复盘（CPU 异常定位等）+ 低代码与可视化规范研读 |
| 稳定性 | 故障报告机制 + 复盘（原因/责任人/改进/预防），从"救火"变"持续改进" |
| 效能目标 | 评估节省工作量 ≥5 人月；自动化测试覆盖率 ≥20%（口径一律"当时设定的目标"） |

> 收束句："交付只是底线，**机制**和**资产**才是 leader 的产出——技术管理的关键是把个人经验变成团队能力。"

## 5. 七问叙事链（万能结构）

### 5.1 七个问题

| # | 问题 | 考什么 | 时长 |
|---|---|---|---|
| Q1 | 一分钟说清产品：是什么、服务谁、核心价值一句 | 抽象概括、业务高度 | 60-90s |
| Q2 | 目标客户是谁？典型业务与决策特征 | 画像颗粒度、是否真懂客户 | 90s |
| Q3 | 行业痛点？按业务链路讲、带真实场景 | 实战认知 vs PPT 认知 | 2-3min |
| Q4 | 产品怎么解决？讲核心架构与关键设计 | 方案与痛点的映射力 | 3min |
| Q5 | 现在还遗留哪些问题？你的解决思路 | 技术判断力、诚实、规划 | 2-3min |
| Q6 | 你实际解决了哪些关键问题？具体案例 | STAR 验真、领导力 | 90s×2-3 |
| Q7 | 给你三个月/半年，优先做什么？为什么 | ROI 思维、优先级、管理视角 | 2min |

> 口诀：**一客户二痛点三方案，四战绩五规划**——Q1/Q2 讲"是谁"，Q3/Q4 讲"值不值"，Q5/Q6/Q7 讲"你行不行"。
> 底稿与数字见 `02-项目叙事-B2B.md`、`04-业务与客户价值.md`。

### 5.2 潜台词对照（回答要对着这一列说）

| 他问 | 他其实在问 |
|---|---|
| 产品是什么 | 能不能用人话讲清，而不是背功能清单 |
| 客户是谁 | 你跟真实客户打过交道，还是对着原型自嗨 |
| 行业痛点 | 搬运文章，还是亲眼见过客户骂街 |
| 怎么解决 | 方案是不是你做的，能不能画图讲 trade-off |
| 现存痛点 | 有没有自我批判，敢不敢说自家产品坏话 |
| 你干了什么 | 简历上哪些是你干的、哪些是团队的 |
| 准备怎么干 | 决策是拍脑袋还是有方法论 |

### 5.3 各问核心要点（浓缩）

- **Q1**：全链路闭环——"让签了合同之后的事全部线上化、可信化、金融化"；差异点是**深入履约层**（交收/资金/票据/仓单），这是金融能做起来的前提。
- **Q2**：四类客户（贸易商 / 核心企业工厂 / 生态服务方 / 平台运营方）；四个特点：金额大决策链长、依赖线下关系、资金敏感、参与方多单据杂。
- **Q3**：七环各一个真实后果（询价多花 70 元/吨、看货白跑 300 公里、合同晚三天丢 400 万、预付拖两天错过涨价、交收节奏对不上靠扯皮、对账靠翻凭证、仓单不清融不到资）。**共同根因：商流/物流/资金流/信息流在线下是割裂的。**
- **Q4**：先给"痛点→产品能力→子系统"映射，再深挖两个：合同域与履约域解耦、双轨履约引擎（顺序轨状态机 / 自由轨事件驱动 / 共用任务数据结构 / 五种交收模式叠加）。
- **Q5**：五个真痛点都带解法（原型与生产鸿沟 / 图表库不统一 / 自由轨复杂度 / iframe 集成脆弱 / 跨域一致性待验证）；话术顺序：先说验证对的部分 → 再说技术债 → 收在优先级判断。
- **Q6**：STAR 五故事——河南能源双平台（1.1 亿吨、673 亿、溢价 8 亿、采购 20 天→7 天）/ ICC 参数重构 / 接口资产自动化 / 期货套保风控 / AI 工程化。**R 必须有数字，A 必须有一个"我拍板"的决策**。
- **Q7**：先止血（组件库+契约+自动对账）→ 再还债（履约 trace、微前端验证、司机端闭环）→ 后增值（供应链金融做深 + AI 试点）。收尾："先保证数据可信，再谈金融增值——信任是这个行业的货币。"

## 6. 训练：5 天冲刺

| 天 | 主题 | 任务 | 自检 |
|---|---|---|---|
| D1 | 叙事链打底 | 背 Q1（60s+90s）；通读 Q2-Q4；抄一遍七环痛点 | 对镜 60 秒不卡壳；七环能默写 |

| D3 | 自我批判与规划 | 精练 Q5/Q7，写一版自己的三个月优先级并录音 | 每个痛点顶住两轮追问 |
| D4 | STAR 打磨 | 选 3 个故事写 200 字卡片，各录 90 秒 | S:A:R ≈ 1:4:2，无流水账 |

### 6.2 追问库（15 条）

**业务**：①大宗与普通 B2B 本质区别（非标/大额/长周期/价格风险/信任成本）②与找钢网/欧冶差异（履约层深度+金融闭环）③参数配置为什么改成场景化（参数组合失控，场景=参数+校验+状态流转）④两轨客户怎么选、选错怎么办（轨间切换策略）⑤平台"鸡生蛋"怎么破（核心企业/园区切入 + 金融做钩子）。
**架构**：⑥双轨共用数据结构怎么防污染 ⑦事件驱动消息丢了/重了（幂等键+对账兜底+trace 回放）⑧资金预检 2PC 与 TCC/Saga 的取舍 ⑨签章/CA/存证合规链路 ⑩仓单防造假（电子仓单+货权留痕+批次溯源+监控）。
**管理**：⑪团队规模/分工/评审与技术债管理 ⑫与技术骨干的意见冲突 ⑬工期估算与延期处理 ⑭业务紧急性 vs 架构长期性 ⑮为什么离开（落在"追求更大业务纵深"，不抱怨）。

> 技术类追问（C 引擎、MySQL、网关、缓存、MQ、CI/CD 等 15 条）见 `12-系统架构高频问题清单.md`，两表不重叠。

### 7.2 前 10 分钟速查

- **业务**：价值三层（效率/风险/增长）｜四种价值（信任中介/信息聚合/交易效率/金融服务）｜五道壁垒（数据飞轮/配置引擎/外部集成/复合人才/信任资产）
- **架构**：四层 + 双核（C 撮合纳秒级 + DS 防腐层 Hessian/Socket）+ 9+ 外部系统

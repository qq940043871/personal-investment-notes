# 04 · 业务与客户价值（D2 / D11）

> **排期**：D2（项目 · 链路与职责里的"业务背景"）+ D11（系统设计口述 + 业务题）
> **依据**：`04-备战手册/00-平台定位与价值总纲.md`（唯一权威口径）+ `01-产品定位/`（10 份）+ `02-业务价值/`（4 份）+ `03-客户案例/`（手册 31KB + 复盘 35KB）
> **本件定位**：业务题不是背术语，是**用客户的账算给他听**。面试官（尤其业务面 / 总监面）只关心三件事：**你懂不懂客户怎么赚钱、你的系统怎么帮他赚、你能不能说清代价**。

---

## 0. 一句话定位（背下来，所有业务回答都从这句展开）

> 面向大宗商品产业链的**全链路数字化交易与合同履约平台**，覆盖钢铁、矿石、化工、农产品、能源等品类，把"**线上交易 → 电子签约 → 物理交割 → 资金结算 → 金融增信**"串成一条。
>
> 核心判断：平台价值来自一件线下做不到的事——**把交易、物流、金融三方产生的真实数据沉淀到同一套合同与履约底座上，再转换成资金方敢采信的信用。**

---

## 1. 60 / 180 秒业务速答

### 1.1 60 秒（被问"你做的这个平台是干什么的"）

> 一句话：**大宗商品的线上交易 + 合同履约平台**。
> 谁在用：上游矿山钢厂要卖货、中间贸易商要周转、下游工厂要买原料，再加上仓储、金融、质检、平台运营，一共**七类角色**，登录后看到的工作台都不一样。
> 解决什么：大宗交易的核心障碍不是"找不到货"，是**不敢跟陌生人做大额交易**——付款和发货谁先？仓单是真的还是假的？数据通不通？所以 26 个痛点往上收，落点就一个字：**信任**。
> 值多少：单笔交易从 5 天压到 1.5 天、对账从 3 天到 2 小时、融资成本从年化 18% 降到 8–10%。
> 技术上它是**双核**：Java 业务中台 + C 单线程撮合，中间用 DS 数据交换中心做异构桥接。

### 1.2 180 秒（被问"详细讲讲业务"）

> 按五层讲：**三条主线**（电子交易 / 现代物流 / 供应链金融，三位一体）、**四件套**（现货商城 / 基差点价 / 供应链金融 / CTRM）、**交易设计**（6 种交易方式 × 4 档周期 × 7 项服务，必须配置化）、**四类资产 × 五类资金方**（仓单 / 合同 / 订单 / 债权，覆盖存货、垫资、预付、挂账四段资金需求）、**七类角色 / 15 个系统角色 / 9+ 外部接口**。
> 技术上最根本的一处设计是**合同与履约解耦**：合同域只记录商业契约，履约域按交收模式动态生成执行计划——新增一种交收模式，合同核心代码不动，只加一个履约策略实现。
> 这一条可以引申到"为什么你们能支持 6 种交易方式 × 5 种交收模式"——因为模式是策略，不是 if-else。

## 2. 五层结构（被要求"画一下业务全景"）

| 维度 | 构成 | 为什么必须放在一起 |
|---|---|---|
| 三条主线 | 电子交易 · 现代物流 · 供应链金融 | 交易产生数据、物流确认真实、金融放大信用 |
| 四件套 | 现货商城 · 基差点价 · 供应链金融 · CTRM | 商城找货、点价锁价、金融供钱、CTRM 管风险 |
| 交易设计与服务 | 6 种交易方式 × 4 档交易周期 × 7 项服务 | 模式与周期正交，必须配置化 |
| 金融资产 | 仓单 / 合同 / 订单 / 债权 × 5 类资金方 | 覆盖存货、垫资、预付、挂账四段 |
| 生态规模 | 7 类角色 / 15 个系统角色 / 9+ 外部接口 | 商流在线、物流在网、资金在监管 |

支撑设计（一句带过，细节在 `02`）：7 个限界上下文、约 14 个领域事件（EDA，发布方不感知消费方）、履约引擎双轨（顺序交收走状态机 / 自由交收走事件驱动 + 规则引擎，5 种交收模式）、资金三层解耦（计划"何时付" / 结算"付多少" / 支付工具"怎么付"，银行 100% 存管）。

## 3. 七类角色 × 三类客户（业务题最常见的第一问）

| 角色 | 链上位置 | 最关心 | 平台入口 |
|---|---|---|---|
| 上游资源方 | 矿山 / 钢厂 / 炼厂 / 种植户 | 高效挂牌、价格发现、收款安全、长协锁价 | 挂牌定价、款项保障 |
| 贸易商 | 批量采购与拆分销售 | 仓单流转、资金周转、链式合同（A→B→C→D）权责 | 购销库存、保理周转 |
| 下游终端 | 加工厂 / 建筑 / 制造 | 原料与货期匹配、长协对冲、品质保障 | 采购比价、质检异议 |
| 仓储物流 | 交割仓 / 监管仓 / 承运 | 仓单注册注销、实物与电子同步、仓储费 | WMS 对接、出入库 |
| 金融机构 | 银行 / 保理 / 供应链金融平台 | 质押物监控、授信数据、放款线上化 | 质押监控、风控数据 |
| 质检机构 | SGS / CCIC 等 | 报告出具与采信、委托结算 | 委托受理、报告上传 |
| 平台运营方 | 平台公司 / SaaS | 交易监管、风控预警、全局看板 | 监管审核、运营分析 |

**加分点（很多人答不出）**：同一角色在**不同产权性质**的企业里决策逻辑不同——**国企重合规与流程留痕、民企重效率与利润、外企重标准与总部合规**。所以同一功能在三类客户里的**推广话术**不同。问到"你怎么做客户推广/需求取舍"，答这个。

## 4. 26 个痛点 → 7 环节 → 三种信任（业务面的主菜）

| 环节 | 数量 | 编号 | 代表痛点 |
|---|:--:|:--:|---|
| 客户 / 账户 | 3 | 1–3 | 开户审核慢、主数据各系统不一致、权限混乱 |
| 交易 | 5 | 4–8 | 摘单超卖、撮合时延、7 大交易模式难支持、模式与合同条款割裂、跨期订单混乱 |
| 履约 | 4 | 9–12 | 保证金状态不一致、履约节点跟踪难、违约处置慢、额度难算 |
| 物流 / 仓储 | 3 | 13–15 | **电子仓单造假与重复质押**、多仓库存查询难、在途不透明 |
| 资金 / 结算 | 4 | 16–19 | 资金不愿在平台过夜、账期长、对账差错、发票断点 |
| 信息 / 数据 | 2 | 20–21 | 行情多源不一致、推送延迟且三端不同步 |
| 风控 / 合规 | 2 | 22–23 | 风控数据散落、审计数据不完整 |
| 架构治理 | 3 | 24–26 | 无统一商品中心、前端老旧、流程割裂 |

**收敛句（一定要说）**：26 个痛点本质是**三种信任**——**付款与发货的先后（交易信任）、仓单的真与假（权属信任）、数据的通与断（信息信任）**。
> 行业视角另有一套 14 个共性痛点（I1–I14），与系统编号有一一映射；引用时系统视角说"痛点 13"，行业视角说"I3-1"，别混。

## 5. 价值怎么算（业务面的杀手锏）

| 价值层 | 内容 | 支撑数据 |
|---|---|---|
| 效率价值 | 省时间与人力 | 单笔交易 5 天 → 1.5 天；对账 3 天 → 2 小时 |
| 风险价值 | 避资金与合规风险 | 电子仓单 + 存证杜绝一货多押；银行 100% 存管 |
| 增长价值 | 多赚钱、做大生意 | 客户月交易量 20 笔 → 50 笔；供应链金融放款 |

**四种价值 = 四处线下困境**：

| 价值 | 线下困境 | 一句高频表达 |
|---|---|---|
| 信任中介 | 不敢跟陌生客户做大额交易 | "把'你跟张老板熟不熟'换成'系统显示这家公司履约率 97%'" |
| 信息聚合 | 逐家电话询价、报价不可比 | 一键比价；采购 5 人的活 3 人干 |
| 交易效率 | 询价、改合同、跑银行、催发货 | 一笔交易 5–7 天压到 1–2 天 |
| 金融服务 | 有好机会但缺钱、融资贵 | 把交易信用变成可融资资产，融资成本 18% → 8–10% |

**量化口径表（能对外说的只有这些，且必须带标注）**

| 指标 | 线下 | 平台 | 标注 |
|---|---|---|---|
| 合同签署周期 | 3–7 天 | 分钟级 | `[项目口径]` |
| 单笔交易周期 | 5 天 | 1.5 天 | `[项目口径]` |
| 财务对账 | 3–5 天 | T+1 自动 | `[项目口径]` |
| 中小企业融资成本 | 年化 18% | 8–10% | `[目标值]` |
| 采购团队人力 | 5 人 | 3 人 | `[项目口径]` |
| 客户月交易量 | 20 笔 | 50 笔 | `[目标值]` |
| 仓单真实性保障 | 人工核验 | 99%+ | `[目标值]` |

> **纪律**：`[项目口径]` 可以说"我们上线后是这个水平"；`[目标值]` 必须说"这是我们设定的目标"。**把目标值说成实测值，是业务面最容易当场翻车的地方。**

供应链金融三种模式：买方预付款融资 / 贸易商存货质押（货值约 70%）/ 卖方应收账款融资（应收约 80%）。资金方敢进来的前提是平台掌握三样线下拿不到的东西：**真实交易记录、仓单流转数据、历史履约数据**。

## 6. 客户案例怎么讲（三分钟一个，结构固定）

```
① 客户是谁（行业 / 规模 / 产权性质）
② 他原来怎么做（线下三步：谁打电话、谁跑银行、谁盖章）
③ 卡在哪（对应 26 痛点里的编号 + 三种信任里的哪一种）
④ 我们改了什么（模块 + 一条关键设计，不是功能清单）
⑤ 数字变化（只用 §5 表里的口径，标 `[项目口径]`）
⑥ 代价与遗留（哪一步还得人来、为什么不自动化）
```

**现成素材**：`03-客户案例/06-客户案例与行业对标手册.md`（行业对标）、`13-客户深度复盘与面试亮点.md`（客户深度复盘 + 亮点）、`05-B2B产品服务客户案例.pdf/.slides.pptx`（对外版）。
> 讲案例必须带 **⑥ 代价与遗留**——只说好处的是销售，说得清代价的才是架构师。

## 7. 追问链

| 追问 | 答 |
|---|---|
| 为什么客户不自己在群里买卖？ | 大额交易缺**信任基础设施**：付款发货先后、仓单真伪、纠纷举证。平台提供的不是"群"，是**可举证的履约记录** |
| 你的系统到底帮客户省了什么钱 | 三笔账：交易周期（资金占用天数 × 资金成本）、对账人力（3 人天 → 2 小时）、融资成本（18% → 8–10%）。**用客户的账算，不用功能说** |
| 客户最不愿意改的是什么 | 流程留痕与审批权限（尤其国企）；所以平台不能"替客户改流程"，要"把流程电子化并留痕" |
| 26 个痛点是拍出来的吗 | 是按 7 个业务环节 + 1 组架构治理梳理的**全局唯一编号体系**，每个痛点都对应模块与验收口径（见 `01-产品定位/03` 角色与业务动作全景） |
| 双核架构对客户有什么感知 | 客户只感知"报价能成交、成交不掉单、行情不延迟"；C 撮合给的是**延迟确定性**，Java 中台给的是**业务可维护性** |
| 业务和技术你怎么平衡 | 技术决策由**业务约束**倒推：大宗单笔资损大 → 稳优先于快 → 宁可拒绝不可降级返回错值 |

## STAR 一句话版

> **S（背景）**：平台要加企业级 AI 能力底座，知识类问题的答案得从文档里来，必须上 RAG。
> **T（任务）**：RAG 的天花板在「入库」这一步，而 Dify 自带解析对复杂中文 PDF 不够用——我要把复杂文档变成干净、可回溯的语料。
> **A（行动）**：做 MinerU 四层增强（图像预处理 / 页级路由 / 专项增强 / 统一 Markdown 中间态），逐个解决多栏、跨页表、图文、公式、扫描件五类「解析不准」+「解析失败静默丢文档」。
> **R（结果）**：交付了一条**解析器可替换**的链路 + 一套**四层验收方法论**；指标正在跑基线（待实测），绝不报没测过的数。

---

## 1. Situation —— 背景：为什么必须动「入库」这一段

公司已有一个大宗商品交易平台（后端 = Java 微服务中台 + C 语言内存撮合引擎），要在这上面加一层企业级 AI 能力底座，输出智能客服、知识检索、政策解读三类应用。

业务侧抱怨集中在三件事，这三件事刚好对应三类问题：

| 死结 | 对应问题类型 | 落到 RAG 上的含义 |
|---|---|---|
| 政策看不懂、甚至看错（抓到已废止/被替代版本） | **文档类** | 答案在政策 PDF 里，且必须带时效与效力位阶 |
| 同一个问题打三次电话（答案只在业务系统里） | **数据类** | 走中台工具网关查实时数据，**不进 RAG** |
| 知识散在十几个老员工脑子里 | **混合类** | 要把文档沉淀成可检索知识 |

知识类问题的答案源头是文档，所以必须有 RAG。而 RAG 有一条铁律：**质量 70% 取决于入库**——召回器再强，也找不回从来没被正确索引的东西（Garbage in, garbage out）。

**我的角色**：前期技术选型 + 数据链路负责人。具体管「文档 → 解析 → 分块 → 元数据 → 向量库」这一段；智能体编排与工作流调优由团队推进（这是必须主动划清的边界）。

---

## 2. Task —— 任务：把复杂文档变成干净语料

选型定了 Dify 做智能层之后，第一个现实问题砸下来：**Dify 自带的解析对复杂中文 PDF 不够用**。我们的语料是政策文件（多栏 PDF / 红头版式 / 扫描件）、合同标书、技术手册——全是传统解析器的死穴。

我的任务拆成三个硬要求：

1. **解析准**：复杂 PDF（多栏 / 嵌套表 / 图文混排 / 公式 / 扫描件）→ 统一 Markdown 中间态。
2. **不丢档**：解析失败**不能静默丢文档**——这是最坏的一种失败，因为它安静。
3. **可回溯**：分块与元数据（来源 / 文号 / 章节路径 / 页码 / 有效期）跟向量库对齐，让下游能按元数据过滤、能回溯原文位置。

## 3. Action —— 困难怎么解决

### 3.0 先给认知：为什么「换更强模型」是错的

这是整条故事最值钱的一句话：

> **解析不准的根源，是「识别 → 结构化输出」链路上每一环——图像质量、版面检测、元素识别、顺序还原——都有独立误差源。** 单一解析后端覆盖不了所有文档形态，所以**优化必须分层，不能寄希望于换一个大模型解决一切**。

正因为误差分布在整条链路，我的方案是**四层增强架构**：

```
① 图像预处理层        超分重建 · 去噪 · 倾斜矫正
        ↓ 页级智能路由
② 双后端              pipeline 后端（电子版·快） vs VLM 后端 1.2B（扫描件·复杂版式）
        ↓
③ 专项增强层          表格二次识别 │ 公式识别增强 │ 多栏顺序修复
        ↓
④ 结构化输出 + 评估闭环  Markdown / JSON · 坏例回流微调
```

### 3.1 五类「解析不准」→ 一张总表

| 困难 | 典型表现 | 我的解法 | 验证指标 |
|---|---|---|---|
| **多页 / 跨页续表** | 跨页续表被拆成两段，第二页只剩一串数字，模型不知道每列代表什么 | 检测相邻页表头重复 + 列宽相似度超阈值 → 自动合并并标「（续表）」；表格语义丢失 → **改用 HTML 输出**（保留 rowspan/colspan，Markdown 才是瓶颈） | Table-TEDS |
| **多栏排版** | 左右栏串行、跨栏大图切断文流、页眉页脚混入正文 | XY-cut 树切分 + 栏分隔线检测混合规则（`reading_order_fixer`，纯规则层不动模型）；页眉页脚跨页位置聚类自动剔除 | 阅读顺序编辑距离 |
| **图片（图文混排）** | 图注与图错配、嵌图内文字丢失、图片位置漂移 | caption 关联 + 嵌图 OCR + 图存对象存储锚点 + 描述标来源 | 抽取集人工比对 |
| **公式** | 长公式/多行公式错、α→a、上标丢失、行内公式切分边界不准 | 公式增强（UniMERNet 升级 checkpoint / 混用 PaddleOCR-VL 公式模块）；超分预处理直接惠及公式；输出 LaTeX + MathML 双格式 | CDM 自动评估 |
| **扫描件** | 低分辨率、摩尔纹、倾斜 → OCR 错误率飙升 | 图像预处理（Real-ESRGAN / SwinIR 超分 + 去噪 + deskew 倾斜矫正）；按页质量评分决定是否触发超分 | OCR 错误率 |

> **把「多页 PDF」翻译成技术内涵**：它真正难的不是「页数多」，而是**跨页的语义单元被切断**——跨页续表、跨栏图文、跨页章节。所以解法也不是「换个能读长文档的模型」，而是**在切分前把跨页单元先拼回来**（续表合并、阅读顺序修复）。

### 3.2 逐条展开（被追问时的细节）

**多栏 / 阅读顺序（方案 6，P0 优先级）**
- 阅读顺序后处理用「XY-cut 树切分 + 栏分隔线检测」混合规则，纯规则层、不动模型，所以**上线最快**（这是它排 P0 的原因）。
- 页眉页脚：跨页位置聚类，固定区域重复出现的元素自动剔除。
- 领域版面识别：用 Label Studio 标几百页自有文档模板，微调版面检测模型。

**表格（方案 3）**
- 关键决策：**输出 HTML 而非 Markdown**——rowspan/colspan 语义在 Markdown 里会丢，MinerU 原生支持 HTML，Markdown 才是瓶颈。
- 跨页续表：相邻页表头重复 + 列宽相似度超阈值 → 自动合并并标「（续表）」。
- 低置信度表格区域裁剪后送专用表格模型（RapidTable / PaddleOCR-VL 表格模块）二次识别回填。

**公式（方案 4）**
- 公式出自 UniMERNet 体系；升级 checkpoint 或混用 PaddleOCR-VL 公式模块（Formula-CDM 当前 SOTA）。
- 行内公式间距阈值按领域语料调优，减少误切分。
- 输出 LaTeX + MathML 双格式。

**图片（图文混排，方案 5）**
- 图文配对：图片提取 + caption 关联 + 原位插入，图注按版面坐标绑定，不靠「离得近」猜。
- 嵌图内文字：对图内文字单独 OCR（复用方案 1 超分），回填为图片描述并保留原图。
- 图存对象存储 + 位置锚点，保证能回溯原图原位。
- 图片描述必须标来源（OCR / 模型生成 / 人工），模型生成的是派生信息、不作事实引用。

**扫描件（方案 1）**
- 超分（Real-ESRGAN / SwinIR 2x~4x）+ 自适应二值化去噪 + Hough 变换 deskew 倾斜矫正。
- 按页质量评分（拉普拉斯方差 / 文本层完整性）决定是否触发超分，**避免无谓 GPU 开销**。

**单一后端不能兼顾精度与速度（方案 2）**
- 页级智能路由：三个判据（① 是否有可提取文本层 ② 图像块面积占比 ③ 版面检测置信度）决定走 pipeline 还是 VLM。
- 价值：把 VLM 调用量控制在必要页面上，吞吐成本降低，同时对上层调用者透明（封装层 `ADocumentParser`）。

### 3.3 解析失败不能静默丢文档（另一条独立的故事）

- **现象**：某批政策 PDF 解析超时或产出空 Markdown，文档在库里「消失」却没人知道。
- **处置**：失败入待办表 + 告警；按类型降级（换后端 pipeline↔VLM / 转 OCR / 人工处理）；保留原文件可重跑；大批量导入可续跑、可重入。
- **验证**：抽取集（多栏 / 嵌套表 / 扫描件各若干份）逐份人工比对结构与表格还原。

## 4. 验证 —— 解析完怎么证明「是对的」

这一节是面试官最爱追的，照四层讲：

### 4.1 先识破最隐蔽的故障：文字对但顺序错

> 每个字都识别对了，阅读顺序和字段关系是错的——解析任务显示成功、入库正常、用户也能搜到相似内容，但模型拿到的证据已经不是原文的意思。**这比解析失败更危险**，因为它不报错。

所以**不能只统计「整份文件是否成功」**，要四类指标分开记。

### 4.2 四层验收检查

| 层 | 查什么 | 对应指标 |
|---|---|---|
| ① 文字 | 文字是否完整、符号是否错认 | OCR 字符错误率 / 公式 CDM |
| ② 顺序 | 阅读顺序是否正确 | 阅读顺序编辑距离 |
| ③ 结构 | 表格行列、表头、标题层级是否保留 | Table-TEDS |
| ④ 定位 | 页码与坐标是否可追溯 | 抽取集人工比对 |

### 4.3 具体怎么验（三层手段）

1. **自建评测集**（方案 7）：参照 OmniDocBench 方法，抽 **200~500 页**代表性文档做人工标注基准。这是所有优化的度量地基——「没有回归集的解析器升级等于赌博」。
2. **抽取集人工比对**：多栏 / 嵌套表 / 扫描件各抽若干份，**逐份**比对结构与表格还原；关键表格保留原表截图作人工复核对照。
3. **坏例回流**：低置信度样本自动进标注队列 → 补充训练数据 → 微调版面 / 表格模型，形成校对闭环。

### 4.4 分类型指标（不是一个大而化之的「解析准确率」）

- 表格 → **Table-TEDS**；公式 → **CDM 自动评估脚本**（`formulas/` 目录存有公式原图）；阅读顺序 → **编辑距离**。
- 页级路由判定：抽样人工标注 100 页，看 pipeline / VLM 判定与实际最优后端的一致率 `【待实测】`。
- 解析成功率：按文档类型分桶（电子版 / 扫描件 / 多栏 / 嵌套表），成功 = 产出结构可用的 Markdown 且表格未破损 `【待实测】`。

> **标准答法**：「我先建评测集再谈优化，没有评测集的调参就是盲人摸象。目前基线数字还在跑，我能给的是这套度量口径和验证方法。」

## 5. Result —— 结果 + 诚实口径

**交付了什么（可讲的）**：
- MinerU 四层增强解析，复杂 PDF → 统一 Markdown 中间态。
- 解析器可替换：**中间态统一是为了让解析器可换——换解析器不动向量库和分块逻辑**。这跟 C 与 Java 之间放一层 DS 数据中心是同一个思路：**用一层协议把两侧解耦**。

**还没拿到什么（必须主动说）**：
- 没有任何「效率提升 X%」「准确率 95%」这类数字，因为**没有生产实测**。
- 效果指标还在验证，我给的是**度量口径与验证方法**，数字要等 POC 跑完。

**如果被问「重新做会怎么改」**（这条很加分）：
- 解析评测集会从**第一天**就建——先有基线（哪一类文档成功率多少），后面每改一版才知道是变好还是变坏。
- 元数据字段（文号 / 章节路径 / 有效期 / 密级）会在入库前就定死，而不是等下游要过滤时才补。

## 6. 视频：没做，但能迁移什么

> **诚实口径**：我们处理的是政策 PDF / 扫描件，**没有视频入库**。视频的 ASR、时间戳、画面 OCR 链路我们没验证过。

**可以讲的迁移判断**（这是加分点，不是缺口）：

- 视频本质上和「扫描件」同属**「必须先转成带位置信息的文本」**这一类。视频链路是：ASR 出带时间戳字幕 → 按语义边界合并 → 内容 + 时间位置 + 来源三者一起进索引。
- **共性工程问题**：位置字段（页码 vs 时间戳）**必须跟 chunk 一起写入，且切分后 start/end 不得错位**——错位会导致引用跳到相邻片段，此时调检索分数修不好。这个结论是跨模态通用的，我在 PDF 上验证过同一件事（页码/坐标必须一路带到底）。
- 标准答法：「视频没做。但我知道哪些结论可以跨模态迁移、哪些不能——位置字段跟 chunk 一起写入是通用的，ASR 和画面 OCR 是视频独有的，不能从 PDF 经验直接照搬。」

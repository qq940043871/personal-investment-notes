## 0. 先读这一节：口径红线

本项目是**双轨**结构（详见仓库其他文档），RAG 相关事实必须分清楚：

| 轨道 | 技术栈 | 我在 RAG 上的边界 |
|---|---|---|
| 公司项目（政策解读 Agent / 电力版） | **Dify** 承载 | **前期选型（Dify vs 自研）+ MinerU 解析改造 + 落向量库**；后续编排由团队推进 |
| 个人储备（Agent Harness） | Python + FastAPI + MainLoop | 属另一条线，与公司项目分开表述 |

**三条铁律：**

1. **归属按真实参与讲**："我负责选型和解析链路改造，团队在此基础上编排"——编排部分如实归团队。
2. **数字只报有出处的**。没有实测过的量化指标一律说"待实测"或直接不给数。文档里的经验值（如阈值 0.85）是**起手值**，说清是"起手配置，需按验证集标定"。
3. **区分"已实现"和"仍需验证的设计"**。面试官追问到没做的部分，正确答法是"这块我们没落地，我的判断是 X，理由是 Y"——比硬撑更能拿分。

## 1. 一条总纲：RAG 是一条"逐级收窄的漏斗"

所有 RAG 面试题，最终都可以归到这张图：

```
全库候选
   │
   ├─ 第一层 · 元数据硬过滤（权限 / 版本 / 时效 / 地域）   ← 越权与过期在这里挡掉
   ├─ 第二层 · 混合召回（BM25 + 向量）                    ← 解决"漏召回"，比谁覆盖得全
   ├─ 第三层 · 融合（RRF / 加权）                          ← 解决"两把尺子怎么合"
   ├─ 第四层 · Rerank（Cross-Encoder）                     ← 解决"排不准"，比谁排得准
   └─ 第五层 · TopK 截断 + Score 阈值                     ← 解决"证据不够别硬答"
```

**面试第一句就该说这个**：绝大多数团队的问题不是"模型不够强"，而是**漏斗第二层压根没开**——正确文档从来没进候选池，后面调 Rerank、改 Prompt 全是白费。

配套的两条链路（系统设计题必考）：

| | 离线入库 | 在线问答 |
|---|---|---|
| 干什么 | 上传 → 解析 → 切分 → Embedding → 批量写入 → 状态记录 | 鉴权 → Query 处理 → 过滤 → 混合召回 → Rerank → 上下文构建 → 流式生成 |
| 面对什么失败 | 解析慢、某页 OCR 挂、部分 Chunk 已写入 | 超时、服务不可用、证据不足 |
| 追求什么 | 吞吐 + 可恢复 + 幂等 | 低延迟 + 可降级 |

**两者必须拆开**——解析任务绝不能一直占用同步 HTTP 请求。

## 3. 逐题展开

### Q01 · 视频为什么不能直接入库 ★☆☆

**30 秒结论**：视频不能复用 PDF 链路。讲解类视频要先 ASR 出带时间戳字幕，再按语义边界合并；答案若在 PPT/操作画面里，还要补同时间段画面文字。**只有内容、时间位置、来源信息三者一起进索引**，后续检索和回答才有可靠输入。

**面试官追问**
1. 你的视频答案主要在人声、字幕还是画面里？
2. 为什么先做 ASR 而不是让多模态模型直接读完整视频？
3. 字幕怎么切才能保住语义又能回到正确时间段？
4. 怎么分别验证字幕召回、答案忠实度、播放器定位？

**本项目怎么接**：**直接说没做**——我们处理的是政策 PDF/扫描件，没有视频入库。但可以讲迁移判断：视频本质上和"扫描件"同属**必须先转成带位置信息的文本**这一类，共性工程问题是"位置字段（页码 vs 时间戳）必须跟 chunk 一起写入，且切分后 start/end 不得错位"。**错位会导致引用跳到相邻片段，此时调检索分数修不好**——这个结论是跨模态通用的。

> 这题的加分点不是"我也做过视频"，而是"我知道哪些结论可以跨模态迁移，哪些不能"。

---

### Q02 · PDF / PPT / 扫描件为何不能共用一条 Pipeline ★★☆

**30 秒结论**：不能先粗暴转纯文本。PDF 要字符层+布局+页码，PPT 要标题+项目符号+页序，扫描件要 OCR，视频要字幕+时间戳。**工程上先按格式路由到不同解析器，再统一输出正文、内容类型、层级路径、位置和来源字段**。

**面试官追问**
1. 支持哪些文件类型，各自进哪个解析器？
2. 统一输出结构里哪些字段对检索和引用是必需的？
3. 解析器失败是终止整份文件还是按页降级？
4. 怎么证明统一格式后没丢掉表格、标题和页码？

**本项目怎么接**：MinerU 的**页级智能路由**就是这条路的同构实现——前置轻量页级分类器，用三个判据（① 是否有可提取文本层 ② 图像块面积占比 ③ 版面检测置信度）决定走 pipeline 后端（原生电子版、快）还是 VLM 后端（扫描件/复杂版式、准）。

回答第 3 问时用这个：**按页降级，不是整份终止**。这也是我们封装层 `ADocumentParser` 的设计——路由对上层调用者透明。

---

### Q03 · 扫描 PDF 的 OCR 与失败降级 ★★★

**30 秒结论**：先判断 PDF 有没有可用字符层；没有才把页面按合适分辨率渲染成图像做 OCR。OCR 结果**必须保留坐标**，再走版面分类、阅读顺序恢复、表格识别。某页低置信度或超时 → 标记、重试或降级，**不让一页拖垮整份文档**。

**面试官追问**
1. 怎么判断字符层不可用，而不是一律 OCR？
2. OCR 有文字但顺序错，查哪一层？
3. 低置信度页面怎么重试、降级、进人工复核？
4. 怎么验证 OCR 结果仍能回到原页和原区域？

**本项目怎么接**
- 第 1 问：MinerU 路由判据第一条就是"PDF 是否有可提取文本层"——**一律 OCR 是最常见的浪费**。
- 第 3 问：图像预处理层（Real-ESRGAN/SwinIR 超分、去噪、deskew 倾斜矫正）就是**重试前的前置动作**；而且我们按页质量评分（拉普拉斯方差 / 文本层完整性）**决定是否触发超分**，避免无谓 GPU 开销。
- 第 4 问：坐标必须一路带到底——OCR 文本框 + bbox + 置信度进 chunk metadata，才能回到原页原区域。

---

### Q04 · 双栏、表格、图片怎么解析 ★★★

**30 秒结论**：不能按 OCR 返回顺序直接拼。先识别正文/标题/表格/图片区域，再按坐标与版面关系**恢复阅读顺序**；表格重建行列与表头，图片绑定标题或说明，跨页内容判断是否同一语义单元。输出必须保留页码和区域位置。

**面试官追问**
1. 双栏页面为什么会出现文字顺序交叉？
2. 无边框表格和跨页表格分别怎么识别与合并？
3. 图片说明与图片主体怎么建立关联？
4. 解析顺序错误会怎么传导到 Chunk 和召回？

**本项目怎么接（这题是强项，要讲透）**
- 第 1 问：**方案 5 多栏与阅读顺序修复**——① 用领域标注数据（Label Studio 标几百页）微调版面检测模型，让它认识自有文档模板；② 阅读顺序后处理用 **XY-cut 树切分 + 栏分隔线检测**混合规则；③ 页眉页脚用跨页位置聚类自动剔除。实施上是在 content_list 输出后加 `reading_order_fixer`，**纯规则层、不动模型，上线最快**（所以排 P0）。
- 第 2 问：**方案 3 表格专项强化**——① **改用 HTML 输出而不是 Markdown**，因为 rowspan/colspan 语义在 Markdown 里会丢（MinerU 原生支持 HTML，Markdown 才是瓶颈）；② 跨页续表拼接：检测相邻页表头重复 + 列宽相似度超阈值 → 自动合并并标注"（续表）"；③ 低置信度表格区域裁剪后送专用表格模型二次识别回填。
- 第 3 问：MinerU 自带**图片提取 + caption 关联 + 原位插入**。
- 第 4 问（关键）：顺序错 → chunk 里是"半句话跨栏断裂"的切片 → 向量看着相关，语义是错的 → **召回被污染且不会报错**。这比解析失败更危险。

---

### Q05 · MinerU 能直接解决 RAG 文档解析吗 ★★★

**30 秒结论**：MinerU 可以做**文档解析基线**，但不能假设所有页面一次处理就正确。多栏阅读顺序、复杂/跨页表格、小语种 OCR、公式和结构化语义仍可能失败。稳妥做法是**保存中间结果，对低置信度或特殊页面分类路由，再用专用表格模型、OCR、规则或人工复核处理**。

**面试官追问**
1. 哪些页面继续走默认解析，哪些触发二次处理？
2. 怎么定义低置信度与异常输出，而不是凭肉眼？
3. 为什么不把所有页面都交给最重的模型？
4. 解析器升级后怎么做回归测试，避免旧文档变差？

**本项目怎么接（这题就是我们的方案，照着讲）**

四层增强架构：
```
① 图像预处理层（超分/去噪/倾斜矫正）
        ↓ 页级智能路由
② pipeline 后端（电子版·快） vs VLM 后端 1.2B（扫描件·复杂版式）
        ↓
③ 专项增强层：表格二次识别 | 公式识别增强 | 多栏顺序修复
        ↓
④ 结构化输出 + 评估闭环（Markdown/JSON + 坏例回流微调）
```

- 第 3 问：路由的价值就是**把 VLM 调用量控制在必要页面上**——不是精度不够，是吞吐成本。
- 第 4 问：**方案 6 评估与数据闭环**——抽 200~500 页代表性文档做人工标注基准，每次模型/规则变更跑回归评测；低置信度样本自动进标注队列 → 补训练数据 → 微调。**"没有回归集的解析器升级等于赌博"**。
- 优先级要能背出来：P0 = 阅读顺序后处理（纯规则零成本）+ 表格改 HTML 输出（配置级）；P1 = 图像预处理 + 页级路由；P2 = 表格二次识别回填 + 公式模型升级；贯穿 = 评估闭环。

---

### Q06 · 解析质量怎么评估 ★★★

**30 秒结论**：至少分四层检查——**文字是否完整 / 阅读顺序是否正确 / 表格与标题层级是否保留 / 页码与坐标是否可追溯**。再准备电子 PDF、扫描件、双栏、跨页表格等固定样本做回归。低置信度页面记录失败类型并隔离处理，**不能只统计整份文件是否成功**。

**面试官追问**
1. 文字准确率高，为什么 RAG 仍可能召回错误？
2. 按页、按元素还是按最终问答评估？
3. 失败页怎么进重跑或人工审核队列？
4. 解析器改动后哪些样本必须回归？

**本项目怎么接**：第 1 问的答案就是"**文字对但顺序错**"——每个字都识别对了，阅读顺序和字段关系是错的，解析任务显示成功、入库正常、用户也能搜到相似内容，但模型拿到的证据已经不是原文的意思。**这是解析侧最隐蔽的故障模式**。我们的应对是四类指标分开记，而不是一个"解析准确率"。

---

### Q07 · Chunk 为什么不能只按固定字数切 ★★☆

**30 秒结论**：固定长度**只能作为上限，不能成为唯一边界**。先按标题、段落、列表、句子、表格等自然结构形成原子单元，再在 Token 预算内合并；超长内容在自然边界递归切分。每个 Chunk 还要**继承章节路径和原文位置**，避免子段落脱离上文。

**面试官追问**
1. Chunk 太小/太大分别伤害哪一段链路？
2. 段落超过上限时按什么顺序递归切？
3. 标题是单独成块还是复制到正文块里？
4. 怎么用检索问题证明切分方案有效？

**本项目怎么接**：Dify 侧对应**父子分块（Small-to-Big）**——子块做索引保精度、父块回填保上下文，直接解决"召回一个孤立句子"的问题。另有一个技巧：**用标记语言型元数据 / 分段标识符**（在 Markdown 里放自定义分隔符）控制分段边界，粒度比自动切词靠谱得多。

第 1 问标准答法：太小 → 丢前提（"但以下情况不适用"被切到上一块，用户搜例外条款只召回到半句规则）；太大 → 主题稀释 + 上下文噪声 + Token 成本上升。

---

### Q08 · Chunk Size 和 Overlap 怎么选 ★★☆

**30 秒结论**：先按文档结构确定候选边界，再把 Chunk Size 当作**最大 Token 预算**。Overlap 只用于缓解边界断裂，**优先对齐句子或段落边界**（Overlap 过大会制造重复召回）。最终在同一批真实问题上比较召回、证据完整性、重复片段和 Token 成本。

**面试官追问**
1. 为什么不同实现会有不同的 Chunk 起始值？
2. Overlap 过大为什么会制造重复召回？
3. 不同文档类型是否该用同一组参数？
4. 最终用哪些指标决定上线参数？

**本项目怎么接**：Dify 起手参数表（**说清是起手值，不是标准答案**）：

| 场景 | max_tokens | overlap |
|---|---|---|
| 事实型问答（查数、查条款） | 300–500 | 10–15% |
| 摘要 / 综述型 | 500–800 | 15–20% |
| 父子模式 | 父 ~1000 / 子 ~200–300 | 父 100 / 子 20 |

**加分说法**：参数改动上线时，要把**索引当成版本化产物**——换参数等于换索引，必须重灌并保留 bad case 对照，不能原地改。

---

### Q09 · 跨页表格、代码块、图片怎么切 ★★★

**30 秒结论**：三者先作为**带类型的原子单元**处理。小表格整体入块；超长表格按行组或逻辑区域拆，但**每块都要保留表头与续页信息**。代码保留缩进和符号，图片绑定标题/说明或结构化描述。任何拆分都要继续携带页码和来源。

**面试官追问**
1. 大表格超 Token 上限时具体按什么切？
2. 为什么每个子表都要复制表头？
3. 代码块怎么避免 OCR 和清洗破坏缩进？
4. 图片生成的描述怎么验证没编造？

**本项目怎么接**：第 2 问直接对应我们的跨页续表方案——**检测相邻页表头重复 + 列宽相似度超阈值 → 合并并标注"（续表）"**。第二页只剩一串数字时，模型不知道每列代表什么。第 4 问：描述必须标明来源是 **OCR / 模型生成 / 人工**三者之一，模型生成的描述是可疑证据，不能当事实引用。

---

### Q10 · Chunk 为什么要带 metadata ★★★

**30 秒结论**：Chunk 除正文外至少保存文档 ID、章节路径、页码/位置、内容类型、版本；需要上下文扩展时再存前后片段 ID。**检索前用权限/版本/时间字段硬过滤，排序时用标题和类型，回答后用来源字段定位原文。字段必须跟业务动作对应，不能为了丰富而堆 metadata。**

**面试官追问**
1. 哪些字段参与向量化，哪些只用于过滤？
2. 前后片段扩展怎么避免拉入另一个章节？
3. 文档更新后旧 Chunk 的版本怎么处理？
4. 来源页码和坐标在解析、入库、返回中怎么传递？

**本项目怎么接（有两个杀手锏）**

**① 电力 FAQ 字段设计**——能背出来就说明是真做过：

| 字段 | 作用 |
|---|---|
| `source_doc_no` / `source_clause` | 溯源，**必填，否则不可溯源** |
| `effective_from` / `effective_to` | 有效期，**电价类必填** |
| `role_scope` / `jurisdiction_scope` | 权限与地域过滤 |
| `confidentiality` | 密级 |
| `review_on` | 下次复核日期，电价类建议 ≤6 个月 |

对照通用直击库，电力版新增的四项（`effective_from/to`、`jurisdiction_scope`、`role_scope`、`source_clause`）**全是电力场景逼出来的**——这句话很值钱，说明字段不是抄模板。

**② 我知道平台的边界**：Dify 的元数据是**文档级不是分段级**，而且**单节点挂多知识库时元数据过滤不可用** → 所以按密级/地域拆库。能说出平台限制的候选人不多。

---

### Q11 · 知识库动态更新与幂等 ★★☆

**30 秒结论**：用**来源与内容生成稳定 Chunk ID**，入库前先查重，已存在跳过 Embedding，新内容批量写入。批量接口**逐条记录失败 ID**，超时做有限重试，字段错误保留现场。内容修改会生成新 ID，但旧版本是否删除要单独的版本与清理策略，**不能和去重混为一谈**。

**面试官追问**
1. 稳定 ID 为什么不能只用文件名？
2. 文件改名、内容改动、重复上传分别怎么处理？
3. Bulk 一部分成功一部分失败怎么恢复？
4. 重试怎么避免再次写入已成功的 Chunk？

**本项目怎么接**：Dify 侧对应 `Update Chunk` **分段级 API**（改某一段自动触发该段重新索引，不用重建整个文档）+ **把外部系统的 source_id 存成自定义元数据**，同步时按它过滤找文档更新，**而不是靠文件名猜**——文件名会重、会改。这正好是第 1 问的标准答案。

### Q12 · 为什么 BM25 和向量都要用 ★★★

**30 秒结论**：两种检索覆盖的漏找问题不同。BM25 依赖原词命中，适合**标题、编号、专业术语**；向量依赖语义相似，适合**用户换了一种说法**。工程上先限定资料范围，让两路各找一批候选，再做融合和重排。验证方式：同一批测试问题上比较**正确原文能否进前几条、第一次出现排第几、重复内容是否减少**。

**面试官追问**
1. 为什么"报销制度"更适合按原词查找？
2. 两路分数标准不同，合并时怎么处理？
3. 正确原文已找到，为什么重排后仍会掉出去？
4. 怎么用同一批问题判断混合检索有效？

**本项目怎么接（电力版是差异化亮点）**

| 通道 | 电力配置要点 |
|---|---|
| 语义（向量） | 常规；**对专有名词效果差** |
| 关键词（BM25/倒排） | **必须覆盖**：文号、专有名词（"两个细则""辅助服务""容量电价"）、条款号 |
| 同义词扩展 | 用术语表做查询扩展（"过网费" → "过网费 OR 输配电价"） |
| 候选池 | `top_k = 15`（后有两道筛，先放宽） |

> **电力场景关键词通道权重应比通用场景更高**——用户问政策时往往直接甩专有名词和文号，这些是精确串，语义检索经常打偏。

**这句话是面试加分项**：说明你是按场景调权重，不是照抄默认配置。

---

### Q13 · RRF 还是加权求和 ★☆☆

**30 秒结论**：BM25 与向量相似度来自不同分布，**原始分数通常不能直接相加**。加权求和需要先做稳定归一化并用验证集调权重；RRF **不依赖原始分数**，只按各列表排名累加倒数排名，因此对尺度差异更鲁棒。是否选 RRF 仍要看真实查询上的排序质量、稳定性与延迟。

**面试官追问**
1. Min-Max 归一化遇到异常高分怎么办？
2. RRF 的常数控制什么，怎么选？
3. 同一文档被两路召回怎么去重？
4. 为什么不能只看最终回答来比较融合算法？

**本项目怎么接**：**诚实说未落地**——我们用的是 Dify 内置混合检索 + 加权分数/Rerank，没有自研融合层。但要知道边界：RRF 会在"两路分数分布都正常且已标定好权重"的场景输给加权融合；而**加权融合遇到某路分数出现极端值时会整体失控**。

---

### Q14 · Rerank 为什么不能跑全库 ★★★

**30 秒结论**：向量检索把 Query 和文档分别编码（Bi-Encoder），适合从大规模语料快速取候选；Cross-Encoder 把 Query 与每个候选一起输入，能看到细粒度交互所以更准，但**计算量随候选数增长**。典型链路是先粗召回较大 Top-N，再批量 Rerank 到较小 Top-K，分别验证召回覆盖、排序提升和新增延迟。

**面试官追问**
1. 正确证据没进粗召回，Rerank 能补救吗？
2. Top-N 怎么定，为什么不是越大越好？
3. 为什么批量推理能提高吞吐但不一定降低单请求延迟？
4. 只精排前几页会带来什么排序一致性问题？

**本项目怎么接（三个硬点）**
- 第 1 问：**不能**。Rerank 只在候选集内重排，召回缺失必须回退到前面几层修。
- **⚠️ TopK 与 Score 阈值只在 Rerank 阶段生效**——不开 Rerank，阈值就是摆设。这是 Dify 的实测坑。
- **降级路径要能说出来**：Rerank 不可用 → 降级为**仅关键词排序 + 强制"仅原文"模式**（排序不可靠时生成的幻觉率会陡升）。

---

### Q15 · Query 重写 / 扩写 / HyDE 何时启用 ★★☆

**30 秒结论**：重写用于把含指代、错别字或不完整的问题变成独立查询；扩写生成同义表达，覆盖不同文档措辞；HyDE 先生成假设答案再做向量检索，适合短而抽象的问题。三者都可能引入偏差，因此**应按查询类型启用、保留原 Query、对原始与改写结果做回退或并行融合**。

**面试官追问**
1. 怎么判断是追问还是新话题？
2. 改写 Query 没结果为什么要回退原问题？
3. 扩写生成多个查询后怎么合并去重？
4. HyDE 生成错误假设会怎么污染召回？

**本项目怎么接（这题有立场，要敢取舍）**：电力政策场景**只做术语表驱动的查询扩展，明确不做 HyDE**。理由：HyDE 是先让模型编一个"假设答案"再去检索，而政策场景的答案是**文号 + 条款原文**，任何生成的假设文本都会把检索带向措辞相近但效力不同的文件。**错命中的代价远大于漏命中**——这个取舍本身就是加分项。

---

### Q16 · Embedding / Rerank 选型与领域微调 ★☆☆

**30 秒结论**：先按语种、文本长度、许可证、显存与吞吐筛出候选，再用项目评测集比较 Recall@K、MRR、延迟和显存。**通用模型在专业术语、否定表达或内部缩写上稳定失败时，才考虑领域微调**；训练数据要包含真实正样本和**易混淆的难负样本**，并与未微调基线做消融。

**面试官追问**
1. 为什么 Embedding 与 Rerank 不能只看同一个榜单？
2. 难负样本为什么比随机负样本更有训练价值？
3. 微调提升来自模型还是数据泄漏？
4. 模型变大后怎么评估吞吐与部署成本？

**本项目怎么接**：未做微调。**触发条件说清楚**：只有当 bad case 稳定集中在某一类（专业术语 / 否定表达 / 内部缩写）**且确认不是解析和切分的问题**时，才值得微调——**先修数据和链路，再动模型**。公开榜单只能缩小范围，不能替你做项目决策。

---

### Q17 · 检索效果差怎么逐层排查 ★★★

**30 秒结论**：按证据流逐层排查——① 正确内容有没有被解析并切进索引 ② 原 Query 与改写 Query 有没有召回 ③ 过滤条件有没有挡掉正确证据 ④ BM25/向量/融合/Rerank 各阶段候选分别是什么 ⑤ 送入模型的上下文是否完整。**每层都要保存候选、分数、过滤条件和版本**，才能定位到具体模块。

**面试官追问**
1. 正确证据没入库，为什么调检索参数没用？
2. 否定问题为什么容易召回正面描述？
3. 多跳问题怎么判断该拆成几个子查询？
4. 怎么设计一条能贯穿全链路的 Trace？

**本项目怎么接**：Dify 侧有知识库 UI 的"召回测试" + 节点级 trace 两级工具。**关键纪律**：RAG 回答错了，第一反应不应该是改 Prompt、换模型、调大 Top-K——**这三个动作都可能有用，但都不该是排查起点**。先确定正确证据在哪一层消失。

---

### Q18 · 资料里没答案时怎么避免硬编 ★★★

**30 秒结论**：检索结果必须先通过**相关性**和**证据充分性**双重判断，不能因为 Top-K 非空就交给模型生成。阈值要用"**应该回答**"和"**应该拒答**"两类真实问题共同校准；低于门槛时可以尝试原 Query 回退、受控扩展检索或明确拒答，**但不能为了提高回答率无限降低阈值**。

**面试官追问**
1. 相似度阈值为什么没有通用数值？
2. 有一段相关证据但不足以回答完整问题时怎么办？
3. 扩大 Top-K 与降低阈值有什么不同风险？
4. 怎么评估该答时答、该拒时拒？

**本项目怎么接（电力版有硬规则）**
- **闸门 A（检索前）**：角色分区 + 地域强过滤；**过滤后候选为 0 → 直接走"未找到依据"，严禁放宽条件重试**。
- **强制 schema**：`conclusion / basis[] / conditions / uncertainty / disclaimer`，其中 `uncertainty` **必填**（可写"原文未涉及"）——强制模型对每个回答评估一次不确定性。
- **禁止行动指导**：不得输出"建议您去办…""可以直接并网"这类话，那是主管部门职责。

---

### Q19 · 引用怎么做到可核验 ★★★

**30 秒结论**：检索阶段先给每个证据分配**稳定 ID**，保存文档、页码和位置；生成时可要求模型引用证据 ID，但**输出后仍要校验编号是否存在、所引片段是否支持对应陈述**。更严格时把答案拆成事实句，用规则、NLI 或人工复核做后处理归因。前端最后把内部 ID 映射成可点击来源。

**面试官追问**
1. 模型为什么会漏引或引用错误编号？
2. 一条陈述需要两段证据时怎么展示？
3. 引用相关但不支持结论，怎么检测？
4. 文档更新后旧答案的引用怎么保持可追溯？

**本项目怎么接（闸门 B 是杀手锏）**

**闸门 B（输出前）三查**：引用真实性（文号存在性 + 条款存在性 + **quote 逐字比对 ≥0.95** + 权限一致性）、越权复核（片段/存在性/标识泄露）。

> **三种引用幻觉里，"真条款号 + 被改写的摘录"最隐蔽也最危险**——条款号是真的，内容被改成了想要的形状。所以必须做逐字比对，**光查条款号存不存在不够**。

这句话基本能镇住追问。

---

### Q20 · 多轮"这个怎么申请" ★★☆

**30 秒结论**：先判断当前输入是上一话题的追问还是新问题；属于追问时，从**有限历史**中提取必要实体，把"这个怎么申请"改写为可独立检索的完整问题。改写结果用于检索，但**必须保留原问题**，在改写无结果或置信度低时回退，或让原 Query 与改写 Query 并行召回后去重融合。

**面试官追问**
1. 只靠代词规则判断追问会漏掉哪些情况？
2. 怎么检测用户已切换话题？
3. 历史里有多个候选实体时如何消解？
4. 改写错误时怎么不让错误传到回答？

**本项目怎么接**：电力版有**多轮意图继承**设计（§4.5），配合 12 类意图分类体系。**关键边界**：直接把整段聊天历史塞给检索器不稳——历史越长无关主题越多，当前问题越容易被稀释。所以是"有限历史 + 补实体改写"，不是"全历史拼 Prompt"。

### Q21 · 对话历史太长怎么办 ★☆☆

**30 秒结论**：最近几轮放低延迟会话窗口，较早历史压缩成摘要，跨会话且需要语义召回的内容进向量记忆或持久库。每轮同时从知识库取静态事实、从记忆模块取相关上下文，再过滤融合。**必须有 TTL、用户隔离、删除与更新策略**。

**面试官追问**
1. 摘要把关键数字压错了怎么发现？
2. 向量记忆为什么会召回语义相近但语境错误的旧对话？
3. 短期与长期记忆分别存哪里？
4. 用户要求删除记忆时，索引和持久库怎么同步？

**本项目怎么接**：未落地。**第 4 问**可以迁移到另一个经验：**删除必须是"索引 + 持久库"双写，只删一边等于没删**——这和增量入库的幂等是同一个问题的两面。

---

### Q22 · 评测集怎么建 ★★☆

**30 秒结论**：先确定知识范围和真实用户问题，再为每题标注**参考答案 + 支持答案的文档/页码/Chunk**。题型要覆盖直接事实、改写、多跳和**无答案**四类，去掉重复与答案泄漏。LLM 可辅助生成初稿但必须人工核对。数据集要分版本，**避免调参时把测试集当训练集**。

**面试官追问**
1. 为什么只用 LLM 自动生成问题会高估系统效果？
2. 一个问题需要多段证据怎么标注？
3. 无答案问题的 Ground Truth 是什么？
4. 怎么避免评测集被用于调参后失去公正性？

**本项目怎么接**：电力版 §13 有验收指标与测试用例；通用侧的闭环逻辑在 `rag-cases/`——**每一次召回测试里"答对了"的样本是最值钱的资产，别让它蒸发在聊天记录里**，应该沉淀成直击库条目。

---

### Q23 · Recall@K / MRR / Faithfulness 各查哪层 ★★☆

**30 秒结论**：Recall@K 看正确证据有没有进前 K，Precision@K 看候选噪声，MRR 看第一条正确证据排多前；生成阶段再看答案正确性、相关性与 Faithfulness（每个事实能否被上下文支持）。**引用要单独查关联性和充分性**。先做分层指标，再看端到端结果。

**面试官追问**
1. Recall@K 很高，为什么最终答案仍可能错误？
2. MRR 适合只有一条正确证据的问题吗？
3. LLM-as-a-judge 的分数怎么校准？
4. 引用正确但答案不完整，算哪一层问题？

**本项目怎么接**：这道题的正确姿势是**"不要把所有指标压成一个总分"**——指标冲突恰恰是定位信号。第 1 问标准答案：证据找回来了但生成模型漏掉限制条件，或者上下文被截断。**分层指标的价值就是告诉你该修哪一段。**

---

### Q24 · 首字为什么慢 ★★★

**30 秒结论**：先把首字前耗时拆成 Query 处理、Embedding、BM25/向量检索、Rerank、上下文构建、模型排队与首 Token 生成。文档向量**离线计算**，重复 Query 可缓存 Embedding；独立的两路召回可并行；ANN 参数、候选数量和 Rerank 批次要一起调。最后用 SSE 流式改善**可感知**延迟。

**面试官追问**
1. TTFT 和完整回答耗时有什么区别？
2. 哪些步骤可以并行，哪些有严格依赖？
3. Query 缓存怎么处理知识库更新与多租户隔离？
4. ANN 参数调快后怎么确认召回没明显下降？

**本项目怎么接（有个大杀器）**：**直击库 L0/L1 不过 LLM，token 消耗为 0** ——这是最强的延迟优化手段，不是调参数能比的。

| 级 | 机制 | 是否过 LLM | token | 一致性 |
|---|---|---|---|---|
| L0 | Dify Annotation 标注回复 | 否 | **0** | 逐字固定 |
| L1 | 精确命中（文号/条款号/标题） | 否 | **0** | 逐字固定 |
| L2 | Q&A 语义匹配 | 否 | 仅 embedding | 逐字固定 |

第 2 问要能说清依赖：模型必须等检索证据准备好才能开始生成，所以**向量检索慢的时候，流式输出只能改变第一个 Token 之后的展示，不能缩短前面的检索等待**——这是链路顺序决定的。

### Q25 · 可上线的 RAG 系统怎么拆 ★★★

**30 秒结论**：拆成**离线入库**与**在线问答**两条主链路。离线负责上传、解析、切分、Embedding、批量写入、状态记录；在线负责鉴权、Query 处理、过滤、混合召回、Rerank、上下文构建、流式生成。关系库存用户和任务元数据，检索引擎存 Chunk。两条链路都要有 Trace、超时、重试、告警与评测回归。

**面试官追问**
1. 为什么解析任务不该一直占用同步 HTTP 请求？
2. PostgreSQL 和检索引擎分别存什么？
3. 哪一层负责多租户权限和知识库过滤？
4. 线上答案错了，怎么从 Trace 定位到具体模块？

**本项目怎么接**：政策解读 Agent 的**六层架构 + 两道闸门**就是答案：
- **闸门 A（检索前）**：权限/地域前置过滤 —— 回答第 3 问：权限必须在**检索前**生效，不是生成后过滤答案。
- **闸门 B（输出前）**：引用真实性 + 越权复核。
- 第 1 问：解析可能持续几分钟到几十分钟，同步 HTTP 必然超时；必须有**文档任务状态机**，部分 Chunk 已写入也要能告诉用户进度。

## 4. 项目主叙事脚本

### 90 秒版本（最常用）

> 我参与的是政策解读 Agent 的 RAG 部分，主要负责**前期选型和文档解析链路的改造**，后续编排是团队在此基础上推进的。
>
> 选型上我们选了 **Dify 而不是自研**，理由是它的知识库 Pipeline 和混合检索、Rerank、元数据过滤都是现成的，团队要的是快速验证业务价值，而自研要自己补解析、切分、召回、重排、追溯一整条链路。Dify 只做编排层，检索资产可以复用外部知识库 API。
>
> 解析侧是另一个故事——**Dify 自带的解析对复杂中文 PDF 不够用**，主要是扫描件、双栏排版、跨页表格和嵌套表头。我做了 MinerU 的改造，核心是四层：图像预处理、页级智能路由、专项增强、评估闭环。最关键的两个动作是**表格改 HTML 输出保留 rowspan/colspan**，以及**跨页续表自动合并**。
>
> 检索侧我们的差异化是**关键词通道权重比通用场景更高**——用户问政策时直接甩文号和专有名词，语义检索经常打偏。另外配了**直击库**：高频问题命中就直接返回标准答案，不过大模型，token 为 0。
>
> 生成侧有两道闸门：**检索前做权限和时效过滤，输出前做引用真实性校验**，其中条款摘录要逐字比对，因为"真条款号 + 被改写的摘录"是最危险的一种幻觉。

### 30 秒版本（面试官打断时用）

> 我负责的是**选型 + 解析改造 + 落向量库**这三段。最有价值的两个动作：一是把 MinerU 的输出从 Markdown 改成 HTML，保住表格的合并单元格语义，并做跨页续表合并；二是建了直击库，高频问题命中不过模型。安全性上做了两道闸门，检索前过滤权限和时效，输出前逐字校验引用。

### 追问应对：把"没做的"说成判断力

| 面试官问 | 怎么说 |
|---|---|
| 你们做了 RRF / 自研融合吗？ | 没有，用 Dify 内置加权 + Rerank。RRF 对分数尺度更鲁棒，但如果两路分数已标定好权重，加权融合效果更好——我们没到需要自研融合层的阶段。 |
| 你们微调 Embedding 了吗？ | 没有。触发条件是 bad case 稳定集中在术语/否定/缩写，且已排除解析和切分问题。我们当时的问题主要出在解析层，先修了解析。 |
| 视频/多模态做了吗？ | 没有。可迁移的结论是"位置字段必须跟 chunk 一起写入且切分后不得错位"，但视频的 ASR、时间戳、画面 OCR 链路我们没验证过。 |
| 命中率/准确率多少？ | **如实说待实测**。只讲设计目标（如直击库命中率设计区间 15%–35%，低于 10% 说明收的不是真高频问题，高于 40% 要警惕把复杂问题硬塞进直击库），不报没测过的数。 |

## 5. 跨题标准答法（必背）

| 话题 | 标准答法 |
|---|---|
| Chunk Size / Overlap | "按结构定边界 + Token 预算 + 用评测集选"，再给场景化起手值 |
| 相似度阈值 | 阈值**没有通用数值**，必须用"该答/该拒"两组问题共同标定；且 TopK/Score 只在 Rerank 后生效 |
| Rerank 范围 | Cross-Encoder 计算量随候选线性增长；**粗召回 Top-N → 精排 Top-K** |
| 两路分数融合 | 分布不同不能直接相加；RRF 只看排名，对尺度鲁棒 |
| 来源标注 | 引用编号**逐字比对**——编号真也不等于支持结论 |
| 多轮历史 | 有限窗口 + 补实体改写 + 保留原 Query 回退 |
| 解析验收 | 四层检查：文字 / 顺序 / 结构 / 定位。**"文字对但顺序错"是最隐蔽的故障** |
| 去重与更新 | 重复写和漏更新是**方向相反**的两个问题，需要稳定 Chunk ID + 版本策略分开处理 |
| 排查起点 | 先定位正确证据在哪一层消失，再谈改 Prompt / 换模型 / 调大 TopK |

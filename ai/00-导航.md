> 2026-10-22 重组：原「根目录平铺 + dify/interview/rag-interview 三目录」改为**四层分层**。

## 分层原则

| 层 | 回答的问题 | 一句话判据 |
|---|---|---|
| `01-认知框架` | LLM / Agent / Harness **是什么、边界在哪** | 不绑定任何平台，换 Dify 或自研都成立 |
| `02-平台工程` | 工具链**怎么用、坑在哪** | 绑定具体平台/组件（Dify 1.17.x、MinerU） |
| `03-业务设计` | 具体业务 Agent **怎么设计** | 绑定业务场景（政策、电力、客服、直击库） |
| `04-面试` | 上面三层的东西**面试怎么讲** | 成品问答 + 外部题库 + 原料语料 |

> 层间是**单向依赖**：面试层引用设计与平台层，业务层引用平台层，认知层不依赖任何下层。发现反向引用即放错了层。

## 两条口径纪律（写材料前先看）

1. **二手材料只作参照**：`wushixiong-agent/`、`语料/` 是外部抓取件，只用来看「别人怎么问」；自家 AI 段口径一律以 `00-面试计划/03-项目叙事-AI.md` 为权威。
2. **Harness 是个人技术储备，不是公司平台技术栈**：公司侧 B2B 平台后端 = Java 微服务中台 + C 语言内存撮合引擎；政策解读 Agent 承载在 Dify 上。任何材料把 FastAPI / Python 说成平台后端栈，都算过度声明。

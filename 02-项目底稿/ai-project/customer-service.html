智能客服

Intelligent Customer Service — 从「给出答案」到「解决问题」，该转人时必须转人

价值出口 · 对外客户 17 步主链路 命中校验四关 转人工是设计的一部分

口径声明：本页描述的是平台整体方案与团队成果。个人实际参与 = 前期底座选型 + 文档解析改造 + 多格式文档落向量库；客服工作流的编排与调优由团队推进。

一、先厘清：智能客服 ≠ 知识库问答

把智能客服做成「挂了个知识库的问答机器人」，在真实业务里一定被投诉——因为它只解决了三分之一的问题。差别在这三件事：

知识库问答 智能客服
目标给出正确答案解决客户的问题
答不出来时说「没找到」就结束必须转人工，且不能让客户重复说一遍
会话结束后结束工单 / 回访 / 质检 / 知识回流，闭环

还有一条最容易被忽略的：客服有将近一半的问题根本不是「知识问题」。「我的工单到哪一步了」「这个月用了多少度电」——答案不存在于任何文档，只存在于业务系统。把它交给 RAG 是智能客服头号事故来源。

二、十个独有约束

① 服务属性——目标是解决问题，不是给出答案。答对了但没解决，客户照样不满意。

② 必须能转人工——转人工是设计的一部分，不是失败；做不成就死循环、升级投诉。

③ 有状态、有生命周期——会话会超时、会跨渠道、会被接续，上下文丢失就得重讲一遍。

④ 高并发多会话——同一机器人同时服务成千上万人，上下文串线会把 A 的资料说给 B，属重大事故。

⑤ 情绪是独立变量——情绪与意图正交，同样的问题不同情绪走不同路径，否则火上浇油。

⑥ 一半问题要查业务数据——答案来自业务系统而非文档，RAG 永远答不对且会一本正经地编。

⑦ 话术有合规红线——不能乱承诺、不能报错价、不能给法律意见。

⑧ 必须闭环——会话结束只是开始，问题没真正解决客户会反复来。

⑨ 一个账号挂多个主体——B2B 场景下一个登录账号常关联母公司 / 子公司 / 多品类经营主体，串了主体就是商业机密泄露。

⑩ 金额与数量错一位就是事故——现货客单价数十万到上千万，数字被模型改写等于真实的货款争议。

三、两个分岔决定整个架构

★ 第一分岔：知识类 / 数据类 / 混合

决定这个问题走「查文档」还是「查业务系统」。走错 = 必然答错。

  • • 知识类 → 直击库 → 命中校验 → 直接返回
  • • 数据类 → 业务 API（Function Call），不是 RAG
  • • 混合类 → 先规则、后数据，两段拼装

第二分岔：命中 / 未命中

决定走「直接返回」还是「走 RAG 全链路」。命中率高 = 快、稳、省。

  • • 命中且四关全过 → 0 生成 token 返回
  • • 任一关不过 → 静默降级走 RAG（不告诉客户「有条但过期了」）
  • • 兜底 → 转人工，附交接包

四、直击库三档 + 命中校验四道关

级别 命中方式 成本 适用
L0标注回复（精确匹配固定问法）0 token高频 Top 20、话术必须逐字合规
L1精确命中（单号 / 产品名 / 条款号）0 token「XX 业务怎么办」这类标准问法
L2语义匹配（embedding，阈值 0.85 起手）仅 embedding「换了说法的同一问题」

但命中 ≠ 可以直接返回。客服比知识问答多一道关，四关全过才放行：

关一
时效校验

关联的规则/资费文件是否仍有效？价格类、政策类必查。

关二
身份校验

这条答案要求的身份级别，当前客户达到了吗？

关三
一致性校验

该 FAQ 关联的源规则是否已被新规则替代？

关四 · 客服独有
话术合规校验

是否含承诺性表述、绝对化用语、法律意见？命中红线即驳回。

关四为什么必须有？知识问答答错了用户自己会判断；客服答错了用户会当成官方承诺。一句模型自己发挥的「可以的，肯定能退」，就可能变成一次赔付纠纷。

五、转人工：六个触发条件 + 一个交接包

触发条件 优先级
① 显式请求（"转人工"）最高
② 情绪升级（愤怒/投诉/提监管）高
③ 高风险话题（资金/责任/赔付/隐私）高
④ 连续未解决（同意图 2 轮未解）中
⑤ 高价值客户（VIP/大客户）中
⑥ 系统异常（数据类接口连续失败）中

交接包（不能让客户重复说）

  • • 客户档案（身份级别、历史服务记录、标签）
  • • 会话摘要（一句话说清客户到底要什么）
  • • 已识别意图与槽位（含已提供的单号）
  • • 情绪与紧急度
  • • 机器人已尝试的动作与结果
  • • 已召回的知识条目（坐席可复用）
  • • 建议的下一步（仅供参考，不强制）

没有交接包的转人工，等于把机器人的难题丢给人、客户还得再讲一遍——体验比直接排队人工更差。

六、验收口径：先定健康区间，再谈效果

20% – 40%

直击命中率健康区间。低于 10% 说明收集的不是真高频问题。

20% – 35%

转人工率正常区间。低于 10% 要警惕该转不转，高于 45% 说明自助能力不足。

首字延迟 P50 / P95

度量口径已定，实测值待 POC 采集（当前无真实数字，不做估算）。

阈值纪律：Rerank 必开——TopK 与 Score 阈值只在 Rerank 阶段生效，不开就是摆设；且错命中的代价远大于漏命中（错命中 = 看似权威但答非所问；漏命中 = 多花点钱走 RAG 或转人工）。

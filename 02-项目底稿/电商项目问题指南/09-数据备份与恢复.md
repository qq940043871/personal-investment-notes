# 09 - 数据备份与恢复

## 个人经验锚点

> 本章为**通用方案 + 可迁移(B2B)**。备份策略、Binlog 日志备份、主从复制属于**通用方案**。本人真实落地的是：**B2B 大宗平台的主从复制 + Binlog 全量/增量备份 + 备份可用性校验**（保障交易数据与 3 年零资金差错）。**两地三中心、异地多活容灾、跨地域数据同步属于行业参考，本人未落地多活容灾**。

> 保证数据不丢失、灾难可恢复

## 📖 概述

数据是交易系统最核心的资产。本章介绍多层次的数据保护策略，并标注本人已落地（主从+备份）与未落地（异地多活）部分。

## 🗄️ 一、备份策略

### 1.1 备份类型

| 类型 | 频率 | 恢复时间 | 存储成本 |
|------|------|----------|----------|
| **全量备份** | 每周/天 | 长 | 高 |
| **增量备份** | 每小时 | 中 | 中 |
| **日志备份** | 实时 | 短 | 低 |

### 1.2 备份架构

```
┌─────────────────────────────────────────────┐
│              数据备份架构                        │
│                                             │
│  ┌─────────┐     实时      ┌─────────┐     │
│  │  主库   │ ──────────► │ Binlog │     │
│  │ MySQL   │              │ Server │     │
│  └─────────┘              └────┬────┘     │
│        │                       │           │
│        │ 全量/增量             │ 增量同步   │
│        ▼                       ▼           │
│  ┌─────────┐              ┌─────────┐     │
│  │  备份库  │ ◄─────────│ 备库   │     │

```

## 🔄 二、主从同步（本人已落地）

### 2.1 异步复制

```ini
# MySQL 配置
[mysqld]
log-bin = mysql-bin
server-id = 1
binlog_format = ROW
sync_binlog = 1
```

> 本人 B2B 平台基于 `ROW` 格式 Binlog 做主从复制与 Canal CDC 变更捕获，兼顾备份与数据同步；备份文件定期做恢复演练验证可用性。

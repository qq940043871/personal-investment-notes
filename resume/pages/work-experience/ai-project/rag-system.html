RAG 与文档解析

RAG Pipeline & Document Parsing — 索引侧决定天花板，检索侧决定命中率，解析侧决定源头是否干净

全平台共用底座 MinerU 四层增强解析 ★ 个人主责环节 16 个卡点清单

本页是个人参与最深的一环：MinerU 复杂 PDF 解析改造（PDF → Markdown）+ 批量解析调度与失败兜底 + 多格式文档落向量库的格式与元数据衔接。检索策略与工作流编排由团队推进。

一、RAG 的四段链路：谁决定天花板

RAG 效果不好，90% 的人第一反应是「换个更好的模型」。但从链路看，模型只在最后一段：

索引侧（离线）
解析 · 分块 · 索引

决定天花板：源文档没解析对，后面全白搭。

检索侧（在线）
混合检索 · Rerank · 过滤

决定命中率：该召回的有没有进候选池。

生成侧
上下文注入 · 溯源 · 空结果

决定可不可信：能不能给出处，没依据时敢不敢不说话。

运维侧
召回测试 · 静默故障 · 成本

决定能不能持续变好：升级完悄悄失效最要命。

一句话：索引侧决定天花板，检索侧决定命中率，生成侧决定敢不敢用，运维侧决定能不能变好。换模型通常排在最后一位。

二、★ 我负责的那一环：把复杂 PDF 变成干净的 Markdown

平台的知识来源里有大量复杂 PDF：政策文件（多栏 + 嵌套表 + 红头版式）、合同标书（跨页续表）、技术手册（图文混排）、扫描件（低分辨率、倾斜）。MinerU 是当前开源 PDF 解析的标杆，但面对这五类仍会出错：

难点类型 典型表现
多栏排版双栏/三栏阅读顺序错乱（左右栏串行）、跨栏大图切断文流、页眉页脚混入正文
嵌套表格多层嵌套表头语义丢失、合并单元格错位、跨页续表被拆断、无边框三线表结构猜错
图文混排图注与图片配对错乱、嵌图内文字丢失、图片插入位置漂移
公式长公式/多行公式识别出错、行内公式与正文切分边界不准、模糊印刷件符号错认（α→a、上标丢失）
扫描件低分辨率、摩尔纹、噪声、页面倾斜导致 OCR 错误率飙升、版面检测框漂移

结论：换一个更大的模型解决不了一切。误差源分布在这条链路的每一环（图像质量 → 版面检测 → 元素识别 → 顺序还原），所以必须分层增强：

第 1 层
图像预处理

超分重建 · 去噪 · 倾斜矫正

第 2 层
双后端页级路由

原生电子版走 pipeline（快）· 扫描件/复杂版式走 VLM

第 3 层
专项增强

表格二次识别 · 公式增强 · 多栏顺序修复（XY-cut + 规则），低置信度回填

第 4 层
统一中间态

输出 Markdown（图存对象存储、表格转 HTML 表），交给下游分块入库

为什么坚持「统一 Markdown 中间态」？解析器是可替换的（MinerU / RAGFlow / 自研），但下游入库只认一种格式。中间态一层隔离，换解析器不需要动向量库和分块逻辑——这和 C 与 Java 之间放一层 DS 数据中心是同一个思路：用一层协议把两侧解耦。

三、解析之外，我另外交付的三件事

批量解析调度

按队列分批、按页数与类型估时长、控制并发避免把机器打满；大批量导入时能续跑、能重入。

失败兜底

解析失败不能静默丢文档：失败入待办表 + 告警，按类型降级（换后端 / 转 OCR / 人工处理），保留原文件可重跑。

入库格式衔接

分块边界与元数据字段（来源、文号、章节路径、页码、有效期）与向量库对齐，保证下游能按元数据过滤、能回溯到原文位置。

四、检索侧：两级过滤，别把顺序搞反

第一层 · 知识库级

决定初步候选池长什么样：用向量、关键词，还是两者混合。

中文场景特别注意：产品型号（BGE-M3）、缩写（EBITDA）、化学式，纯向量大概率漏——混合检索在某些场景是必需项，不是优化项。

第二层 · 节点级

在这个池子上做 Rerank、元数据过滤、TopK 截断。

顺序反了就救不回来：知识库级选错，节点级再调 Rerank 也没用——正确文档压根没进池子。

Rerank 的三个坑（不知道就等于白配）：

  • ① TopK 与 Score 阈值只在 Rerank 阶段生效——不开 Rerank，这两个参数基本不落地，调半天毫无变化。
  • ② Rerank 默认关闭，需自己配；多模态知识库必须配多模态 Rerank，否则图片被排除。
  • ③ 默认 TopK=3 / 阈值 0.5 只适合「先跑起来看看」，生产要以召回测试的实际 score 分布为准。

五、验收口径

解析成功率（分类型）

按电子版/扫描件/表格密集/多栏四桶统计；失败必须可告警可重跑。实测值待采集。

召回率基线

50–100 条真实问题跑召回测试取基线，作为一切调优的对照。

可溯源率

答案能回到「文件 + 页码 + 段落」的比例，目标口径 100%。

诚实清单：Dify 没替你解决的部分包括——权限最小化（要中台做）、知识治理流程（要业务做）、静默故障排查（要专人盯）、评测集建设（要标注做）。把这些当成「平台自带」，是 RAG 项目最常见的幻觉。

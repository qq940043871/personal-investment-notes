一、项目背景：三个「管不住」的死结

平台建在已有的 B2B 大宗商品交易平台之上。业务侧的抱怨集中在三件事上，它们都不是「IT 系统不好用」，而是重复性脑力劳动没有人替人去做：

死结一 · 政策看不懂、看错

政策不是「追加新版本」，而是「失效 / 被替代」。自己上网找文件，极易抓到已废止的版本；更隐蔽的是效力位阶错、越权看内部稿。

死结二 · 同一个问题打三次电话

「我的单子到哪一步了」「这个月用了多少」这类问题，答案因人而异的实时数据，问三个人得三个口径，7×24 更是无从谈起。

死结三 · 知识散在十几个人脑子里

商品规格、业务流程、审批口径全在老员工经验里。人走知识走，新人靠师父带，口径永远不统一。

平台定位：在 B2B 交易平台之上加一层企业级 AI 能力底座——Dify 承担「智能层」，自研业务中台承担「业务层」，统一输出智能客服、知识检索、政策解读三类应用。一句话记法：Dify 解决「AI 怎么做得快、怎么调得好」，自研中台解决「AI 怎么接得稳、怎么管得住」。

四、核心技术决策：一次选型复盘

六个候选不在同一层级（框架库 / 云厂商 PaaS / 开源应用平台 / 通用自动化），混在一起比必然失焦。先分层，再逐个淘汰：

决策点 背景 / 问题 我的判断 收益 / 结果
① 否决「框架层纯自研」
LangChain / LlamaIndex		 有人说「自己搭一套最可控」。 缺的是平台而不是库：可视化调试、Prompt 版本、知识库管理、召回测试、流式 API 网关全要自研，且与业务价值无关；MVP 到生产还要补重试、降级、限流、观测、权限注入，2–3 周起步。 省下数月基建，团队人力不押在框架兼容性上。
② 否决云厂商 PaaS
阿里云百炼		 全生命周期管理、SLA、专属版隔离都很完备。 数据与模型绑同一厂商、按量计费有平台溢价、合规口径仍需自证「模型跑哪、数据落哪、密钥谁管」。留作二期备选，不做主底座。 避免一次性的迁移悬崖与线性增长的 TCO。
③ FastGPT / RAGFlow / n8n 逐个淘汰 各有杀手锏：知识库专精、文档理解最深、集成节点最多。 FastGPT 编排广度不足；RAGFlow 强在 RAG 弱在应用层，改当解析器插件用；n8n 协议非 OSI 开源（对外交付有合规不确定性）+ AI 只是附加项。 取其长不受其限：复杂文档走 RAGFlow/自研解析后再入库。
④ 定盘 Dify 需要私有化、模型中立、RAG 达生产门槛、还要能 API 交付。 唯一同时满足：Apache-2.0 修改版可私有化可二开 + OpenAI-compatible 模型完全中立 + RAG（分块/混合检索/Rerank/召回测试）齐备 + Workflow 与 Agent 双模 + 一键发布 REST/流式 API。 赢在「能力全面度 × 可控性 × 周期」的综合最优，不是单项第一。
⑤ 为什么还要自研业务层 Dify 社区版 RBAC 只到工作空间/应用级，无行级权限、无事务幂等补偿、无 SSO 与完整审计。 中台承接：细粒度鉴权、工具网关、审计与 trace_id 关联、按部门/租户的 token 计量、存量 ERP/OA/CRM 集成、多渠道前端。 AI 从「业务部门偷买的一个工具」变成「有审计、有配额、有退场路径」的生产系统。

六、「企业级」三个字意味着什么

市面上自称企业级的平台，多数只是「能跑起来的 demo」。企业级是可检验的，用六条硬指标：

硬指标 具体含义 平台对应机制
数据不出域敏感数据不进第三方，或按敏感度分级走不同通道内网私有化部署 + 敏感度划通道（通用走第三方、涉密走内网）
模型中立换模型不改业务代码、不影响业务连续性OpenAI-compatible 端点 + 中台网关抽象，保留「换编排引擎」的退出路径
权限收口越权访问在系统层被拦，不靠模型自觉统一身份 + 工具网关统一鉴权，校验永远在中台侧
可审计可计量每次 AI 调用可归因到人、到部门、到单据trace_id 关联业务操作日志与 AI 调用日志；token 按部门/租户计量分摊
可降级不崩模型挂了/超时了/答不准了，给「信息更少但更确定」的结果门控降级三档（完整解读 / 仅原文 / 未找到依据）；转人工是设计的一部分
可退出不被单一厂商路线图卡死协议宽松（Apache-2.0 修改版）+ 可二开 + 插件 / MCP 扩展

七、能力边界：它不解决什么

不替代业务决策。它出草稿、给依据、标风险，决定权在人；合同、授信、定级一律「AI 建议 + 人确认」。

不做算法创新。定位是把成熟能力接进业务，不是训练新模型；微调只在效果瓶颈明确时才上。

不解决数据本身脏。源头解析错、版本乱，下游一律错——这是数据治理问题，不是 AI 问题。

不直连业务数据库。所有数据访问走中台受控工具/API，这是硬约束不是建议。

不承诺「零幻觉」。只能做到「无依据不开口 + 降级到原文 + 可溯源」，宣称零幻觉的材料一律不合格。

不承担合规责任主体。平台给的是辅助，最终合规责任仍在业务流程与责任人。

八、子系统详解

智能客服

知识类走直击库、数据类走业务 API，命中校验四关 + 转人工六条件。

知识库与智能检索

采集 → 解析 → 分块 → 索引 → 发布，把口径变成唯一版本。

政策解读（通用 + 电力）

六层架构 + 两道纯代码闸门，时效与效力位阶用规则算。

RAG 与文档解析

MinerU 四层增强解析 + 两级检索过滤，我主责的数据链路。

大模型管理

第三方 / 内网 vLLM / 轻量 Ollama 三通道，模型可换代码不动。

模型微调

非必选项：先证明瓶颈，再决定是否上微调。

数据标注

标注集即回归测试集，未命中样本回流成知识资产。

智能体开发

Workflow 保确定性、Agent 补开放环节，工具一律过中台网关。

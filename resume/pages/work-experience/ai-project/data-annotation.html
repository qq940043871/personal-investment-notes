数据标注

Data Annotation — 标注集既是效果评估的燃料，也是回归测试集

底座 · 迭代燃料 双人标注 + 一致性校验 未命中样本回流

口径声明：本页描述的是标注体系的设计。个人参与 = 解析产物与样本回流的格式衔接；标注执行与质量抽检由业务侧承接。

一、标注不是「给数据打个标签」

在 AI 平台里，标注承担的是一个更硬的职责：它是「效果变好了」的唯一证据来源。没有标注集，所有关于「准确率提升了」的说法都只是感觉。

没有评测集

改了 Prompt、换了分块、上了 Rerank，谁也说不清是变好还是变坏，只能靠「我觉得」。

没有回归集

修好一个问题、弄坏两个旧问题，没人发现——直到客户投诉。

没有回流

每次召回测试「答对了」的样本蒸发在聊天记录里，知识资产永远不会长大。

二、三类标注对象

对象 标什么 用在哪个环节
意图这句话属于哪个意图（4 大类 20 子类），主意图与多意图分别标意图识别准确率、第一分岔（知识类/数据类）
槽位角色、业务域、地域、时点、单号等关键要素的位置与取值槽位抽取、必抽槽位缺失时的追问策略
答案质量给定召回内容，标注「答对 / 部分对 / 答错 / 应拒答」四档RAG 效果评估、Prompt 与分块调优的对照基线

三、质量控制四件套

① 双人标注
关键样本交叉标

高价值/高风险样本至少两人独立标，分歧进入仲裁。

② 一致性校验
标注规范先落地

给出判定口径文档，再统计标注者间一致率；口径不清就先去吵清楚口径。

③ 抽检
按批次抽检

抽检不合格整批退回，不能只改抽样到的那几条。

④ 版本管理
标注集带版本号

每次效果对比都注明用的是哪个版本的标注集，否则数字无法比较。

四、回流闭环：让每一次「答对了」都留下来

线上会话 · 未命中 / 答错 / 转人工的样本
抽样与清洗 · 去隐私、去重、按意图归类
标注与验证 · 人工给标准答案 → 进回归集
直击库候选池 · 审核通过后成为 L0/L1 条目，0 token 命中

这条闭环同时解决三个问题：省 token（新条目变直击）、保一致（同一问题从此只有一个口径）、能迭代（回归集越用越厚）。所以标注在平台里不是成本中心，是资产生产线。

五、验收口径

回归集规模

起步 50–100 条覆盖主意图，之后按线上未命中样本持续增补。

标注一致率

关键样本双标一致率作为标注质量红线，不达标先修规范再标。

直击库覆盖率

高频问题被直击库覆盖的比例，直接决定 token 成本与一致性。

一句话：标注是让 AI 项目「可迭代」的前提。没有它，团队只能在黑暗里改 Prompt。

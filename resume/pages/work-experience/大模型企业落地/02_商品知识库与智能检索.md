## 一、本人参与的真实链路（MinerU 解析 → 向量库）

> 这是本目录中与本人真实工作**直接相关**的部分，其余章节为方案设计。

### 1.1 链路位置

```
多格式文档（PDF / Word / Excel / PPT / 扫描件）
        ↓
   MinerU 统一解析 → Markdown
        ↓
   清洗 / 分块 / 元数据补充
        ↓
   Embedding 向量化
        ↓
   写入向量库（供检索）
```

### 1.2 本人负责的关键点

| 关键点 | 具体工作 | 难点 / 处理思路 |
|--------|---------|----------------|
| 批量解析调度 | 组织多文档批量解析任务 | 大文档耗时长，需并发控制与任务队列 |
| 失败兜底 | 解析失败重试与降级 | 扫描件 OCR 失败、版面异常时的兜底策略 |
| 下游入库格式衔接 | 统一 Markdown 输出格式 | 保证下游向量库入库格式一致、元数据可对齐 |
| 格式统一 | 多格式 → Markdown | 表格、公式、多栏排版的结构保真 |

### 1.3 为什么先解析成 Markdown

- 目标是把**异构文档统一成结构化 Markdown**，再交下游向量化入库，降低下游对格式差异的耦合；
- 相比直接把原始 PDF 丢给向量化，先解析成 Markdown 能显著改善切片质量与元数据可控性（该结论来自前期链路验证）；
- 对涉密文档，解析与入库环节需在内网环境下完成（见 09 的数据敏感度分层通道）。

> **边界说明**：本人参与的是**解析 → 入库**这一段。Embedding 模型的生产选型、向量库的生产部署、检索策略调优由团队推进或属方案设计。

## 二、业务价值（方案预期）

> 下表为**方案预期**，用于说明检索能力的方向，**非实测收益**。

```
传统检索 vs 智能检索（目标形态）

传统：
  客户："我要找能用在新能源电池里的钴"
  系统：精确关键词匹配 → 无结果
  结果：客户流失

智能（目标）：
  客户："新能源电池原材料"
  系统：语义理解 → 钴、镍、锂、锰 + 下游应用
  结果：精准匹配 + 关联推荐
```

| 指标 | 传统检索 | 智能检索（预期） |
|------|---------|-----------------|
| 召回率 | 40~60% | 85~95%（预期） |
| 搜索时长 | 10~30s | <3s（预期） |
| 关联推荐点击 | 5% | 25%（预期） |
| 转化提升 | — | +30~50%（预期） |

### 3.2 典型应用场景（方案设想）

#### ① 智能规格匹配

```markdown
客户需求：需要一批电阻率<0.1的铜杆，用于高端电缆

（设计）AI处理流程：
1. 解析需求参数：铜(Cu)、形态=杆、电阻率<0.1
2. 查询知识图谱：
   - 牌号匹配：TU1、TU2 无氧铜
   - 规格匹配：直径8mm/10mm/12mm
   - 替代方案：低氧铜杆(电阻率<0.017)是否可接受
3. 返回结果：
   - 匹配商品列表（含规格对比表）
   - 价格参考
   - 供应商信息
```

│ 到岸价：$9,295/吨 ≈ ¥67,700/吨         │
│ 交货地：上海保税区                      │
│ 备注：含保险，买方自行清关              │
├─────────────────────────────────────────┤

│ 升水分位为示例，实际需接入行情数据      │

#### ③ 合规自动检查（方案设想）

- **出口管制**：自动识别 EAR / 瓦森纳清单商品

### 5.2 向量化模型选型（调研结论）

| 模型 | 维度 | 优势 | 适用场景 |
|------|-----|------|---------|
| text-embedding-3-large | 3072 | OpenAI官方，效果好 | 通用场景 |
| BGE-M3 | 1024 | 中英双语，中文优化 | 跨境电商 |
| M3E | 768 | 开源免费，部署简单 | 成本敏感 |
| GTE | 1024 | 阿里开源，中文能力强 | 大宗商品 |

> 上表为**调研结论**（供选型判断），生产选型由团队定。

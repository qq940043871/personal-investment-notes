一、项目背景与要解决的问题

B2B 平台对外要承载多租户门户、开放平台与内部微服务调用。早期没有统一入口，各服务各自暴露 HTTP 接口，认证、限流、脱敏各写各的；更麻烦的是接口契约没人管——上游改了字段不通知下游，上线当天才暴露兼容问题，跨模块协作互相踩脚。

入口不统一

认证、鉴权、限流逻辑散落在各服务，安全策略无法统一收敛与审计。

契约会漂移

接口字段、错误码、版本各改各的，下游不知道上游变了，联调才发现不兼容。

高峰易雪崩

冬储高峰流量突增，单个慢服务拖垮整条调用链，缺少限流与熔断保护。

核心定位：网关作为系统对外的统一入口，集中做认证校验、权限拦截、IP 安全、限流熔断、敏感脱敏与缓存；同时承担接口契约治理职责——用一句话概括治理边界就是「管连线，不管黑盒」：网关负责接口的连通性、契约与流量，服务内部实现由各自负责。

五、接口契约治理：管连线，不管黑盒

网关不关心服务内部怎么实现（黑盒），但必须管住服务之间怎么连（连线）：契约、版本、兼容性。我们通过以下机制把它落地：

契约登记中心

每个对外/内部接口登记请求响应结构、错误码、版本，形成可查询的契约清单。

兼容性校验

接口变更走评审，做前后向兼容性检查；不兼容变更必须升版本并通知下游。

灰度与版本并存

新旧版本接口在网关并存，按调用方灰度切换，避免一次性切换引发联调事故。

契约看板

持续统计调用量、错误率、耗时，契约执行情况一目了然，异常自动告警。

六、配套管理机制

On-call 值班

Java 侧排班值班，网关有统一告警与排障入口，出问题凭 traceId 快速定位，值班记录沉淀进复盘。

技术债台账

网关与接口相关债务统一登记、排优先级，定期在迭代中偿还，避免债务无声累积。

契约评审

跨模块接口变更必须走契约评审，上游改字段需提前通知下游，把联调问题前置到设计阶段。

七、关键决策与踩坑

决策一 · 安全策略全部收敛到网关过滤器链

把认证、鉴权、IP、脱敏从各服务上收到网关，统一策略、统一审计。踩坑：早期把脱敏放在业务层，导致漏改的服务泄露敏感字段；上收网关后一处配置全局生效。

决策二 · 限流按「租户 + 接口」双维度，而非全局单限

全局单阈值要么保护不足、要么误伤大户。踩坑：曾因某租户突发大流量挤占全局配额导致其他租户受影响；改为按租户维度隔离配额后，单个租户的峰值不再外溢。

决策三 · 熔断只对非核心依赖开启自动快速失败

资金与交易主链路的依赖不做自动快速失败，避免误熔断造成交易中断；对报表、统计、消息推送等非核心依赖开启熔断降级。

决策四 · 契约先行，接口变更必须过评审

立规矩：契约是硬约束。改字段要么兼容、要么升版本，禁止「静默改协议」。这条规矩把大量上线当天的联调事故提前到设计阶段消灭。

八、关键实现

认证过滤器（GlobalFilter）

统一校验 JWT 并透传身份，未通过直接拦截。

@Component
public class AuthFilter implements GlobalFilter, Ordered {

    @Autowired private JwtService jwtService;

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String token = exchange.getRequest().getHeaders().getFirst("Authorization");
        if (token == null || !token.startsWith("Bearer ")) {
            exchange.getResponse().setStatusCode(HttpStatus.UNAUTHORIZED);
            return exchange.getResponse().setComplete();
        }
        try {
            Claims claims = jwtService.verify(token.substring(7));
            exchange.getAttributes().put("userId", claims.getSubject());
            exchange.getAttributes().put("tenantId", claims.get("tenantId"));
            exchange.getAttributes().put("roles", claims.get("roles"));
        } catch (Exception e) {
            exchange.getResponse().setStatusCode(HttpStatus.UNAUTHORIZED);
            return exchange.getResponse().setComplete();
        }
        return chain.filter(exchange);
    }

    @Override public int getOrder() { return -100; }
}

限流熔断配置

按租户与接口维度限流，熔断用于非核心依赖降级。

spring:
  cloud:
    gateway:
      routes:
        - id: trade-service
          uri: lb://trade-service
          predicates:
            - Path=/api/trade/**
          filters:
            - name: RequestRateLimiter
              args:
                key-resolver: "#{@tenantKeyResolver}"   # 按租户维度限流
                redis-rate-limiter.replenishRate: 200
                redis-rate-limiter.burstCapacity: 400
            - name: CircuitBreaker
              args:
                name: tradeCb
                fallbackUri: forward:/fallback/trade

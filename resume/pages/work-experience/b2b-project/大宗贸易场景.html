平台支持的交易模式与履约闭环

Trading Modes & Fulfillment Loop - 五种交易模式如何走进签约—支付—交收—开票的闭环

项目背景：B2B 大宗商品交易平台的难点不在"能不能交易"，而在撮合方式各异 + 履约环节极长。不同客户用挂牌、竞价、询价、招标、基差点价五种截然不同的成交方式，成交之后还要走签约、支付、仓单过户/发货、税务开票。这些模式与闭环，正是由我参与建设的平台业务中台承载——底层 C 语言内存撮合引擎负责高并发撮合，Java 微服务业务中台负责业务编排，两者经自研 DS 数据中心（防腐层）异构桥接。

我的角色：技术经理 / Java 侧负责人。我负责把五种交易模式统一抽象为可配置的成交策略，并把它们接入同一条履约闭环（状态机 + Saga 长流程）；交易模式的差异化通过配置化承载，履约侧统一复用合同中心的能力。下文先讲五种交易模式，再讲它们如何汇入"交易→签约→支付→仓单过户/发货→税务开票→完成"这一条闭环。

五种交易模式

1. 挂牌交易

卖方（或买方）挂出明确的"商品、数量、价格、交割地"，对手方直接下单成交。价格透明、即时性强，是大宗交易最基础的"明码标价"模式。

我的关注点：挂牌单进入撮合引擎前的库存/额度校验，成交后一次性生成订单并进入签约流程；挂牌价格与数量的变更走配置化的风控规则。

2. 竞价交易（竞买/竞卖）

由一方发起，多方在规定时窗内出价，按规则（最高价/最低价/延时规则）决胜。适合紧俏货源或需要"价高者得"的资源，价格由市场博弈形成。

我的关注点：竞价的时间窗、延时规则、出价门槛由租户配置决定；出价与结算是高并发场景，撮合在 C 内存引擎完成，成交结果经 DS 数据中心回传 Java 侧生成订单，幂等处理重复成交事件。

3. 询价交易

买方发出询价单（品名、数量、交割要求），多个卖方报盘，买方择优确认。过程非公开、可议价，适合需要多轮沟通的定制化或大额交易。

我的关注点：询价单与报价单是一对多关系，需保证"同一询价只确认一个成交"（分布式锁 + 状态机），确认后按选中的报价单生成合同。

4. 招标交易

招标方发布标书（含资质、技术、商务要求），供应商投标，经资格与评分评审后定标。流程更正式、可追溯，适合集团化采购与合规要求高的场景。

我的关注点：招标有多阶段审批 + 评标评分，我把流程节点做成可配置的审批链模板，评分规则走 Drools，适配不同客户的合规流程。

5. 基差点价交易

成交价 = 基准价（挂钩行业指数/期货价）+ 基差。签约时先确定数量与基差，价格随指数在约定窗口内点价确定。既锁定供需，又保留价格弹性，是矿山/钢厂长协常用的定价方式。

我的关注点：点价事件触发时需调用外部行情源（外联网关统一适配），点价时点与结果必须留痕（事件溯源），后续资金与开票按点价后的最终价计算，避免价格争议。

实现：交易模式抽象为可配置策略

五种模式若各写一套代码，必然膨胀。我的抽象是：交易模式 = 策略 + 配置——统一的成交回调入口，按租户配置的成交策略分派；价格形成、决胜规则、点价窗口全部配置化，新增模式只加策略实现。 

/** 成交策略：五种交易模式共用同一成交回调，差异由策略与配置承载 */
public interface TradeModeStrategy {
    TradeMode mode();
    /** 撮合引擎成交回调 -> 生成平台订单（经 DS 数据中心桥接） */
    Order onMatched(MatchResult match);
}

@Service
public class TradeModeDispatcher {

    private final Map<TradeMode, TradeModeStrategy> strategies;

    public TradeModeDispatcher(List<TradeModeStrategy> list) {
        this.strategies = list.stream()
            .collect(Collectors.toMap(TradeModeStrategy::mode, Function.identity()));
    }

    /** 按租户配置的交易模式分派；成交事件幂等消费 */
    public Order dispatch(String tenantId, MatchResult match) {
        TradeMode mode = tenantConfigRepository.get(tenantId).tradeMode();
        TradeModeStrategy strategy = strategies.get(mode);
        if (strategy == null) throw new BusinessException("未支持的交易模式: " + mode);
        return idempotentConsumer.consume(match.getMatchId(), () -> strategy.onMatched(match));
    }
}

public enum TradeMode {
    LISTING("挂牌"), AUCTION("竞价"), INQUIRY("询价"),
    TENDER("招标"), BASIS_PRICING("基差点价");
    private final String desc;
    TradeMode(String desc) { this.desc = desc; }
}

/** 基差点价：最终价 = 基准价 + 基差，点价事件留痕 */
@Service
public class BasisPricingStrategy implements TradeModeStrategy {

    @Autowired private ExternalGateway externalGateway; // 行情源适配

    @Override public TradeMode mode() { return TradeMode.BASIS_PRICING; }

    @Override public Order onMatched(MatchResult match) {
        BigDecimal base = marketIndexService.latest(match.getIndexCode());
        BigDecimal finalPrice = base.add(match.getBasis());
        eventStore.append(new PricePricedEvent(match.getMatchId(), base, match.getBasis(), finalPrice));
        return orderService.create(match, finalPrice);
    }
}

履约闭环：交易 → 完成

交易成交

签约（合同中心）

支付结算

仓单过户 / 发货

税务开票

履约完成

闭环的关键在于：无论哪种交易模式成交，成交都收敛为一份合同，后续环节对模式无感。合同中心用状态机驱动"签约→支付→交收→开票→完成"，用 Saga + 事件溯源保证跨环节一致性（详见"业务模块"与"合同履约"两页）。

  • 交易 → 签约：成交结果经 DS 数据中心回传，幂等生成合同，租户配置决定合同模板与审批链；
  • 签约 → 支付：电子签章双签完成后进入支付，支持预付款/尾款/分期及复杂资金组合；
  • 支付 → 交收：组织交收走仓单过户，自由交收走自行发货 + 物流轨迹；
  • 交收 → 开票 → 完成：收货/完成才可开票，开票保证金按配置冻结/解冻，全部资金流水供日终对账。

行业背景（一句话）

大宗商品多为标准化工业原料（煤炭、钢铁、矿石、农产品等），交易金额大、周期长、涉及仓储物流金融多环节；上下游（矿山/钢厂/电厂/贸易商）常以长协锁定供需，并借助期货市场对冲价格波动。平台的价值正是把这些分散的线下撮合与履约动作，沉淀为可配置、可追溯、资金安全的在线闭环。

公共服务模块

Common Services - 平台级公共能力，沉淀通用能力、避免各业务微服务重复造轮子

核心定位：公共服务模块是平台级基础设施，位于业务微服务之下、为其提供文件、消息、字典、定时、数据同步等通用能力。它的价值不是"多一个服务"，而是让几十个业务微服务在存储、推送、配置、调度、数据同步上统一收口——口径一致、复用一致、运维一致。

核心能力实现

文件存储（MinIO 对象存储）

合同附件、发票 PDF、物流单据、签章文件全部走统一文件服务，底层 MinIO。业务方只拿 fileId，存储实现与桶策略对业务透明；上传走预签名直传，避免大文件占用应用带宽。 

@Service
public class FileStorageService {

    @Autowired private MinioClient minioClient;

    /** 预签名上传：前端直传 MinIO，返回 fileId，业务只存 fileId */
    public PresignedUpload presignedPut(String bizType, String ext) {
        String objectKey = bizType + "/" + UUID.randomUUID() + "." + ext;
        String url = minioClient.getPresignedObjectUrl(
            GetPresignedObjectUrlArgs.builder()
                .method(Method.PUT)
                .bucket(bucketOf(bizType))
                .object(objectKey)
                .expiry(15, TimeUnit.MINUTES)
                .build());
        return new PresignedUpload(objectKey, url);
    }

    /** 下载：返回短时效预签名 URL，不暴露对象存储内网地址 */
    public String presignedGet(String objectKey) {
        return minioClient.getPresignedObjectUrl(
            GetPresignedObjectUrlArgs.builder()
                .method(Method.GET)
                .bucket(bucketOf(objectKey))
                .object(objectKey)
                .expiry(10, TimeUnit.MINUTES)
                .build());
    }
}

字典 / 配置管理（多租户 + 缓存）

字典项与业务配置按租户维度隔离，一次读取后写入 Redis 缓存；配置变更通过消息通知各节点失效本地缓存。这是多租户可配置化的底层支撑——合同模板、资金比例、交易模式的配置都从这里读。 

@Service
public class TenantConfigService {

    @Autowired private TenantConfigRepository repository;
    @Autowired private RedisTemplate<String, String> redis;

    private static final String KEY = "cfg:%s:%s"; // 租户 + 配置键

    /** 读配置：先缓存，回源后写入；租户隔离 */
    public String get(String tenantId, String cfgKey) {
        String key = String.format(KEY, tenantId, cfgKey);
        String cached = redis.opsForValue().get(key);
        if (cached != null) return cached;

        String value = repository.find(tenantId, cfgKey).getValue();
        redis.opsForValue().set(key, value, 30, TimeUnit.MINUTES);
        return value;
    }

    /** 变更后主动失效缓存（由配置变更消息触发） */
    @EventListener
    public void onConfigChanged(ConfigChangedEvent e) {
        redis.delete(String.format(KEY, e.getTenantId(), e.getCfgKey()));
    }
}

定时任务（XXL-Job 统一调度）

所有定时任务（日终对账、报表生成、超期提醒、outbox 投递）统一由 XXL-Job 调度，自带分片、失败重试与告警。任务代码只关注业务逻辑，调度与容错由平台负责。 

@Component
public class OutboxDispatchJob {

    @Autowired private OutboxRepository outboxRepository;
    @Autowired private KafkaTemplate<String, String> kafkaTemplate;

    /** outbox 可靠投递：分片拉取未发送消息 -> 投 Kafka -> 标记已发送 */
    @XxlJob("outboxDispatchJob")
    public void dispatch() {
        List<OutboxMessage> pending = outboxRepository.findPending(0, 200);
        for (OutboxMessage msg : pending) {
            kafkaTemplate.send(msg.getTopic(), msg.getIdempotentKey(), msg.getPayload());
            outboxRepository.markSent(msg.getId());
        }
    }
}

CDC 数据同步（Canal 增量订阅）

通过 Canal 订阅 MySQL binlog，把变更投递到 Kafka，供ES 检索、缓存刷新、数据异构同步消费。业务代码不感知同步逻辑，避免在业务里散落"双写"。 

@Component
public class ContractCanalListener {

    @Autowired private KafkaTemplate<String, String> kafkaTemplate;

    /** Canal 监听合同表变更，投递到 Kafka 供检索/缓存消费 */
    @CanalEventListener
    public void onEvent(CanalEntry.EventType type, CanalEntry.RowData rowData) {
        Map<String, String> change = Maps.newHashMap();
        rowData.getAfterColumnsList().forEach(c -> change.put(c.getName(), c.getValue()));

        kafkaTemplate.send("cdc.contract",
            change.get("contract_id"), JsonUtil.toJson(change));
    }
}

分布式锁（Redisson）

对"同一询价只确认一个成交""同一合同只允许一次结算"等临界区，用 Redisson 分布式锁串行化，配合幂等键防止并发重复处理。这是公共能力，被业务中台多处复用。 

@Service
public class DistributedLockService {

    @Autowired private RedissonClient redisson;

    /** 以业务号加锁，锁内执行临界逻辑，避免并发重复处理 */
    public <T> T executeWithLock(String lockKey, long waitMs, Supplier<T> action) {
        RLock lock = redisson.getLock("lock:" + lockKey);
        try {
            if (!lock.tryLock(waitMs, 30, TimeUnit.SECONDS)) {
                throw new BusinessException("操作过于频繁，请稍后重试");
            }
            return action.get();
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new BusinessException("锁获取被中断");
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }
}

关键决策与价值

能力收口

存储/推送/字典/调度统一出口，避免各服务重复实现

对业务透明

业务只依赖 fileId/配置键，不感知底层存储与同步实现

多租户支撑

字典/配置按租户隔离，是可配置化落地的底座

性能与稳定

缓存 + 预签名直传 + 分片调度，核心接口稳定 200ms 内

统一调度

XXL-Job 承载日终对账等任务，对账 9 人天 → 2 小时

数据一致

CDC 增量同步 + outbox 可靠投递，支撑最终一致

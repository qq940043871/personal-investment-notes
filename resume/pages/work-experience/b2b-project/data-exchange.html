Data Service Center · Anti-Corruption Layer — 收敛 C 撮合引擎与 Java 微服务之间的协议转换、可靠性与可观测性

技术经理 / Java 侧负责人 异构桥接层 C ↔ Java 协议互通

一、项目背景与要解决的问题

平台是「C 内存撮合引擎 + Java 微服务业务中台」的异构组合。撮合引擎用 C 写、以 TCP 自定义二进制协议与 Hessian 通信；业务中台是 Spring Cloud 微服务。两者天然在语言、协议、团队、迭代节奏上都不一样。早期各 Java 服务直接点对点调用 C 引擎，问题很快暴露：

强耦合

每个 Java 服务都自己拼装 C 侧报文、自己处理 Socket 连接与超时，协议一变要改一圈。

可靠性散落

重试、幂等、降级逻辑重复实现且实现不一致，偶发重复下单、丢单难以定位。

不可观测

跨语言调用没有统一 traceId，出问题只能靠两边各自翻日志，定位靠猜。

核心定位：把 C 与 Java 之间的协议转换、可靠性、可观测性统一收敛到 DS 数据中心这一层防腐层（Anti-Corruption Layer）。Java 侧只面向 DS 的统一报文编程，不感知 C 侧协议细节；C 团队与 Java 团队由此可以各自独立演进、互不阻塞。

四、关键设计决策与踩坑

决策一 · 统一报文，所有调用都必须带 requestId 与 traceId

早期各家自定义字段，幂等无从下手。我们规定：无论 Hessian 还是 TCP 二进制，进入 DS 后一律归一为统一报文，requestId 用于幂等去重，traceId 用于全链路追踪，timestamp + version + signature 用于时序、兼容与安全。

决策二 · 幂等前置到 DS：同一 requestId 命中即返回原结果

踩过的坑：网络抖动触发重试，撮合侧被重复下达同一笔委托，出现重复成交。修复做法是把幂等做成 DS 的职责——用 requestId 在 Redis 建立「处理中/已完成」状态，重试命中已完成直接回放原响应，绝不让重复请求打到 C 引擎。

决策三 · 超时与重试必须成对设计

不同能力设置差异化超时：查询类短超时 + 自动重试；资金/委托类短超时 + 不自动重试，交由幂等与对账兜底。踩坑：曾把委托类接口也配成自动重试，造成重复委托；此后强制「重试开关 + 幂等能力」两者必须同时具备才允许开启。

决策四 · 降级分级 + 链路追踪可观测

把 C 侧能力划分核心（委托/成交/行情）与非核心（统计/报表），核心能力优先保障并有独立资源池，非核心快速失败不拖垮主链路；同时 traceId 从 Java 入口一路透传到 C 侧返回值，排障时两端日志可凭 traceId 对齐。

决策五 · 数据同步改造成 Kafka 事件驱动 + Outbox

原先 Java 服务之间点对点直连同步数据，耦合重、易丢消息。改造为 Kafka 事件驱动：业务写库与发消息通过本地消息表（Outbox）保证原子，消费端按业务键幂等去重，支持重放补偿。DS 承担统一的消息编解码与投递。

五、统一报文格式

{
  "header": {
    "requestId": "uuid-xxx-xxx",      // 幂等去重键
    "traceId":   "trace-xxx-xxx",     // 全链路追踪
    "timestamp": 1699999999999,
    "source":    "trade-service",
    "target":    "matching-engine",
    "version":   "1.0.0"
  },
  "body": {
    "action": "placeOrder",
    "data": { "contractNo": "C2020001", "price": 1850, "quantity": 100 }
  },
  "signature": "sha256..."
}

Header

请求元信息：requestId（幂等）、traceId（追踪）、timestamp、source/target、version。

Body

业务数据载体：动作 + 具体业务数据，与 C 侧能力一一对应。

Signature

安全签名，确保报文完整性与来源可信。

六、关键实现

协议适配器（Hessian ↔ 统一报文）

协议适配层将 Hessian 与 TCP 二进制统一进出，Java 侧只面向统一报文编程。

// 协议适配器：双向转换 C 侧二进制 <-> 统一报文
@Component
public class HessianProtocolAdapter implements ProtocolAdapter {

    @Override
    public UnifiedMessage deserialize(byte[] data) throws Exception {
        Hessian2Input input = new Hessian2Input(new ByteArrayInputStream(data));
        Object raw = input.readObject();   // C 侧 Hessian 对象
        input.close();
        return convertToUnified(raw);      // 归一为统一报文
    }

    @Override
    public byte[] serialize(UnifiedMessage msg) throws Exception {
        ByteArrayOutputStream bos = new ByteArrayOutputStream();
        Hessian2Output output = new Hessian2Output(bos);
        output.writeObject(convertToHessian(msg));
        output.flush();
        output.close();
        return bos.toByteArray();
    }
}

public interface ProtocolAdapter {
    UnifiedMessage deserialize(byte[] data) throws Exception;
    byte[] serialize(UnifiedMessage msg) throws Exception;
}

Kafka + Outbox + 消费幂等

写库与发消息保持一致，消费端幂等去重，替代点对点直连同步。

// 事务内写业务表 + 写 outbox 本地消息表（同一本地事务，保证原子）
@Service
public class TradeEventPublisher {

    @Autowired private TradeOrderMapper orderMapper;
    @Autowired private OutboxMapper outboxMapper;

    @Transactional
    public void placeOrder(TradeOrder order) {
        orderMapper.insert(order);
        outboxMapper.insert(OutboxMessage.builder()
            .bizKey(order.getOrderNo())                 // 幂等键
            .topic("trade.order.created")
            .payload(JSON.toJSONString(order))
            .status("NEW")
            .build());
    }
}

// 消费端：按 bizKey 幂等，重复投递直接丢弃
@KafkaListener(topics = "trade.order.created")
public void onOrderCreated(String payload) {
    OutboxMessage msg = JSON.parseObject(payload, OutboxMessage.class);
    if (!dedupService.markConsumed(msg.getBizKey())) {
        return;   // 已消费过，跳过
    }
    settlementService.onOrderCreated(msg);
}

Redisson 分布式锁 + 缓存

撮合前的资源互斥（如同一合约的结算批次）用 Redisson 分布式锁；热点数据（合约字典、行情快照）走缓存降低 C 侧压力。

@Service
public class MatchLockService {

    @Autowired private RedissonClient redisson;
    @Autowired private StringRedisTemplate cache;

    // 分布式锁：同合约结算批次互斥，看门狗自动续期
    public <T> T withContractLock(String contractNo, Supplier<T> action) {
        RLock lock = redisson.getLock("ds:contract:" + contractNo);
        lock.lock(30, TimeUnit.SECONDS);
        try {
            return action.get();
        } finally {
            lock.unlock();
        }
    }

    // 行情快照缓存：降级时兜底返回最近快照
    public String latestSnapshot(String contractNo) {
        return cache.opsForValue().get("ds:snapshot:" + contractNo);
    }
}

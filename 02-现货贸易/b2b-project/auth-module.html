认证与权限模块

Authentication & Authorization - 统一认证、单点登录与角色权限收口

项目背景：平台服务多家企业（多租户），用户分属不同租户、不同角色（买方/卖方/运营/管理员），且对外只有中间件网关这一个统一入口。认证与权限必须在这里收口：谁进得来（认证）、进来能干什么（角色权限）、跨系统如何一次登录（单点登录）。它是平台的安全边界，也是多租户隔离的第一道闸门。

我的角色：技术经理 / Java 侧负责人。我负责这块的技术选型与边界定义：确定采用"统一 Token 认证 + 网关集中校验 + RBAC 角色权限"的成熟方案组合，而不是自研一套复杂的认证协议。我关注的是多租户下的权限隔离与认证在网关侧的一致收口，具体实现由团队落地。

技术选型与边界（如实说明）

  • 采用：基于服务端会话式统一 Token（DS 中心化签发、Redis 存储与主动巡检失效）的统一认证、网关集中校验、RBAC 角色权限、登出全系统广播；
  • 不自研：不自行实现 OAuth2/OIDC 全套协议栈，认证协议、加密算法、密码存储走成熟标准与组件，平台只做集成与编排；
  • 边界：认证负责"身份可信"，权限负责"能否访问"，二者都在网关侧收口，业务微服务不再各自维护鉴权逻辑。

核心实现

1. 统一认证 + 网关集中校验

登录成功后签发 Token（含用户与租户标识），之后所有请求在中间件网关统一校验 Token 合法性与有效期；校验通过才放行到业务微服务。业务侧只从网关注入的身份上下文取用户，不重复鉴权。 

@Service
public class AuthService {

    @Autowired private UserRepository userRepository;
    @Autowired private TokenService tokenService;      // 标准 Token 签发/校验
    @Autowired private PasswordEncoder passwordEncoder; // 标准密码编码器

    public LoginResponse login(LoginRequest req) {
        User user = userRepository.findByUsername(req.getUsername());
        // 统一提示，避免暴露"用户是否存在"
        if (user == null || !passwordEncoder.matches(req.getPassword(), user.getPassword())) {
            throw new BusinessException("用户名或密码错误");
        }
        if (user.isDisabled()) {
            throw new BusinessException("账号已被禁用");
        }
        String token = tokenService.issue(user); // 内含 userId / tenantId / roles
        return LoginResponse.of(token, user.toSafeInfo());
    }

    public void logout(String userId) {
        tokenService.revoke(userId); // 会话失效，网关后续校验不通过
    }
}

2. RBAC 角色权限：菜单 + 接口

权限模型为"用户 → 角色 → 权限"。登录后加载用户的菜单权限树（前端渲染导航）与接口权限集合（网关侧做接口级拦截）。角色与权限按租户维护，天然隔离。 

@Service
public class UserPermissionService {

    @Autowired private RoleRepository roleRepository;
    @Autowired private MenuRepository menuRepository;
    @Autowired private ApiPermissionRepository apiPermissionRepository;

    /** 按用户加载菜单树 + 接口权限；均限定在当前租户内 */
    public UserInfoDTO loadUserInfo(Long userId, Long tenantId) {
        List<Role> roles = roleRepository.findByUserAndTenant(userId, tenantId);
        List<Long> roleIds = roles.stream().map(Role::getId).collect(Collectors.toList());

        List<Menu> menus = menuRepository.findByRoles(roleIds);
        Set<String> apiPerms = apiPermissionRepository.findByRoles(roleIds).stream()
            .map(ApiPermission::getPermission)
            .collect(Collectors.toSet());

        return UserInfoDTO.builder()
            .userId(userId)
            .roles(roles.stream().map(Role::getCode).collect(Collectors.toList()))
            .menus(buildMenuTree(menus))   // 菜单树
            .apiPermissions(apiPerms)      // 接口权限，供网关拦截
            .build();
    }

    /** 菜单由 parentId 递归组装成树 */
    private List<MenuDTO> buildMenuTree(List<Menu> menus) {
        Map<Long, List<Menu>> grouped = menus.stream()
            .collect(Collectors.groupingBy(Menu::getParentId));
        return build(grouped, 0L);
    }

    private List<MenuDTO> build(Map<Long, List<Menu>> grouped, Long parentId) {
        return grouped.getOrDefault(parentId, List.of()).stream()
            .map(m -> MenuDTO.builder()
                .id(m.getId()).name(m.getName()).path(m.getPath()).icon(m.getIcon())
                .children(build(grouped, m.getId()))
                .build())
            .collect(Collectors.toList());
    }
}

3. 单点登录（SSO）

平台内多个子系统（交易、合同、结算、运营后台）共享一次登录状态：认证中心集中签发会话票据，各子系统凭票据到认证中心校验，无需各自维护登录。登出时统一失效会话，实现"一处登出、多处下线"。

4. 多租户权限隔离

每个用户归属于一个租户，Token 中携带租户标识；网关与业务侧强制以租户维度过滤数据与权限，从认证层就杜绝跨租户越权访问。这是"一套引擎 + 每客户一套配置"能在权限层面成立的前提。

5. 会话与登录安全基线

内建基础登录安全：登录失败次数计数与临时锁定、账号禁用/启用、会话有效期与主动失效、登出联动。这些是平台安全基线的一部分，由团队按统一规范实现。 

@Service
public class LoginFailService {

    @Autowired private RedisTemplate<String, String> redis;

    private static final String FAIL_KEY = "login:fail:";
    private static final int MAX_FAIL = 5;

    /** 记录失败次数，达到阈值临时锁定（基于 Redis 计数，自动过期） */
    public void recordFail(String username) {
        String key = FAIL_KEY + username;
        Long count = redis.opsForValue().increment(key);
        if (count != null && count == 1) {
            redis.expire(key, 1, TimeUnit.HOURS);
        }
        if (count != null && count >= MAX_FAIL) {
            redis.opsForValue().set("login:lock:" + username, "1", 30, TimeUnit.MINUTES);
        }
    }

    public boolean isLocked(String username) {
        return Boolean.TRUE.equals(redis.hasKey("login:lock:" + username));
    }

    public void clearFail(String username) {
        redis.delete(FAIL_KEY + username);
    }
}

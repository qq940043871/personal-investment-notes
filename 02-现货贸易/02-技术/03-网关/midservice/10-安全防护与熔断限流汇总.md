## 第二部分：熔断限流与慢协议隔离（现状 vs 目标）

### 1. 源码现状：只有"简化 / 人工版"

| 能力 | 源码实际 | 缺失 |
|---|---|---|
| 熔断 | **系统级全站熔断**（人工 `SysPara 40310`，发版维护用） | 无单协议自动熔断、无三态/半开探针 |
| 限流 | **批量协议数量上限** `maxMultiApiCount` | 无 QPS 限流、无租户/接口分级配额 |
| 隔离 | 无 | 无舱壁、无超时分层 |
| 间接缓解 | Redis 缓存、用户维度锁、Greencard、慢接口告警（只观察不阻断） | — |

### 2. 根因

> **一请求一线程、自顶向下全同步阻塞，协议之间共享同一批执行资源。**

三个病灶：共享 Tomcat 线程池 · 全局串行点（`DSUtils.getClient()` static synchronized ×135 调用点、`releaseConnection()`、`ShardedReidsPool.getConnect()`）· 无熔断无舱壁。**五类放大机制的源码位置见 08 §五。**

### 3. 事故佐证（瓶颈后移）

> 扩容 ×5 后入口容量放大、DB 出口不变，**几分钟打穿 DB 全站不可用**；扩容是放大器不是解药，先限流再扩容。

### 4. 目标态设计（五层防线 + 四支柱）

**五层防线**：网关限流/熔断/降级 → 后端接口级限流 + 连接池隔离 → 缓存 90% 命中 → DB 连接数与慢查询治理 → 架构规范兜底。

**四支柱**：异步化 ＋ 舱壁 ＋ 熔断 ＋ 无状态。**四件套**（熔断三态、逐层递减超时且不自动重试、每协议令牌桶、有界队列背压）完整设计见 **03 §五–§七**；落地顺序见 **01 §5**。

### 5. 配置基线（只给指针）

| 层 | 参数 | 权威文档 |
|---|---|---|
| 网关 | 慢接口全局限流 200 QPS / 单实例 40 QPS、连接池 20、超时 1s | `../../03-问题排查/11` §4.1 |
| 网关 | 熔断判据（慢调用 ≥50%、5s 半开）、全局锁与舱壁改造项 | `midservice/03` §七/§八 |
| 连接池 | DS `maxCon`、`SOCKET_MAX`、`http.maxConnections`、Tomcat 线程 | `midservice/05` |
| 容量目标 | 读 5 万 QPS / 写 1000 TPS 逐跳核对与验收门槛 | `midservice/01` §2/§8 |
| 实例数口径 | 读链路 3 节点；写链路扩容后 5 实例 | `midservice/01` §2.2、`../../03-问题排查/11` |

### 6. 隔离验收硬标准

> 注入 5s 慢协议，快协议 P99：隔离前 50ms → 5s+，隔离后稳定 50ms 内。压测步骤见 **02 §八**。

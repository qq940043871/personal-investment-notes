竞价行情推送架构全景（三合一）

前端要保证「竞价状态 + 倒计时」始终准确，依赖三件事咬合：① 推拉分离决定数据从哪来、快不快；② 三层检测保证连接假死、数据停流一定被发现；③ 五步恢复时序保证断线重连后状态与倒计时重新对齐，而不是停在断线那一刻。三者缺一，页面都会出现「看着正常、数据已死」。

贯穿主线：独立 WS 通道收增量（快） → 三层检测发现故障（不漏报） → 重连后按 ③拉快照 + ④校时钟 重建基准（状态准、倒计时准） → 重订阅从最新 seq 开始（不回退、不串台）。

一竞价行情推送架构：推拉分离

推送由 C 撮合引擎直推独立 WebSocket 服务，不经 dataShare 中继；查询仍走 midservice 网关。两条通道不共用任何节点，独立扩容、独立发布、独立故障。

推送通道（只发不取） 查询通道（只取不推） 客户端状态

二复杂网络环境下 WebSocket 的稳定性设计：故障 / 检测 / 兜底

WebSocket 在真实互联网里必然断。真正的难题不是断线后怎么重连，而是「客户端不知道自己已经断了」——所以检测必须做三层。

故障形态 三层检测 兜底动作

三从断线到恢复：五步时序

重连不等于重订阅。第三、四步（拉快照、校时钟）最常被省略——代码不报错、页面显示「已连接」，但价格和倒计时永远停在断线那一刻。

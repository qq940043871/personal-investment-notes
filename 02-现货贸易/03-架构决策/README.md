# 03-架构决策 · 设计与决策叙事库

> **本目录回答一个问题：为什么这么设计、被追问时怎么讲。**
> 文体是"设计文档 + 叙事手册"：每篇都要能支撑评审与面试追问，因此强调**口径标注**（哪句是底稿、哪句是推演）与**依据指针**（结论指向哪份源文档 / 哪段代码）。

**不写进本目录的三类内容**：

1. **源码细节复述** —— 需要行号证据的放 `midservice/`、`dataShare/`，本文档只引用结论。
2. **与已有手册重复的科普** —— 例如 JVM 参数怎么调、缓存三大问题，属于 `arch/`。
3. **未标注的"已实现"** —— 设计推演必须写【设计推演】，不能与项目事实混写。

## 五、写作约定（本目录所有文档共同遵守）

1. **口径标注**：`【源文档】` = 源自项目设计源文档；`【底稿口径】` = 项目底稿已写明；`【设计推演】` = 本文推导，**不代表已实现**，面试必须说成"设计思路"；`【归纳】` = 对源文档的整理。

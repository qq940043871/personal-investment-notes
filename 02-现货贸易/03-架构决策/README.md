# 03-架构决策 · 设计与决策叙事库

> **本目录回答一个问题：为什么这么设计、被追问时怎么讲。**
> 文体是"设计文档 + 叙事手册"：每篇都要能支撑评审与面试追问，因此强调**口径标注**（哪句是底稿、哪句是推演）与**依据指针**（结论指向哪份源文档 / 哪段代码）。

---

## 一、这一层负责什么（边界）

| 内容类型 | 归属 | 说明 |
|---|---|---|
| 架构方法论、选型取舍、机制设计、面试追问预案、机制图 | **本目录** | 讲"为什么"与"怎么答"，允许设计推演但必须标注 |
| 源码走读、缺陷清单、容量测算、压测数据 | `../b2b-project/` | 讲"代码里是什么"，要 `文件:行号` |
| 通用工程问题（20 章） | `../电商项目问题指南/` | 行业方案 + 经验锚点 |
| 业务价值、客户案例 | `../01-业务与价值/`、`../02-客户与案例/` | 业务语言 |

**不写进本目录的三类内容**：

1. **源码细节复述** —— 需要行号证据的放 `b2b-project/`，本文档只引用结论。
2. **与已有手册重复的科普** —— 例如 JVM 参数怎么调、缓存三大问题，属于 `电商项目问题指南`。
3. **未标注的"已实现"** —— 设计推演必须写【设计推演】，不能与项目事实混写。

## 五、写作约定（本目录所有文档共同遵守）

1. **口径标注**：`【源文档】` = 源自项目设计源文档；`【底稿口径】` = 项目底稿已写明；`【设计推演】` = 本文推导，**不代表已实现**，面试必须说成"设计思路"；`【归纳】` = 对源文档的整理。
2. **三句话开头**：每篇前部给出"被问到时先答这三句"，再展开细节。
3. **追问链**：复杂主题必须带「高频追问预案」，回答要能继续往下接。
4. **依据指针**：结尾列"要查什么 → 去哪"，指向源文档或代码位置，避免结论无根。
5. **单一信息源**：同一结论只维护一份，其余位置放指针（见第四节）。

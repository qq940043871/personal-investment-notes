## 📖 概述

高可用（High Availability）是交易系统的生命线。一次宕机可能造成可观损失。本章介绍高可用的通用方案，并标注本人已落地与未落地的部分。

## 🏗️ 一、高可用架构设计

### 1.1 什么是高可用

**可用性指标**：
```
可用性 = MTBF / (MTBF + MTTR) × 100%

MTBF (Mean Time Between Failures)：平均故障间隔时间
MTTR (Mean Time To Repair)：平均修复时间
```

| 可用性 | 年故障时间 | 适用场景 |
|--------|-----------|----------|
| 99% | 3.65天 | 普通系统 |
| 99.9% | 8.76小时 | 企业级 |
| 99.99% | 52分钟 | 电商核心 |
| 99.999% | 5分钟 | 金融级 |

### 1.2 高可用架构原则

```
1. 消除单点故障 (Single Point of Failure)
2. 冗余设计 (Redundancy)
3. 故障隔离 (Fault Isolation)
4. 快速故障转移 (Failover)
5. 优雅降级 (Graceful Degradation)
```

## 🔄 二、故障转移机制

### 2.1 数据库故障转移

```
┌─────────┐      自动切换       ┌─────────┐
│  主库   │ ─────────────────► │  从库   │
│(读写)   │                    │(只读)   │
└─────────┘                    └─────────┘
     ▲                             │
     │     自动选主                 │
     └─────────────────────────────┘
```

### 2.2 缓存故障转移

```
正常情况：
┌─────────┐  写入   ┌─────────┐
│ 应用    │ ──────►│ Redis主 │
└─────────┘        └─────────┘

故障时自动切换：
┌─────────┐  写入   ┌─────────┐
│ 应用    │ ──────►│ Redis从 │
└─────────┘        └─────────┘
```

**Sentinel 故障检测**：
```yaml
# Sentinel 配置
sentinel monitor mymaster 127.0.0.1 6379 2
sentinel down-after-milliseconds mymaster 5000
sentinel failover-timeout mymaster 30000
```

## 🔥 三、熔断与降级

### 3.1 熔断器模式

```
                    熔断器状态机
                         
    ┌──────────┐   失败次数超限    ┌──────────┐
    │  关闭     │ ───────────────►│  打开     │
    │ (Closed) │                  │ (Open)   │
    │ 正常熔断  │                  │ 拒绝请求  │
    └────┬─────┘                  └────┬─────┘
         │                              │
         │  成功                         │  半开
         │  ◄────────────────────────  │
         │                              │
         │                        ┌─────▼─────┐
         │                        │   半开     │
         │                        │ (Half-Open)│
         │                        │  探测请求  │
         └────────────────────────┴───────────┘
```

### 3.2 降级策略

| 策略 | 说明 | 示例 |
|------|------|------|
| **接口降级** | 非核心接口关闭 | 关闭商品推荐 |
| **功能降级** | 简化业务流程 | 下单不验库存 |
| **页面降级** | 返回静态页面 | 活动页静态化 |
| **返回兜底** | 返回默认值 | 返回空列表 |

### 3.3 限流策略

**限流算法**：
- 计数器算法
- 滑动窗口算法
- 漏桶算法
- 令牌桶算法

## 📊 四、监控与告警

### 4.1 监控体系

```
┌─────────────────────────────────────────────────────┐
│                    监控金字塔                        │
│                                                     │
│                         ▲                          │
│                        /│\                         │
│                       / │ \                        │
│                      /  │  \                       │
│                     /   │   \                      │
│                    /────┼────\                     │
│                   /     │     \                    │
│                  /──────┼──────\                   │
│                 /       │       \                  │
│           ┌────┴───────┴───────┴────┐            │
│           │      应用层监控         │            │
│           │   (APM / 链路追踪)      │            │
│           └────┬───────┬───────┬────┘            │
│                │       │       │                   │
│           ┌───┴───┐ ┌─┴──┐ ┌──┴───┐            │
│           │基础层 │ │组件 │ │业务层 │            │
│           │监控   │ │监控 │ │监控   │            │
│           └───────┘ └────┘ └──────┘            │
└─────────────────────────────────────────────────────┘
```

### 4.2 核心监控指标

| 指标类型 | 指标项 | 告警阈值 |
|----------|--------|----------|
| **基础监控** | CPU使用率 | > 80% |
| | 内存使用率 | > 85% |
| | 磁盘使用率 | > 90% |
| **应用监控** | 接口QPS | < 基线50% |
| | 接口RT | > 500ms |
| | 错误率 | > 1% |
| **组件监控** | MySQL连接数 | > 80% |
| | Redis内存 | > 90% |
| | MQ积压 | > 10万 |

### 4.3 告警通知

```yaml
# Prometheus AlertManager 配置
groups:
  - name:电商核心服务
    rules:
      - alert: 服务不可用
        expr: up{job="order-service"} == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "订单服务不可用"
          description: "{{ $labels.instance }} 已宕机超过1分钟"
      
      - alert: 高错误率
        expr: rate(http_requests_total{status=~"5.."}[5m]) > 0.05
        for: 5m
        labels:
          severity: warning
```

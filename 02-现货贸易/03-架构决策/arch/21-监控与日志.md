# 21 - 监控与日志

> 如何构建可观测性系统

---

## 📖 概述

可观测性是系统稳定运行的保障。本章介绍 Prometheus + Grafana 指标监控、日志检索与告警体系。

---

## 个人经验锚点

| 分类 | 内容 |
|------|------|
| **真实做过** | **B2B 大宗交易平台**：Elasticsearch 集中式日志检索 + 业务埋点；Micrometer 指标暴露 + Prometheus + Grafana 面板；关键链路告警（资金差错、撮合异常、Kafka 积压、XXL-Job 失败）；**Canal CDC** 同步状态监控 |
| **通用方案/行业知识** | 全链路 APM（SkyWalking/Pinpoint）深度追踪、OpenTelemetry 统一标准、大规模日志采集（Filebeat→Logstash→ES 集群）的容量治理 —— 属行业参考；本人用的是「ES 检索 + Prometheus 指标 + 告警」的中等规模方案 |

## 📝 三、日志收集

### 3.1 日志规范

```java
// 日志规范
@Slf4j
public class OrderService {
    
    public void createOrder(OrderDTO dto) {
        // 使用MDC追踪
        MDC.put("traceId", TraceContext.getTraceId());
        MDC.put("orderId", dto.getOrderId());
        
        try {
            log.info("创建订单, userId={}, skuId={}", dto.getUserId(), dto.getSkuId());
            // 业务逻辑
        } catch (Exception e) {
            log.error("创建订单失败, userId={}", dto.getUserId(), e);
            throw e;
        } finally {
            MDC.clear();
        }
    }
}
```

## 🚨 四、告警规则

```yaml
# AlertManager告警规则
groups:
  - name: ecommerce_alerts
    rules:
      - alert: HighErrorRate
        expr: rate(http_requests_total{status=~"5.."}[5m]) > 0.01
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "接口错误率超过1%"
      
      - alert: HighLatency
        expr: histogram_quantile(0.95, http_request_duration_seconds[5m]) > 0.5
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "P95响应时间超过500ms"
```

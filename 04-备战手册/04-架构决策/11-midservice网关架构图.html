二

契约与参数关

拦截成本 = 本地内存 · 零 IO（契约注册表本地缓存）

未定义字段一律拒绝 —— 不忽略、不透传

② 契约校验

③ 参数预校验

只校验「形状」

④ 压力参数强制校验

防「一次查询拖垮 DB」

批量 ≤ 200 · 排序字段白名单
显式拒绝，不做静默截断

主轴 · 拒绝要早、要便宜：十道关按「拦截成本」归为五档——本地 Map（②③④）→本地计数 + 缓存读（①⑤⑥）→签名计算（⑦）→缓存读 → 网络调用（⑧⑨）→出口治理（⑩）│扫描器在 ② 就被拒，连鉴权都不做。

组件 · 观察者与执行者分离：midservice 是执行者（限流 / 熔断 / 脱敏 / 转发）│midmon 是观察者（只发现并报告，通过配置下发让 midservice 执行）│监控挂了不影响交易，限流策略只有一个执行点。

边界 · 网关不做业务：库存 / 授信 / 状态机 / 事务编排 / 重计算一律下沉业务层│判据：凡需问「这个客户是谁、这笔业务合不合法」才能做的判断，都不属于网关。

跨轨备注（认知对照）：本图为公司项目轨道——Java Web 自研 midservice│其「闸门排序 + 契约即白名单 + 观察者／执行者分离」与个人储备的 Harness 方法论同构，两条轨道口径独立、技术栈不互指。

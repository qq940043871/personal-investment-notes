# 05 技术管理 · 索引（团队 · 流程 · 效能 · 整改 · 稳定性）

> **定位**：本目录是「技术管理」分类的**唯一入口**。管理类事实、证据与话术的**权威版本仍留在既有权威件里**（见 §四 依据指针），本文件只做三件事——**收口口径、给 90 秒速答、给导航**，不复述正文。
> **分类维度**：`04-备战手册/` 下 `00`–`06` 按备战维度（讲什么、何时用）。本目录专答一类题——**"你怎么管研发、怎么带团队、怎么保稳定、怎么还技术债"**；技术深度归 `04-架构决策`，排障归 `04-架构决策/生产问题排查/`，话术归 `06-面试准备`。

## 一、一句话口径

**技术管理 = 机制 × 证据 × 杠杆**：不是自己写代码，而是让对的决策在对的框架下发生。我对团队的产出定义有三层——**交付只是底线，机制（规范 / 复盘 / 辅导）和资产（软著、专利、标准库）才是 leader 的产出**；技术管理的关键，是**把个人经验变成团队能力**。

## 二、90 秒速答（被问"你怎么管研发"时）

> 「我管 **20 人**研发团队——3 人 C 撮合内核、6 人 Java 业务中台、5 人 Vue 前端、5 人测试，向总经理汇报。管理上我做四件事：
> **第一，关键节点强制评审**——需求收口、设计、技术三个评审加 QA 验收、发布评审、移交评审，六个闸门**不通过不流转**，把需求不清、设计不足、测试遗漏的返工挡在开发之前；
> **第二，多项目并行可视化**——需求池 / 已评审 / 开发中三态看板加排期表，优先保关键路径；
> **第三，稳定性三线闭环**——目标层（重大故障 ≤1 次/年、中等故障 ≤3 次/年、首页打开 <1.5 秒、核心业务并发 ≥1000/秒，这是当时定的考核线）、机制层（上线评审 + 压测 + 监控 + On-call）、闭环层（故障报告复盘，重复问题必须转成规范或自动化检查项）；
> **第四，带人**——周技术分享轮流主讲、结对辅导定向带教、调研沉淀进团队知识库。
> 一句话收束：**我不只是管项目进度，更管研发过程的确定性。**」

**换题不换骨架**：换"怎么保质量"→ 只讲第一件；换"多项目怎么排"→ 只讲第二件；换"出了故障怎么办"→ 只讲第三件 + 排障 SOP；换"怎么带人"→ 只讲第四件。

## 五、追问链（三层，练到能脱稿）

| 层 | 追问 | 应答骨架 |
|---|---|---|
| 一层 | 规范真被执行了吗？ | 关键节点**强制过审 + 表单留痕**（评审表 / 发布记录 / 移交记录），不通过不流转；证据取 `12` §8.2 第一类 |
| 二层 | 多项目资源冲突怎么排？ | 三态看板 + 排期表 + 关键路径优先；"业务急 vs 架构不允许"的答法走 `12` §五 Q2（先给边界，再给替代路径与代价） |
| 三层 | 规范会不会拖慢交付？ | 规范的目标是**减少返工**：需求不清、设计不足、测试遗漏三类返工才是最大成本；配套低代码与组件化把交付从写代码变成做配置 |
| 一层 | 团队出故障你第一件事做什么？ | 先止损留证（日志 / 监控 / 操作记录），恢复后复盘定根因、责任人、改进措施，转成规范或自动化检查项 |
| 二层 | 稳定性数字怎么来的？ | 一律加限定语：这是**当时设定的团队目标 / 考核线**，不是长期达成值 |
| 三层 | 带人拿过什么结果？ | 结对辅导 + 周分享 + 调研沉淀；目标口径：节省工作量 **≥5 人月**、自动化测试覆盖率 **≥20%**、专利 / 软著按实际项数（数字均为目标线） |

## 六、讲述口径（讲管理必守）

1. **所有指标带"目标 / 考核线 / 当时定的"限定语**——重大故障 ≤1 次/年这类数字，讲"当时定的考核线"。
2. **报类别名**：客户与内部系统一律用脱敏类别名（证据清单已脱敏）。
3. **简历口径现场保持一致**：13 年、20 人（3/6/5/5）、向总经理汇报、外部接口 **9+**、微服务 12+——全库口径见 `../00-资料库总览.md` §2.1。
4. **叙事版本按岗位二选一**：3 分钟版 A（做成了什么）/ B（架构深潜）/ C（研发管理体系），管理岗用 C；C 的落地证据回 `12` §八，本处只留指针。
5. **讲整改讲主线**：十一项收束成"把定制改代码变成配置与契约"这一条主线（配置化 / 契约化 / 合规 / 复用 / 数据可信五条腿），讲主线与机制。

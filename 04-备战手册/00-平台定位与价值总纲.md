## 一、平台要回答的问题

大宗商品（钢铁、矿石、化工、农产品、能源）是制造业与农业的原材料底座；中国是全球最大的大宗商品消费与进口国之一，年交易规模在 50 万亿量级 `[项目口径]`。这门生意与零售电商的差别，来自四处结构性特征。

| 维度 | 特征 | 由此产生的经营约束 |
|---|---|---|
| 商品 | 非标品，单批品质指标 10 项以上；单笔金额 100 万–1 亿；价格日波动可达 5%；必须实物交割 | 一次品质或价格判断失误，就可能吃掉全部毛利 |
| 参与方 | 单笔交易涉及 5–10 方；买卖双方存在"谁先付款谁先发货"的博弈；中小企业融资成本年化 12–18% `[项目口径]` | 交易卡在信任上，而不是卡在货源上 |
| 流程 | 全履约周期 30–90 天；跨境多式联运；10 种以上单证；滞期费可达数万美元/天 | 链路长、变量多，任何节点延误都会传导成违约 |
| 数字化 | 交易金额与复杂程度远高于零售，线上化程度却显著更低 | 大量单据、对账与风控仍依赖电话、邮件与 Excel |

把这四处约束收敛成一句：货源通常不缺，缺的是跟一个新客户做大额交易的底气。这份底气由两件事决定——付款与发货的先后（交易信任），以及货物权属的真伪（仓单信任）。平台要回答的，正是这两件事。

## 二、一句话定位

面向大宗商品产业链的**全链路数字化交易与合同履约平台**。覆盖钢铁、矿石、化工、农产品、能源等品类，把"线上交易 → 电子签约 → 物理交割 → 资金结算 → 金融增信"串成一条。

本文的核心判断：平台的价值来自一件线下做不到的事——把交易、物流、金融三方产生的真实数据沉淀到同一套合同与履约底座上，再把它转换成资金方敢采信的信用。

## 三、平台是什么：一处刻意保留的复杂度

这个系统之所以"复杂"，来自五层结构必须同时成立；任何一层缺失，整条链路就断。

| 维度 | 构成 | 为什么必须放在一起 |
|---|---|---|
| 三条主线 | 电子交易 · 现代物流 · 供应链金融（三位一体） | 交易产生数据、物流确认真实、金融放大信用 |
| 四件套 | 现货商城 · 基差点价 · 供应链金融 · CTRM | 商城找货、点价锁价、金融供钱、CTRM 管风险 |
| 交易设计与服务 | 6 种交易方式 × 4 档交易周期 × 7 项服务 | 从长协到即期、从协商到竞价，模式与周期正交，必须配置化 |
| 金融资产 | 仓单 / 合同 / 订单 / 债权 四类资产 × 5 类资金方 | 覆盖企业资金链的存货、垫资、预付、挂账四段 |
| 生态规模 | 7 类角色人群 / 15 个系统角色 / 9+ 外部接口 | 商流在线上、物流在网内、资金在监管、信息在平台 |

支撑这五层的技术底座是一组彼此咬合的设计（细节见 `04-架构决策/` 系列）：

- 领域划分：7 个限界上下文（合同 / 履约 / 资金 / 物流 / 票务 / 纠纷 / 配置）`[项目口径]`
- 集成方式：领域事件驱动（EDA），约 14 个领域事件，发布方不感知消费方
- 履约引擎：双轨驱动——顺序交收走状态机，自由交收走事件驱动加规则引擎；5 种交收模式（款到发货 / 货到付款 / 定金尾款 / 分期 / 信用证）
- 资金链路：三层解耦（资金计划"何时付" / 结算账单"付多少" / 支付工具"怎么付"），4 种结算渠道，银行 100% 存管
- 外部连接：9+ 接口（银行、物流、税务、征信、仓单登记等）

其中最根本的一处是合同与履约解耦：合同域只记录商业契约，履约域按交收模式动态生成执行计划。新增一种交收模式时，合同核心代码无需改动，只需新增一个履约策略实现。

## 四、卖给谁：七类生态角色

平台面向七类生态角色，每类在链上位置不同、最关心的问题不同，登录后看到的工作台也不同。

| 生态角色 | 链上位置 | 最关心的问题 | 平台给它的入口 |
|---|---|---|---|
| 上游资源方 | 矿山 / 钢厂 / 炼厂 / 大型种植户 | 高效挂牌、价格发现、收款安全、长协锁价 | 挂牌与定价、款项保障 |
| 贸易商 / 中间商 | 批量采购与拆分销售 | 仓单流转、资金周转、链式合同（A→B→C→D）权责 | 购销与库存、保理与周转 |
| 下游终端用户 | 加工厂 / 建筑 / 制造企业 | 原材料与货期匹配、长协对冲、品质保障 | 采购与比价、质检异议处理 |
| 仓储物流服务商 | 交割仓库 / 第三方监管仓 / 承运 | 仓单注册注销、实物与电子同步、仓储费计收 | WMS 对接、出入库与费用 |
| 金融机构 | 银行 / 保理公司 / 供应链金融平台 | 质押物监控、授信数据、放款线上化 | 质押监控、风控数据、放款流程 |
| 质检机构 | 第三方检测（如 SGS / CCIC） | 报告出具与采信、委托与费用结算 | 委托受理、报告上传 |
| 平台运营方 | 平台公司 / SaaS 服务商 | 交易监管、风控预警、全局数据看板 | 监管与审核、运营分析 |

同一个角色在不同产权性质的企业里，决策逻辑并不相同——国企重合规与流程留痕，民企重效率与利润，外企重标准与总部合规。这决定了同一功能在三类客户里的推广话术（见 `01-产品定位/02` §二-B）。

若按价值链位置切分，还可细分为八类（把中游生产企业与中小买家单列）：上游资源方 / 中游生产企业 / 贸易商 / 中小买家 / 仓储 / 金融 / 物流 / 平台运营方。八类与七类是同一生态的两种切法，不是两套系统。

## 五、解决什么：26 个痛点与一处根因

系统视角的痛点共 26 个，是全局唯一的编号体系（1~26），按 7 个业务环节加 1 组架构治理组织。

| 环节 | 数量 | 编号 | 代表痛点 |
|---|---|---|---|
| 客户 / 账户 | 3 | 1–3 | 开户审核慢、客户主数据各系统不一致、权限混乱 |
| 交易 | 5 | 4–8 | 摘单超卖、撮合时延、7 大交易模式难支持、模式与合同条款割裂、跨期订单混乱 |
| 履约 | 4 | 9–12 | 保证金状态不一致、履约节点跟踪难、违约处置慢、保证金额度难算 |
| 物流 / 仓储 | 3 | 13–15 | 电子仓单造假与重复质押、多仓库存查询难、在途状态不透明 |
| 资金 / 结算 | 4 | 16–19 | 资金不愿在平台过夜、账期长回款慢、对账差错多、发票断点与税务不合规 |
| 信息 / 数据 | 2 | 20–21 | 行情多源不一致、推送延迟且三端不同步 |
| 风控 / 合规 | 2 | 22–23 | 风控数据散落无法全局计算、审计合规数据不完整 |
| 架构治理 | 3 | 24–26 | 无统一商品中心、前端架构老旧、业务流程割裂协同成本高 |

行业视角另有一套 14 个共性痛点（I1–I14），与系统编号存在一一映射，映射表见 `02-业务价值/05` 附录 A。引用时，系统视角写作"痛点 13"，行业视角写作"I3-1"。

把 26 个痛点向上收敛，落点是一个字——信任。它有三种面孔：付款与发货的先后（交易信任）、仓单的真与假（权属信任）、数据的通与断（信息信任）。26 个痛点，本质上是这三种信任在 7 个环节里的具体表现。

## 六、值多少：三层价值与四种价值

价值分三层，逐层升高。

| 价值层 | 内容 | 支撑数据 |
|---|---|---|
| 效率价值 | 帮客户省时间与人力 | 单笔交易周期 5 天到 1.5 天；对账 3 天到 2 小时 `[项目口径]` |
| 风险价值 | 帮客户避资金与合规风险 | 电子仓单加存证，杜绝一货多押；银行 100% 存管 |
| 增长价值 | 帮客户多赚钱、做大生意 | 客户月交易量 20 笔到 50 笔；供应链金融放款 |

在这三层之下，平台对客户的价值可以拆成四种，每种对应线下的一处具体困境。

| 价值 | 解决的线下困境 | 一句高频表达 |
|---|---|---|
| 信任中介 | 不敢跟陌生客户做大额交易 | 把"你跟张老板熟不熟"换成"系统显示这家公司履约率 97%" |
| 信息聚合 | 逐家电话询价、报价不可比 | 一键比价替代逐家问价，采购团队 5 人的活 3 人干 `[项目口径]` |
| 交易效率 | 询价、改合同、跑银行、催发货 | 一笔交易从 5–7 天压到 1–2 天 |
| 金融服务 | 有好机会但缺钱、融资贵 | 把交易信用变成可融资资产，融资成本 18% 降到 8–10% |

可对外引用的量化口径汇总如下，均为项目口径，实际数值以上线后实测替换。

| 指标 | 线下 | 平台 | 依据 |
|---|---|---|---|
| 合同签署周期 | 3–7 天 | 分钟级 | `[项目口径]` |
| 单笔交易周期 | 5 天 | 1.5 天 | `[项目口径]` |
| 财务对账 | 3–5 天 | T+1 自动 | `[项目口径]` |
| 中小企业融资成本 | 年化 18% | 8–10% | `[目标值]` |
| 采购团队人力 | 5 人 | 3 人 | `[项目口径]` |
| 客户月交易量 | 20 笔 | 50 笔 | `[目标值]` |
| 仓单真实性保障 | 依赖人工核验 | 99%+ | `[目标值]` |

供应链金融提供了三种可落地的模式：面向买方的预付款融资、面向贸易商的存货质押（按货值约 70%）、面向卖方的应收账款融资（按应收账款约 80%）。资金方愿意进入的前提，是平台掌握三样线下拿不到的东西——真实交易记录、仓单流转数据、历史履约数据。

## 七、凭什么赢：四件套的信用回路

单个模块的价值有限：只做商城是普通交易网站，只做点价是行情工具，只做金融没有标的，只做 CTRM 是内部风控。四者共用同一套合同与履约底座后，形成一条闭环回路。

```
        交易活跃
       ↗        ↘
   金融渗透 ←  数据变厚
       ↖        ↙
        授信更准
```

图 1：四件套咬合的信用回路——交易产生数据，数据变成信用，信用带来资金，资金放大交易。

这条回路的壁垒来自咬合本身：只做交易的人拿不到信用数据，只做金融的人拿不到真实交易，只做风控的人两头都没有。由此长出五道护城河。

| 护城河 | 为什么难以复制 |
|---|---|
| 数据回路 | 没有交易数据的人做金融靠猜，平台靠算；数据越多，风控越准，客户越多 |
| 配置化引擎 | 规则由多个客户的真实业务沉淀而成，新进入者需要时间才能达到同等灵活度 |
| 外部集成深度 | 已接入多家银行、多个仓库 WMS 与税务接口，仅税务一项对接周期就以月计 |
| 行业复合人才 | 既懂技术又懂大宗贸易的人稀缺 |
| 信任资产 | 运营时长乘以零重大资金事故，无法速成 |

与三类常见竞争者的定位差异可以一句话概括：传统软件厂商有产品但没有交易数据，纯交易平台有交易但没有深入行业，银行系有资金但没有交易数据。平台的位置，是唯一把交易、物流、金融三个环节的数据放到同一底座上的。

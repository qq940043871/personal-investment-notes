# HR 问答：AI 编码推行与原型辅导

> 用途：HR / 猎头在微信、BOSS 直聘、电话里问「在职期间推行过用 AI 编写代码和测试吗？用的是国内还是国外？」时的逐字回复与追问弹药。
> 依据：`04-技术管理/02A-技术管理补充件.md` 第十项（规范脚手架 + AI Skill 封装）与第二部分 §十一（AI 辅助研发推行：四块应用 / 模型工具清单 / 口径护栏）、`04-技术管理/01-技术整改十一项与落地.html` r10、`midservice Boot 改造实录`、`06-技术随笔/有限资源的管理与优化.md`。
> 口径红线：① 品牌按本人实际清单讲——**模型 deepseek / glm（国内为主），开发工具 Trae / VS Code + 插件**；② 不说「效率提升 XX%」这类无基线百分比；③ 模型用「国内为主 + 数据不出内网」框定，国外模型只在个人脱敏场景做参考、不进生产，不评论工具优劣。

## 一、可直接粘贴的完整回复（微信一屏版，约 320 字）

> 推行过，而且是当成研发流程的一部分来做，不是自己私下用。
>
> ① **编码**：用 AI 补全、生成脚手架和样板代码、做改造类迁移——比如老框架的网关迁到 Spring Boot，让 AI 通读遗留源码定位兼容问题，我负责方案取舍和验收。核心业务逻辑和资金链路的代码必须逐行看过才合。
> ② **测试**：AI 生成用例骨架、边界值和参数组合，**含压力测试脚本与场景骨架**；业务语义的断言手写补，跑通才算数。
> ③ **规范**：把开发规范写进仓库当 AI 的上下文，人和 AI 读同一份规则；重复的活儿封成可复用的技能，提效不依赖某个人。
> ④ **辅导产品经理用 HTML 出原型**：过去是 PM 画图、开发做页、来回三轮，现在给 PM 一套页面模板和规范，他们自己用 AI 生成能双击打开、直接演示的页面。技术这边只保留规范维护和上线前还原度核对——原型阶段的开发投入基本归零，需求争议从「口头描述」变成「对着页面点」。
>
> 模型以**国内为主**，生产用 **deepseek、glm**（私有化部署 / 国内云），开发工具推行过 **Trae** 和 **VS Code + 插件**；代码和数据都在内网、客户现场私有化部署，业务代码出外网是红线。**国外模型只在个人时间、脱敏、不涉及业务数据的前提下**用来做方案对比和读英文资料，不进生产链路。

## 三、四条追问弹药

| 会被问 | 答法 |
|---|---|
| 「你说的迁移是哪次？」 | midservice（交易网关 1018 系统）从 WAR 迁成 Spring Boot 可执行 war，先 1.5 验证再升 2.7；升级前扫了 91 个遗留 jar 的常量池引用做兼容差集，逐项排掉 5 类坑（裁剪版 c3p0 让自动配置直接挂、包名迁移、commons-logging 重复类等）。闭环是：读文档 → 反编译核实 → 方案 → 实施 → 冒烟 → 记录 |
| 「测试怎么用 AI？」 | AI 擅长结构性用例（参数组合、边界、异常分支、**压测脚本与场景骨架**），不擅长业务语义断言（如「冻结金额 = 可用余额 − 已占用」）。分工是 AI 铺骨架、人写断言，跑通才算数，AI 生成的测试按「新提测代码」对待 |
| 「效果怎么衡量？」 | 基准是「产出一页标准管理页」：1–2 小时手写 → 几分钟出稿 + 人工校对；生成物自带规范（色板 / 组件 / 命名 / 导航注册） |
| 「AI 出过问题吗？」 | 出过，典型是「看着对但边界没考虑」。所以定规矩：AI 输出 = 待审代码，注释标明来源与验证方式，必须过人 review + 有测试覆盖才能合 |

## 四、原型辅导追问弹药

| 会被问 | 答法 |
|---|---|
| 「PM 不懂代码怎么落地？」 | 正是不教他们写代码，教的是「用业务语言描述一页有什么」。底层是模板 + 规范 + AI 生成，PM 只需说清字段、操作、状态——这本来就是他该做的事 |
| 「PM 出的原型能当需求文档吗？」 | 不替代 PRD，是让 PRD 有个可点验的载体。规则、异常、权限仍写在文档里，页面只承载「长什么样、怎么走一遍」 |
| 「质量怎么保证？」 | 规定即约束：模板固定骨架、色板统一、导航必须注册；有自动核对环节比对页面与需求清单，缺项直接列出。我做验收，不替他们写 |
| 「1300 页怎么协作？」 | 按子系统分目录、按模板生成，每人只碰自己那几页；跨页一致性靠规范而非开会 |
| 「开发会不会被甩锅？」 | 边界清楚：PM 对业务正确性负责，我对规范与技术可行性负责 |

## 五、两条纪律

1. **说「重新分工」，不说「AI 提效」**——真正省掉的不是打字时间，是「PM → 开发 → PM」那几轮来回。
2. **必须说出自己负责的边界**（规范 + 验收）。只说「我教 PM 用 AI」像随手一教；说「我定规范、我做验收、他们自己出」才是主导设计。

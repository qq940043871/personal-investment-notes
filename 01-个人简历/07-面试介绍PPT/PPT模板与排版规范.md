# 个人成果汇报 PPT · 模板与排版规范

> 配套文件：`deck-kit.mjs`（设计令牌 + 页面原语）、`build-intro.mjs`（页面编排）
> 成品：`面试自我介绍-haswhere.pptx`（15 页）
> 风格配方：**正式工作汇报** —— 严谨 · 秩序 · 克制；金融级的严肃，但保留人物叙事的温度

---

## 一、画布与栅格

| 项 | 值 |
|---|---|
| 画布 | 13.333in × 7.5in（16:9） |
| 左右安全边距 | `M = 0.62in` |
| 内容区宽度 | `CW = 12.093in` |
| 正文区纵向范围 | `1.70 → 6.30`（claim 之后 → 结论带之前） |
| 结论带 | `y = 6.42`，高 0.5–0.55 |
| 页脚 | `y = 7.10` |
| 栅格列 | `gridX(n, gap)` —— 等宽 n 列，默认 gap 0.2 |

**纵向四段固定结构**：页眉（0.26–0.66）→ 标题区（0.84–1.70）→ 正文区（1.70–6.30）→ 结论带 + 页脚（6.42–7.36）。

> 铁律：所有内容必须落在 `0.62 ≤ x ≤ 12.713`、`1.70 ≤ y ≤ 6.30` 内。**任何元素越过 6.30 就会和结论带打架**。

## 二、配色（按角色定义，不按颜色名）

| 角色 | 色值 | 用途 |
|---|---|---|
| `bg` | `FAF7F2` | 页面底色（暖米白） |
| `surface` | `FFFFFF` | 主面板 / 卡片 |
| `surface2` | `F2EDE3` | 次级面板 / 结论带底（暖纸感） |
| `ink` | `1F2430` | 主文本 |
| `muted` | `5B6472` | 次级文本 |
| `faint` | `8A93A0` | 注释 / 页眉右侧 |
| `accent` | `2E6DA4` | 主强调（钢蓝）：线条、项目符号 |
| `accentDark` | `1E4E79` | 深强调：小标题、表头、关键结论 |
| `amber` | `A86A0E` | **数字强调**（琥珀）：KPI 值、时间标签、章节标签 |
| `positive` | `2F8F5B` | 语义：达成 / 结果 |
| `risk` | `B44A3C` | 语义：否决 / 风险 / 付出代价 |
| `caution` | `B4700F` | 语义：待填 / 注意 |
| `hairline` / `grid` | `D9D3C7` / `EAE5DA` | 细线 / 栅格线 |

**配色纪律**：只有 `accent`（钢蓝）+ `amber`（琥珀）两个主色，语义三色（positive / risk / caution）仅用于标注结论正负。**禁止整页出现第三种饱和色**。

## 三、字体与字号阶梯

字体：中文 `Microsoft YaHei`，拉丁/数字 `Arial`。`token()` 会自动为数字/百分比/日期做缩字保护（不换行 + 按框宽收缩），并**按取值内容自动切换字体**——含中文字符时走 `Microsoft YaHei`，纯拉丁走 `Arial`。

| 层级 | 字号 | 字重 | 颜色 | 出现位置 |
|---|---|---|---|---|
| 封面主名 | 60 | Bold | ink | 封面 |
| 封面副标 | 22 | Bold | accentDark | 封面 |
| 页面标题（Action Title） | 23 | Bold | ink | 每页 claim |
| 页面副标（sub） | 11.5 | Regular | muted | claim 下方 |
| 大号成果数字 | 18 | Bold | accentDark | 四本账等 |
| 卡片标题 | 15 | Bold | ink | topCard |
| 卡片标题（次级） | 12.5 | Bold | ink | 流程节点 / 时间线职位 |
| 正文 | 11 – 12 | Regular | ink / muted | 说明段 |
| 项目符号 | 10 – 11.5 | Regular | ink | bullets |
| 小字 / 注释 | 9 – 10.5 | Regular | muted / faint | 卡片角标 |
| KPI 值 | 19 – 28 | Bold | amber | kpi() |
| 页眉 / 页脚 | 11 / 9 | Bold / Regular | amber+accentDark / faint | chrome() |

> 一句页内最多出现 **3 个字号层级**，超过就是排版失控的信号。

## 四、页面骨架（chrome）

每页（除封面、结尾页）统一挂三件套：

1. **页眉**：左 = `第一部分 · 我是谁`（amber）+ 页名（accentDark），右 = 文档名（faint）；下方 0.66 处一条 hairline。
2. **页脚**：左 = 署名 `haswhere · 技术经理`，右 = 页码 `02 / 15`；上方 7.06 处一条 grid 线。
3. **结论带（band）**：`y=6.42`，暖纸底 + 左侧 0.07 宽强调竖条 + 一句结论。**每页必须有一句"所以呢"**，这是全篇最有价值的设计约定。

## 五、常用页型模板

| 页型 | 用在哪 | 结构 | 例子 |
|---|---|---|---|
| **封面 Cover** | 第 1 页 | 大号英文名 + 中文职位 + 分隔线 + 两行标签 + 联系方式；右上角装饰色块梯 | p01 |
| **陈述页 Claim+卡片** | 观点 + 3 列论证 | claim → 3 张 `topCard`（顶边强调 + 标题 + 分段落正文 + 底部结论条） | p05 / p13 |

- 2 列：gap 0.24 → 单列 5.93
- 3 列：gap 0.24 → 单列 3.87
- 4 列：gap 0.20 → 单列 2.87
- 5 列：gap 0.46 → 单列 1.87（**已是下限，再窄中文就折行**）

## 六、排版铁律（踩过的坑）

1. **多段文本必须显式换行**：pptxgenjs 的 `addText` 传 run 数组时**默认不换行**，多段内容要逐段设 `breakLine: true`（见 `topCard` / `bullets`）。

2. **卡片高度 < 1.2in 时**，KPI 的数值与标签框会重叠 → 竖排（上数字 / 下标签）改**横排**（左数字 + 右标签）。

3. **层名字宽固定 1.55in**，`tierRow` 层名超过约 8.4em 会折行，如「业务中台 Java 微服务」→ 砍成「业务中台 Java」。

4. **窄列（< 2.4in）里的 bullet 每条控制在 12 字内**，否则会撑破卡片高度。

5. **数字/日期短令牌一律走 `token()`**，避免 `2 月 → 1 周` 这种串被折断。

6. **含中文的取值必须走中文字体**：Arial 没有 CJK 字形，回退后会触发负字距、字符重叠（实测「9 人天 → 2 小时」「3000 家」被挤成一坨）。`token()` 已改为按内容自动切字体（含中文 → `F.zh`）；新增自定义渲染函数时要照做。`value` 仍建议以数字/百分比/年份为主，中文短句优先放 `label`。

7. **一页一主题**：标题即观点（Action Title）。

## 七、如何复用这套模板

```
改内容    → 编辑 build-intro.mjs 里对应页面块
出成品    → node build-intro.mjs                （生成 .pptx）
出预览    → soffice --headless --convert-to pdf --outdir render 面试自我介绍-haswhere.pptx
          → python render_preview.py            （PDF → 逐页 PNG + 拼图 montage-intro.png）
验收      → 打开 render/pages/*.png 逐页看溢出 / 折行 / 错位
            （该目录为可再生中间产物，不入库：用完即可删，重跑上一行即恢复）
```

**改新汇报场景**时的最小改动：只碰 `build-intro.mjs` 的页面块，`deck-kit.mjs` 是设计系统，一般不动。

**排版自检三问**：
- 有没有元素越过 `y = 6.30`（撞结论带）？
- 每个卡片里最长的一行会不会折成 3 行以上？
- 这一页的"所以呢"写没写进结论带？

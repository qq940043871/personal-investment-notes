## 四、口径纪律（写材料前先看）

1. **对外口径以主线件为准**：AI 段一律以 `00-面试计划/03-项目叙事-AI.md` 为权威；本目录设计与选型文档是它的依据库，不另立标准。
2. **业务口径锚定 B2B 大宗商品现货平台**：所有场景、意图、接口以公司 B2B 现货平台（交易 · 支付结算 · 合同履约 · 仓单 · 物流 · 税务 · 供应链金融）为准，权威来源 `00-面试计划/02-项目叙事-B2B.md`。
   - 与平台架构的咬合点见 `03-业务设计/AI智能体企业级应用平台-定位与项目价值.md` §8.1 三条硬约束（平台规则≠法规 / 撮合状态带时点 / 写操作转工单），改任何一篇都要同步其余两篇。
3. **方案与事实分开**：`03-业务设计/` 的方案若未落地，标注「设计 / 目标口径」，不填数字、不编来源。
4. **个人线与公司平台不混**：Harness / 自研 RAG（外置 `../../personal-ai-engineering/`）同属个人技术储备（Python + FastAPI + Ollama），**不是公司平台技术栈**；公司侧为 Java 微服务中台 + C 内存撮合，政策 Agent 承载在 Dify。
5. **路径口径**：本目录内引用写相对路径（`./…`），对外引用一律带 `02-AI智能体/` 前缀。
6. **外置目录不重复入库**：`ai-rag-self-engineering/`、`ai-agent-harness/` 只存在于 `personal-ai-engineering/`，本库改路径时**只改指针**，不得把正文复制回来。

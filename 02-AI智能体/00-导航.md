# 02-AI智能体 · 总导航

> **本目录是 AI 域的唯一定居点。** 2026-10-30 起，原根级 `ai/`（认知 / 平台 / 业务 / 面试四层方案集）与 `02-AI智能体/`（项目底稿 `ai-project/` + `大模型企业落地/`）**合并为一套 01–06 编号体系**，不再有两套并列的 AI 目录。
>
> **路径口径**：全库引用统一写仓库根相对路径，如 `02-AI智能体/03-业务设计/政策解读Agent-通用设计.md`；`ai/` 前缀已全部作废。

## 一、六目录分层（谁回答什么问题）

| 目录 | 层 | 回答的问题 | 一句话判据 |
|---|---|---|---|
| `01-认知框架/` | 认知层 | LLM / Agent / Harness **是什么、边界在哪** | 不绑定任何平台，换 Dify 或自研都成立 |
| `02-平台工程/` | 平台层 | 工具链**怎么用、坑在哪** | 绑定具体平台/组件（Dify 1.17.x、MinerU） |
| `03-业务设计/` | 设计层 | 具体业务 Agent **怎么设计** | 绑定业务场景（政策、电力、客服、直击库） |
| `04-面试/` | 表达层 | 上面几层**面试怎么讲** | 成品问答 + 外部题库 + 原料语料 |
| `05-项目底稿/` | 事实层 | 公司 AI 平台**整体方案与我的参与边界** | 9 页富 HTML，讲述时必须带限定语 |
| `06-大模型企业落地/` | 事实层 | 前期建设**我本人做了哪几件事** | 只记录真实参与（选型 / 解析链路 / 敏感度分层） |

> 编号即阅读顺序：**先认知 → 再平台 → 再设计 → 再看项目事实 → 最后转成面试话术**。

## 二、依赖方向（发现反向引用即放错了层）

```
                    ┌──────────── 04-面试（消费全部，只引用不复述）
                    │
01-认知框架 ──► 02-平台工程 ──► 03-业务设计
                    │                 │
                    └────► 05-项目底稿（事实：平台整体方案 / 团队成果）
                    └────► 06-大模型企业落地（事实：本人前期参与与判断）
```

- `01` 不依赖任何下层；`02` 只在 `01` 的概念上用平台能力；`03` 引用 `02` 的组件事实。
- `05` / `06` 是**事实层**：只陈述「平台长什么样」与「我做了哪几件事」，不写新方案；方案在 `01`–`03`。
- `04` 只能引用上层，**不得另立口径**。

## 五、口径纪律（写材料前先看）

1. **二手材料只作参照**：`04-面试/wushixiong-agent/`、`04-面试/语料/` 是外部抓取件，只用来看「别人怎么问」；自家 AI 段口径一律以 `00-面试计划/03-项目叙事-AI.md` 为权威。
2. **Harness 是个人技术储备，不是公司平台技术栈**：公司侧 B2B 平台后端 = Java 微服务中台 + C 语言内存撮合引擎；政策解读 Agent 承载在 Dify 上。任何材料把 FastAPI / Python 说成平台后端栈，都算过度声明。
3. **业务口径锚定 B2B 大宗商品现货平台**：`03-业务设计/` 下所有场景、意图、接口一律以公司 B2B 现货平台（交易 · 支付结算 · 合同履约 · 仓单 · 物流 · 税务 · 供应链金融）为准，权威来源 `02-现货贸易/b2b-project/overview.md`。
   - **不要**再出现 ToC 公用事业 / 通用电商口吻（户号、电费、账单、保修期、积分会员）。
   - 与平台架构的咬合点见 `03-业务设计/AI智能体企业级应用平台-定位与项目价值.md` §8.1 三条硬约束（平台规则≠法规 / 撮合状态带时点 / 写操作转工单），改任何一篇都要同步其余两篇。
4. **事实层不外扩**：`05` / `06` 只写真实参与；`01`–`03` 的方案若未落地，标注「设计 / 目标口径」，不填数字、不编来源。
5. **路径口径**：本目录内引用一律写仓库根相对路径（`02-AI智能体/...`），不再出现 `ai/`；同层目录之间用 `./` 亦可，但对外引用必须带 `02-AI智能体/` 前缀。

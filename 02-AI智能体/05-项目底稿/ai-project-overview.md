## 一、个人参与边界（重要，先读这一节）

本项目的页面描述的是**平台整体方案与团队成果**，不代表任何个人的参与范围。

- **个人真实参与** = ①前期底座选型（Dify vs 自研，六路对比与边界划分）② MinerU 复杂 PDF 解析改造（PDF → Markdown）③ 多格式文档落向量库的格式与元数据衔接 ④ 解析调度与失败兜底。
- **由团队推进** = 智能体编排与工作流调优、上下文与执行循环、模型微调训练、业务中台的日常业务开发。
- **不得混入** = 个人自研的 Agent Harness（Python + FastAPI + MainLoop）属**个人储备**，与本平台无关，不能写进本平台的能力清单。

**数值口径**：原型期尚未采集实测数据，所有效率/成本类指标一律标注 `待实测` 或 `目标口径`，**不填数字、不编来源**。

## 三、平台的三条硬约束（写进架构规范）

1. 权限校验**永远在中台侧**执行，不把数据过滤责任交给 Prompt。
2. Dify **不直连业务数据库**，只通过中台工具网关访问。
3. 工作流内**不写复杂业务逻辑**，只做路由、拼装、调用与格式化。

## 四、能力边界（不解决什么）

不替代业务决策 · 不做算法创新 · 不解决数据本身脏 · 不直连业务库 · 不承诺「零幻觉」· 不承担合规责任主体。

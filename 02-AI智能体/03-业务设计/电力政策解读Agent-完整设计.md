## 0. 这份文档的重点

通用政策解读的骨架已经定了。本文只解决两件事：

1. **落到电力垂直场景** —— 电力政策的文件体系、主管机关、专有术语、时效模型都跟通用政策不一样，照搬会翻车。
2. **把主链路铺细** —— 这条链路是本系统的主动脉：

```
客户输入 → ① 输入规范化 → ② 意图识别 → ③ 槽位抽取
        → ④ 匹配知识库问答集（直击）
             ├─ 命中 → ⑤ 命中校验 → 直接返回（不过大模型）
             └─ 未命中 → ⑥ 走 RAG 全链路 → 生成 → 核验 → 返回
```

第 ④ 步「直击」是本方案省 token、保一致性的核心；而第 ⑤ 步「**命中校验**」是绝大多数同类方案会漏掉、且一旦漏掉就会出事故的一环（见 §6.4）。

## 1. 电力政策解读的六个独有难点

不搞清楚这些，做出来的就是"能搜到文件"的玩具，而不是能用的解读助手。

| # | 难点 | 通用政策没有的麻烦 | 翻车后果 |
|---|---|---|---|
| 1 | **文件体系里有一层"非政府但有约束力"** | 《供电营业规则》《电力交易规则》《两个细则》由电网企业/交易中心/派出机构发布，**不是政府规范性文件**，却对市场主体有事实约束 | 把企业规则当政府政策引用 → 效力定性错误 |
| 2 | **主管机关多头且分层** | 发改委（价格）、能源局（规划/监管）、能源局**区域派出机构**（华北/华东/华中/东北/西北/南方能源监管局）、省发改委、省能源局、部分省在工信厅 | 找错主管 → 建议用户去错部门 |
| 3 | **术语口语化极严重** | "度电""过网费""隔墙售电""两个细则""代购电价"—— 全是行业黑话，且**不写进正式文件** | 按口语原文检索 → 关键词通道全空 |
| 4 | **电价与时效强绑定** | 电价文件多为"自 X 年 X 月 X 日起执行"，一年一调，且带执行周期 | 用过期电价 → **直接算错钱** |
| 5 | **地域差异极大** | 同是"分布式光伏并网"，各省接入容量上限、备案流程、补贴规则完全不同 | 拿外省政策答本省问题 |
| 6 | **角色决定适用条款** | 同一件事，发电企业、电网企业、售电公司、用户看到的条款完全不同 | 答非所问（甚至答了不该适用的条款） |

> 第 6 条是最隐蔽的。用户问"电价怎么算"，如果不知道他是**发电侧**还是**用户侧**，答案可能完全相反。所以**角色是必抽槽位，不是可选**。

## 2. 总体链路

```
                            客户输入
                               │
              ┌────────────────▼────────────────┐
              │ [0] 接入 · 会话 · trace_id       │
              └────────────────┬────────────────┘
              ┌────────────────▼────────────────┐
              │ [1] 鉴权 · 权限画像加载           │  每轮重载，不缓存
              └────────────────┬────────────────┘
              ┌────────────────▼────────────────┐
              │ [2] 输入规范化                    │  口语→术语 / 文号识别 / 纠错
              └────────────────┬────────────────┘
   ╔══════════▼══════════╗
   ║ [3] 意图识别（三层）  ║  规则 → 轻量模型 → 保守兜底
   ╚══════════╤══════════╝
   ╔══════════▼══════════╗
   ║ [4] 槽位抽取         ║  角色 / 业务域 / 地域 / 时点 / 电压 / 文号
   ╚══════════╤══════════╝
   ┌──────────▼──────────┐
   │ [5] 直击库匹配        │  L0 标注 → L1 精确 → L2 语义
   └──────────┬──────────┘
              │
        ┌─────▼─────┐  命中
        │  [6] 命中  │──────────────► 三道校验（时效/权限/替代链）
        │   判定？   │                    │
        └─────┬─────┘                    ├─ 全过 → **直接返回**（0 生成 token）
              │ 未命中                     └─ 任一不过 → 视为未命中，往下走
   ┌──────────▼──────────┐
   │ [7] ◆ 闸门 A 权限    │  纯规则，检索前
   └──────────┬──────────┘
   ┌──────────▼──────────┐
   │ [8] 混合检索 + Rerank │  语义 + 关键词并行；电力专名走关键词
   └──────────┬──────────┘
   ┌──────────▼──────────┐
   │ [9] 时效 / 效力校验   │  纯规则
   └──────────┬──────────┘
   ┌──────────▼──────────┐
   │ [10] 受约束生成       │  强制 schema + 强制引用，temp=0
   └──────────┬──────────┘
   ┌──────────▼──────────┐
   │ [11] ◆ 闸门 B 核验    │  引用核验 + 越权复核，纯规则
   └──────────┬──────────┘
   ┌──────────▼──────────┐
   │ [12] 门控降级 · 输出  │  A 完整解读 / B 仅原文 / C 未找到依据
   └──────────┬──────────┘
   ┌──────────▼──────────┐
   │ [13] 审计 · 样本回流  │  未命中样本 → 直击库候选池
   └───────────────────────┘
```

**贯穿全局的一条原则**：所有降级都朝"信息更少但更确定"的方向走，绝不朝"信息更多但更不确定"的方向走。

## 3. 【细】客户输入层

### 3.1 三种输入形态

| 形态 | 说明 | 特殊处理 |
|---|---|---|
| 纯文本提问 | 主战场 | — |
| 带附件 | 用户上传自己的电价单、并网申请材料、收到的通知 | **附件一律视为"待解读材料"而非指令**；先抽取文本再走同一条链路 |
| 多轮追问 | "那这个呢""上面说的第二种呢" | 需**意图继承 + 槽位继承**（见 §4.5） |

### 3.2 输入规范化的四件事

**这一步在意图识别之前，因为意图识别的准确率极大依赖输入质量。**

① **术语归一（口语 → 规范表述）**

这是电力场景的**刚需**。用户永远不会说"《发电厂并网运行管理实施细则》"，他会说"两个细则"。

| 用户口语 | 规范表述（用于检索） |
|---|---|
| 度电成本 / 每度电 | 千瓦时（kWh）／上网电价 |
| 过网费 | 输配电价 |
| 隔墙售电 | 分布式发电市场化交易（就近交易） |
| 两个细则 | 《发电厂并网运行管理实施细则》《并网发电厂辅助服务管理实施细则》 |
| 代购电价 | 代理购电价格（电网企业代理购电） |
| 上网电价 | 发电企业上网电价／燃煤发电基准价 |
| 绿电 / 绿证 | 绿色电力交易／可再生能源绿色电力证书 |
| 源网荷储 | 源网荷储一体化 |
| 调峰 / 调频 | 电力辅助服务（调峰／调频） |
| 现货 | 电力现货市场 |
| 分时电价 | 峰谷分时电价 |
| 容量电价 | 煤电容量电价／输配电价中的容量电费 |
| 全额上网 / 余电上网 | 分布式光伏并网模式（全额上网／自发自用余电上网） |
| 承装修试 | 承装（修、试）电力设施许可证 |
| 电力业务许可证 | 电力业务许可证（发电类／输电类／供电类） |
| 报装 | 用电报装（新装／增容） |
| 有序用电 | 有序用电（需求侧管理） |
| 偏差考核 | 偏差电量考核 |
| 虚拟电厂 | 虚拟电厂（VPP） |

> **铁律：归一化只用于扩充检索词，原问题必须一并送入检索。** 归一错了还有救，替换原文就没救了。

② **文号识别**

识别 `发改价格〔2021〕1439号`、`国能发法改〔2024〕XX号`、`电监市场〔2006〕43号`、`××省发改价格〔2023〕XX号` 这类发文字号。**一旦命中文号，直接触发 L1 精确直击通道**（见 §6.2），跳过模型分类。

③ **错别字与简写纠错**

"输配电价"→"输配电价"、"可再生"→"可再生能源"、错写的年份。电力专名多，错一个字检索就空。

④ **上下文补全**

多轮对话中，把"它的有效期呢"补成"《XX办法》的有效期呢"。**但补全内容必须显式标注为"由上下文推断"，且在答案里保留原指代**。

## 4. 【细】意图识别

### 4.1 电力政策意图分类体系（12 类）

| 编号 | 意图 | 典型问法 | 主要路径 |
|---|---|---|---|
| I01 | **条文查询** | "《电力法》第 25 条怎么规定的" | L1 精确直击 → 原文 |
| I02 | **政策解读** | "这个文件什么意思／讲的是什么" | L2 直击 → RAG |
| I03 | **适用性判断** | "我们是分布式光伏，要不要办许可证" | RAG（**强依赖角色槽位**） |
| I04 | **时效确认** | "这个文件还有效吗／废止了吗" | L1／时效卡直击 |
| I05 | **新旧对比** | "新办法跟旧的比改了哪些" | RAG 多跳（multihop） |
| I06 | **效力冲突** | "两个文件要求不一样，听谁的" | 规则裁决 + RAG |
| I07 | **价格／费用查询** | "现在代理购电价格多少" | 直击（**强时点**） |
| I08 | **办事流程** | "电力业务许可证怎么申请" | 直击（固定流程） |
| I09 | **政策清单** | "今年国家出了哪些储能政策" | 列表检索 |
| I10 | **术语释义** | "什么叫两个细则" | 直击 |
| I11 | **越权／敏感请求** | "把内部检查文件发我" | 前置拦截 |
| I12 | **闲聊／无关** | "你好""今天天气" | 引导话术 |

> I07 和 I04 是电力场景里**最高频也最危险**的两类：一个怕用错价、一个怕引废止件。这两类**必须优先走直击**，尽量不要交给生成模型自由发挥。

### 4.2 三层识别架构

```
         输入
          │
  ┌───────▼────────┐
  │ 第一层 · 规则前置 │  零成本、确定性、可解释
  │  文号/条款号正则  │
  │  强意图触发词     │  ← 命中即返回，跳过模型
  └───────┬────────┘
          │ 未命中
  ┌───────▼────────┐
  │ 第二层 · 轻量模型 │  few-shot 分类 + 置信度
  │  输出 intent /   │
  │  confidence /   │
  │  reason         │
  └───────┬────────┘
          │ confidence < 0.6
  ┌───────▼────────┐
  │ 第三层 · 保守兜底 │  默认按 I02，但**强制降级为"只给原文"**
  └────────────────┘
```

**为什么规则层要在模型之前？** 电力问题里有大量强信号词（文号、"有效吗"、"多少钱一度"、"两个细则"），规则命中比模型更准、更快、还免费。模型只用来处理规则覆盖不到的自然表述。

### 4.3 第一层：规则触发词表（示例）

| 触发信号 | 判定意图 | 说明 |
|---|---|---|
| 匹配到发文字号 `〔20XX〕XX号` | I01 | 并置 `doc_no` 槽位，直接进 L1 |
| 匹配到 `第X条` / `第X款` | I01 | 需配合文号或上文语境 |
| 含"还有效吗／废止／失效／过期／施行了吗" | I04 | — |
| 含"电价／价格／多少钱／收费标准" + 时点词 | I07 | 时点缺失 → 追问 |
| 含"怎么办／如何申请／需要什么材料／流程" | I08 | — |
| 含"区别／变化／改了／新旧对比" | I05 | — |
| 含"不一致／冲突／听谁／以哪个为准" | I06 | — |
| 含"什么意思／怎么理解／解读一下" | I02 | — |
| 含"内部／未公开／征求意见稿／涉密／机要" | I11 | 前置拦截 |
| 含"我们公司／我厂／我们是" + 业务名词 | I03 | 触发角色槽位追问 |

> ⚠️ 规则表要**可运营**：用配置文件维护，不要写死在提示词里。政策话术会变（比如新出个"新型电力系统"），运营要能自己加词。

### 4.4 第二层：轻量模型分类

- 用**小模型**（分类任务不需要大模型），few-shot 给每类 2–3 个电力实例
- **只输出枚举标签 + 置信度 + 一句理由**，不要让它自由发挥
- 枚举标签必须收敛到 §4.1 的 12 类，**不允许"其他"泛滥**（"其他"占比超 15% 说明分类体系有缺口）

### 4.5 多轮意图继承

| 场景 | 处理 |
|---|---|
| 追问同一话题 | 继承上轮 `intent` + `slots`，只更新变化的部分 |
| 话题跳转 | 检测到新意图 → **丢弃旧槽位**，避免"上一轮是光伏、这一轮问火电"却带着光伏角色 |
| 指代消解 | "它""这个""第二个"→ 回指上轮实体；**无法确定回指对象时，追问而不是猜** |

> 话题跳转的槽位清理是个高频 bug 源：用户先问光伏补贴、再问火电容量电价，如果槽位没清，系统会拿"光伏"去过滤火电政策。

### 4.6 意图识别易错点（电力专属）

| 易错点 | 说明 |
|---|---|
| "许可证"歧义 | **电力业务许可证**（发电/输电/供电类，能源局发）vs **承装（修、试）电力设施许可证**（施工类，派出机构发）—— 名字都叫许可证，主管、条件、层级完全不同 |
| "分布式光伏"说法多 | 屋顶电站、自发自用、户用光伏、工商业屋顶 —— 都是分布式光伏 |
| "并网"归属 | "我要办并网"可能是 I08（流程）也可能是 I03（适用性），靠角色槽位消歧 |
| 把方案当规定 | 用户拿《XX实施方案》问"法律效力"→ 正确答案是**它不构成行政管理依据**（见 §9） |
| 价格问题的伪确定性 | "现在电价多少"看似简单，实则**必须绑定地域 + 时点 + 用户类别**，三者缺一不可答 |

## 5. 【细】槽位抽取

### 5.1 槽位表

| 槽位 | 取值 | 缺失时 | 对链路的影响 |
|---|---|---|---|
| `role` | 发电企业／电网企业／售电公司／电力用户／储能／新能源 | 从权限画像取；取不到则追问 | **决定适用条款**（关键） |
| `biz_domain` | 电价／并网接入／市场交易／许可证资质／补贴／消纳／安全／辅助服务 | 从问题推断 | 决定检索范围 |
| `jurisdiction` | 国家／省／市 | 默认用户画像地域 | 强过滤条件 |
| `on_date` | 日期 | 默认今天 | 时效判定、电价版本 |
| `voltage` | 电压等级 | 可空 | 并网/接入类问题必需 |
| `doc_no` | 发文字号 | 可空 | 命中即走 L1 |
| `capacity` | 装机容量 | 可空 | 补贴/备案阈值类问题必需 |

### 5.2 角色识别（本系统的关键设计）

**同一个问题，角色不同，正确答案不同。** 举例：

> 问："上网电价是多少？"
> - 发电企业 → 问的是**上网电价**（燃煤基准价 / 市场化电价）
> - 电力用户 → 这个词对他没意义，他实际想问**到户电价 / 代理购电价格**
> - 售电公司 → 关注**批零价差 / 代理购电价格**

所以：**角色槽位必须优先解析，且在答案中显式声明"我按 XX 角色作答"。** 角色来源排序：
1. 用户显式声明（"我们是售电公司"）
2. 权限画像中的企业类型
3. 历史会话（低置信，需确认）

### 5.3 时点与地域

- **时点**：默认今天；"去年""2023年""新标准实施后"都要换算成日期。**时点不可解析时不得推定**，要在答案里显式声明所依据的时点。
- **地域**：用户未指定 → 用画像地域；显式指定 → 校验是否越权（见闸门 A）。

## 6. 【细】直击库匹配（"匹配到就直接返回"）

这是本方案的核心机制。**命中就不过大模型**，直接返回标准答案。

### 6.1 三级直击

| 级 | 命中方式 | 成本 | 适用 | 是否过 LLM |
|---|---|---|---|---|
| **L0** | Dify Annotation 标注回复 | 0 token | 高频 Top 20 问法、话术必须逐字统一 | 否 |
| **L1** | 精确命中（文号／条款号／标题） | 0 token | "《电力法》第25条""发改价格〔2021〕1439号" | 否 |
| **L2** | Q&A 语义匹配（embedding） | 仅 embedding | "什么是两个细则"这类换了说法的问法 | 否 |

> L0 能力最强但**绑在单个应用上**，跨应用不可复用、无版本管理，只适合做高频兜底。**L1/L2 的 Q&A 库才是能共享、能 API 批量管、能随 DSL 进 Git 的知识资产。** 推荐 L0 + L1/L2 双层。

### 6.2 L1 精确命中的三种键

| 键 | 命中条件 | 返回 |
|---|---|---|
| 文号键 | 文号规范化后完全相等（全角/半角、括号形式统一后） | 该文件全文摘要 + 状态 + 官方链接 |
| 条款键 | 文号 + 条款号同时命中 | **该条款原文逐字** + 上下文条款 |
| 标题键 | 文件标题规范化后相等 | 文件卡片（标题/文号/状态/效力/链接） |

**规范化规则**（否则精确匹配会大量漏）：`〔〕` 与 `[]` 与 `()`, 全角数字与半角数字，`号` 的有无，空格与全角空格 —— 统一后再比。

### 6.3 L2 语义命中的参数

| 参数 | 起手值 | 说明 |
|---|---|---|
| 检索模式 | Q&A 模式（问题—答案对） | 不是通用分段模式 |
| `top_k` | **1** | 直击只要最优一条，多了反而乱 |
| `score_threshold` | **0.85** | 宁高勿低（理由见 §6.6） |
| Rerank | **必须开启** | ⚠️ TopK 与 Score 阈值**只在 Rerank 阶段生效**，不开则阈值是摆设 |
| 元数据过滤 | 按 `role_scope` / `jurisdiction` 过滤 | ⚠️ Dify 元数据是**文档级不是分段级**，且**单节点挂多知识库时元数据过滤不可用** → 按密级/地域拆库 |

### 6.4 ★ 命中校验：三道关（最容易被漏掉的一环）

**命中 ≠ 可以直接返回。** 这是电力场景必须补的一步 —— 因为电价的时效性太强，返回一个过期答案的代价比"没答上"大得多。

```
直击命中
  │
  ├─ 关一 · 时效校验
  │    命中条目关联的源文件，在 on_date 时点是否仍有效？
  │    ├─ 已废止 / 已过期 / 已被替代 → **判定失败**
  │    └─ 电价类条目：还须核对执行周期是否覆盖 on_date
  │
  ├─ 关二 · 权限校验
  │    该条目的 confidentiality / role_scope 是否允许当前用户看？
  │    └─ 不允许 → 判定失败（且不得暴露"这条存在但你没权限"）
  │
  └─ 关三 · 替代链校验
       源文件是否已被新文件替代（supersedes 链）？
       └─ 已替代但 Q&A 未更新 → **判定失败**，并告警"该 FAQ 待更新"
  │
  ▼
三道全过 → 直接返回    ／    任一不过 → 视为未命中，静默走 RAG
```

> 🔴 **为什么"静默"？** 不要告诉用户"我有一条但过期了，所以走检索" —— 那等于泄露了内部知识库的组织信息。
>
> 🔴 **为什么必须有时效校验？** FAQ 是**人工写的、静态的**，而电价是**会变的**。一条"代理购电价格是 X"的 FAQ，过一年就是错误答案。**不绑时点的 FAQ 就是定时炸弹。**

### 6.5 电力 FAQ 库字段设计

| 字段 | 说明 |
|---|---|
| `faq_id` | 主键 |
| `question` | 标准问法 |
| `answer` | 标准答案（**必须逐字确定**，电价/期限这类数字不能有多种说法） |
| `intent` | 归属意图（§4.1 编号） |
| `role_scope` | 适用角色（空 = 全部） |
| `jurisdiction_scope` | 适用地域（空 = 全国） |
| `source_doc_no` | 依据文件文号（**必填，否则不可溯源**） |
| `source_clause` | 依据条款号 |
| `effective_from` / `effective_to` | 该答案的有效期（**电价类必填**） |
| `status` | draft / active / retired |
| `confidentiality` | 密级 |
| `hits` | 命中计数（用于晋升/淘汰） |
| `review_on` | 下次复核日期（**电价类建议 ≤6 个月**） |

> 对照通用直击库（`rag-cases/registry.csv`），电力版**新增了 `effective_from/to`、`jurisdiction_scope`、`role_scope`、`source_clause`** —— 这四项全是电力场景逼出来的。

### 6.6 阈值标定与"错命中代价"

- L1 精确命中：**无阈值**，但必须过 §6.4 的校验
- L2 语义命中：阈值 **0.85** 起手；0.85–0.92 区间打"待抽检"标记
- **错命中的代价 ≫ 漏命中**：错命中 = 甩给用户一个看似权威但答非所问的成品答案（用户会信）；漏命中 = 多花几毛钱走 RAG。所以**阈值宁高勿低**。

### 6.7 直击库的维护闭环

```
线上未命中的问题 ──┐
人工标注的好答案 ──┼──► 候选池 ──► 审核 ──► active ──► 定期复核 ──► 淘汰
审计日志的高频问法 ─┘                    （hits 达阈值）（review_on 到期）
```

**关键指标**：命中率目标 **15%–35%**。低于 10% 说明收集的根本不是真高频问题，别硬撑；高于 40% 要警惕是不是把该走 RAG 的复杂问题也硬塞进了直击库（那会牺牲准确性）。

## 7. 【细】未命中 → RAG 全链路

复用 `policy-agent` 的六层架构与两道闸门，此处只列**电力场景的差异化配置**。

### 7.1 闸门 A · 权限前置（检索前）

- **角色分区**：不同角色可见的政策不同（如电网企业内部的运行规则，用户侧不可见）
- **地域强过滤**：用户只能看本辖区 + 上级文件
- 过滤后候选为 0 → 直接走"未找到依据"，**严禁放宽条件重试**

### 7.2 混合检索（电力版配置）

| 通道 | 电力配置要点 |
|---|---|
| 语义通道（向量） | 常规；对专有名词效果差 |
| 关键词通道（BM25/倒排） | **必须覆盖**：文号、专有名词（"两个细则""辅助服务""容量电价"）、条款号 |
| 同义词扩展 | 用 §3.2 的术语表做**查询扩展**（把"过网费"扩成"过网费 OR 输配电价"） |
| 候选池 | `top_k = 15`（后有两道筛，先放宽） |

> **电力场景的关键词通道权重应该比通用场景更高**。因为用户问政策时，往往直接甩专有名词和文号 —— 这些是精确串，语义检索经常打偏。

### 7.3 Rerank 与生效参数

- Rerank 必开，生效 `top_k = 5`，`score_threshold` 起手 0.5（按验证集标定）
- Rerank 不可用 → **降级为仅关键词排序 + 强制"仅原文"模式**（排序不可靠时生成的幻觉率会陡升）

### 7.4 时效与效力校验（纯规则）

- 剔除"未施行／已废止／已过期"文件
- 按位阶排序，标注每条候选的效力等级
- 同事项多文件冲突 → 套用法律适用规则裁决（见 §9）

## 8. 生成与两道闸门（要点）

生成环节的电力补充：

- **强制 schema**：`conclusion / basis[] / conditions / uncertainty / disclaimer`
- **强制引用**：每条结论挂 `basis`，`quote` 必须与检索到的条款**逐字一致**
- **禁止行动指导**：不得输出"建议您去办…""可以直接并网"这类话 —— 那是主管部门职责
- `uncertainty` **必填**（可写"原文未涉及"）—— 强制模型对每个回答评估一次不确定性

**闸门 B（输出前）** 三查：引用真实性（文号存在性 + 条款存在性 + quote 逐字比对 ≥0.95 + 权限一致性）、越权复核（片段/存在性/标识泄露）。

> 三种引用幻觉里，**"真条款号 + 被改写的摘录"最隐蔽也最危险** —— 条款号是真的，内容被改成了想要的形状。所以必须做逐字比对，光查条款号存不存在不够。

## 9. 电力政策文件体系与效力（电力专属）

### 9.1 位阶与示例

| 位阶 | 类型 | 电力例子（示例，非穷举） |
|---|---|---|
| 2 | 法律 | 《中华人民共和国电力法》《可再生能源法》 |
| 3 | 行政法规 | 《电力供应与使用条例》《电网调度管理条例》《电力监管条例》 |
| 5 | 部门规章 | 《电力业务许可证管理规定》《承装（修、试）电力设施许可证管理办法》（能源局令） |
| 7 | 部门规范性文件 | 《关于进一步深化燃煤发电上网电价市场化改革的通知》（发改价格〔2021〕1439号）、《电力中长期交易基本规则》 |
| 7 | 地方规范性文件 | 各省电价文件、各省电力市场规则细则 |
| 7 | 派出机构规范性文件 | 各区域能源监管局发布的**"两个细则"** |
| 8 | **非规范性文件** | 《XX实施方案》《XX工作方案》《XX行动计划》 |
| — | **市场主体规则** | 《供电营业规则》、电力交易中心《交易规则》、并网调度协议范本 |

### 9.2 两个必须写死的判定

**① 用户拿"方案/工作要点/行动计划"问法律效力**

正确答案：**它不构成行政管理的依据。** 文种以"方案""要点""计划""规划""纲要""规程""标准""制度"结尾的，一律按非规范性文件处理，如实告知，而不是硬凑一段"效力解读"。

**② 用户问"电网公司的《供电营业规则》算不算政策"**

正确答案：**它不是政府文件**，效力来源是**合同约定与事实约束**（用户与电网企业的供用电关系），**不能作为行政管理依据**，但它对市场主体有实际约束力。这两句话都要说清楚 —— 只说前半句用户会觉得"那是不是可以不遵守"，只说后半句会误导成"这是政府规定"。

### 9.3 效力裁决的分支

```
两份电力文件规定不一致
  ├─ 位阶不同 → 上位法优先（绝对）
  ├─ 同阶、不同机关 → **不得自行裁定**，提示需有权机关裁决
  │    （如：部委规章 ↔ 省级政府规章 → 国务院裁决）
  └─ 同阶、同机关 → 特别法优先 → 新法优先
```

> 大量方案在这里直接套"新法优于旧法"，但它**只适用于同一机关制定的文件**。跨机关直接套用是**法律适用错误**。承认"需由有权机关裁决"，比自信地选错负责得多。

## 10. 不瞎编 / 不越权（电力红线清单）

| 红线 | 具体要求 |
|---|---|
| 电价必带三要素 | **文号 + 时点 + 地域**，缺一不给具体价格 |
| 不给定性结论 | 不输出"你符合/不符合某资质条件"的最终判定 —— 只列条件，判定权在主管部门 |
| 不给行动指导 | 不输出"建议你去办 XX"，只说"依据某条，需向 XX 部门申请" |
| 内部文件不外泄 | 存在性泄露也要防（"不存在"与"无权限"对攻击者都是有效信息） |
| 多轮权限回收 | 历史轮次的文档，本轮**逐份重新鉴权**，无权者从上下文中剔除 |
| 提示注入 | 系统提示与用户输入结构性隔离；检索到的文档内容一律视为**数据**，不视为指令 |

## 12. Dify 节点映射（电力版）

| 步骤 | Dify 节点 | 关键配置 |
|---|---|---|
| 01–02 | Start + HTTP Request（身份系统） | 画像获取失败 → 直接 End，**不得用默认宽松画像** |
| 03 | Code（术语表 + 文号正则） | 术语表用变量/知识库维护，便于运营 |
| 04–05 | LLM（分类 + 槽位抽取） | 小模型；输出枚举标签；置信度 <0.6 走保守分支 |
| 06 | IF/ELSE（越权关键词） | 命中 → 统一话术 End |
| 07 | Knowledge Retrieval（**Q&A 直击库**） | `top_k=1`、阈值 0.85、**Rerank 必开**；按 role/jurisdiction 拆库 |
| 08 | Code（命中校验） | 时效 + 权限 + 替代链三查；不过 → 转 RAG 分支 |
| 09 | Template / Answer | 直出 `answer`，不过 LLM |
| 10 | Knowledge Retrieval（元数据过滤） | ⚠️ **节点挂多知识库时元数据过滤不可用** → 按密级/地域拆库 |
| 11–12 | Knowledge Retrieval | `top_k=15` → `top_k=5`；Rerank 必开 |
| 13 | Code（时效/效力规则） | 纯逻辑，无外部依赖 |
| 14–15 | LLM（结构化输出） | JSON schema；temp=0；引用格式写死 |
| 16–17 | Code（核验 + 复核） | 不过 → IF/ELSE 重试 → 再失败降级 |
| 18 | IF/ELSE + Template + HTTP | 三档分流；审计落库；未命中样本回流 |

**两个必须记住的 Dify 特性坑**（呼应 `02-AI智能体/02-平台工程/Dify-RAG关键点详解.md`）：

1. **元数据过滤在"单节点挂多个知识库"时不可用** → 电力场景角色/地域维度多，必须**按地域或密级拆库**
2. **TopK 与 Score 阈值只在 Rerank 阶段生效** → 直击库不启 Rerank，0.85 的阈值就是摆设，会得到一个人人命中、准确率崩坏的直击库

## 13. 验收指标与测试用例

### 13.1 五个硬指标

| 指标 | 目标 | 不达标说明 |
|---|---|---|
| 引用真实率 | **100%** | 红线，没有"接近 100%"这回事 |
| 越权拦截率 | **100%** | 红线 |
| 直击命中准确率 | **≥ 99%** | 错命中危害大，宁可漏不可错 |
| 时效正确率 | ≥ 99.5% | 元数据质量不行（施行日/失效日缺失） |
| 该拒就拒率 | ≥ 95% | 门控阈值太松，模型在硬答 |

### 13.2 必测用例（电力场景）

| 类别 | 用例 |
|---|---|
| 时效边界 | 电价文件执行周期首日/末日；"暂行"3 年到期；公布日与施行日之间（第三种状态） |
| 直击校验 | 命中一条**已过期**的 FAQ → 必须驳回并走 RAG |
| 角色歧义 | 同一问题分别以"发电企业/用户"身份提问 → 答案必须有差异且各自正确 |
| 地域差异 | 同一问题指定两个省 → 答案落到各自属地文件 |
| 术语归一 | "过网费是多少"→ 必须能检索到"输配电价"相关文件 |
| 效力冲突 | 部委规章 ↔ 省规章不一致 → 必须标"需裁决"，不得自行选一个 |
| 非规范性文件 | 拿《XX实施方案》问效力 → 必须答"不构成行政管理依据" |
| 引用幻觉 | 编造条款号 / 真条款号 + 改写摘录 → 都必须被闸门 B 拦下 |

## 14. 分期落地建议

| 期 | 范围 | 交付标准 |
|---|---|---|
| **一期 · 直击 + 只读** | 步骤 01–09 + 仅原文输出 | 把"哪份文件、哪一条、什么状态"和"高频问答集"做准。**先别上生成** |
| **二期 · 受约束解读** | 加 10–18 | 闸门 A/B 上线，RAG 全链路打通 |
| **三期 · 扩展意图** | I05 新旧对比、I03 适用性判断 | 多文档比对复用同一套效力裁决规则 |
| **四期 · 治理闭环** | 审计回溯 + 样本回流自动化 | 未命中样本自动进直击库候选池 |

> 一期不生成解读，很多人会嫌"不够智能"。但正是这一步能在**零幻觉风险**的前提下把**元数据质量、直击库准确率、权限模型**三个地基验完。地基没验就上生成，等于在没地基的地方盖二楼 —— 而且你永远不知道是哪一层塌的。

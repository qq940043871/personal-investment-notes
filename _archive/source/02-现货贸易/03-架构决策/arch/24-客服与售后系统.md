# 24 - 客服与售后系统

> 如何设计工单与售后处理链路

---

## 📖 概述

本章介绍工单系统与售后处理链路。

> **口径说明**：以下内容区分「本人真实做过（含早期系统雏形）」与「通用方案/行业知识」。

---

## 个人经验锚点

| 分类 | 内容 |
|------|------|
| **真实做过（早期）** | **在线投诉平台（2015）**的工单链路：用户提单 → 坐席处理 → 状态回写业务单据；**B2B 大宗平台**期间做过订单状态机驱动的售后处理。这些是售后系统的工程基础，但**非成熟的客服中台** |
| **真实做过（现职）** | **B2B 大宗交易平台**的售后/异常处理：以**状态机 + 事件溯源**驱动退换货与结算异常的处理与留痕，强调处理过程可追溯、资金不差错 |
| **通用方案/行业知识** | 大规模客服中台（智能分流、知识库、坐席质检、满意度体系）、平台级评价与信誉体系 —— 属行业参考，本人未主导过大型客服平台建设 |

## 📝 一、工单系统

### 1.1 工单状态机

```
[待处理] ──► [处理中] ──► [待确认] ──► [已解决]
    │            │            │
    ▼            ▼            ▼
[已退回]     [升级处理]   [已关闭]
```

### 1.2 工单表设计

```sql
CREATE TABLE `t_work_order` (
  `id` BIGINT PRIMARY KEY,
  `order_id` BIGINT,
  `user_id` BIGINT,
  `type` TINYINT,           -- 1=退款 2=退货退款 3=投诉 4=其他
  `status` TINYINT,         -- 1=待处理 2=处理中 3=待确认 4=已解决
  `reason` VARCHAR(500),
  `images` VARCHAR(2000),    -- 图片凭证
  `created_at` DATETIME,
  `updated_at` DATETIME
);
```

## 🔄 二、售后处理

### 2.1 退款流程

```java
@Service
public class RefundService {
    
    @Transactional
    public void processRefund(Long orderId, RefundDTO dto) {
        Order order = orderService.getById(orderId);
        
        // 1. 校验退款金额
        if (dto.getAmount() > order.getPayAmount()) {
            throw new BizException("退款金额超出");
        }
        
        // 2. 更新订单状态
        order.setStatus(OrderStatus.REFUNDING);
        orderDao.updateById(order);
        
        // 3. 原路退回
        refundPayment(order.getPayChannel(), order.getTradeNo(), dto.getAmount());
        
        // 4. 更新状态
        order.setStatus(OrderStatus.REFUNDED);
        orderDao.updateById(order);
        
        // 5. 发送退款消息
        mqProducer.send("order-refund", order);
    }
}
```

实时直播

Live Streaming — 多路同屏预览、云台可控、协议可降级，值班室与手机端看到的是同一路流

1/4/9/16 分屏 ONVIF 云台 WebRTC < 500ms 三级降级

场景背景：监控室值班的基本动作只有三个——同时盯住几十路画面、发现异常时把镜头转过去看清、把看到的那一刻截下来。这三件事对技术的要求完全不同：多路同屏考验的是分发与解码资源，云台考验的是和摄像头的控制协议，截图考验的是前端能不能拿到未跨域的原始帧。把它们塞进一个页面，才是「能用」和「能演示」的区别。

我的角色：直播链路的方案设计与实现。核心决策有两个：① 分屏不做「N 个摄像头 N 条拉流」，改为服务端一路输入、多客户端分发；② 云台不接厂商私有 SDK，改走 ONVIF 标准，让设备可替换。播放器侧我负责协议降级与实例生命周期治理——这是浏览器端最容易出内存泄漏的地方。

四个模块

1. 多路分屏预览

1 / 4 / 9 / 16 分屏自由切换，双击某一路放大到单屏，缩略图与主画面联动。值班员靠一屏扫完一个区域，不用来回切页签。

我的关注点：分屏不是「开 16 个播放器」，而是按可见区域按需装载——切到 4 屏时立刻卸载另外 12 路的解码器，否则 16 路同时硬解会把中低端显卡直接打满。这一条是把「演示能跑」变成「值班能盯 8 小时」的关键。

2. 云台 PTZ 控制

上下左右转动、镜头拉近拉远、速度可调、松手即停。发现画面里有异常，不用跑现场就能把镜头对准。

我的关注点：控制指令走 ONVIF 的 ContinuousMove / Stop，而不是各厂商私有 HTTP 接口——换句话说，换一个牌子的摄像头不用改代码。另外「松手即停」必须真的发一条 Stop，否则网络抖动丢了停止指令，镜头就会一直转到限位。

3. 实时截图

看到问题的瞬间一键截图，直接落到本地，不用装截图工具再裁剪。

我的关注点：Canvas 取帧要求视频源同源或允许 CORS，否则 toDataURL 会抛安全异常、拿到一张空白图——这是流媒体播放器接截图功能时最常见的坑，服务端必须在响应头放开流地址的跨域策略。

4. 多端协议自适应

PC 优先 WebRTC（<500ms），不支持则 FLV（1–2s），再不行 HLS（3–5s）；手机端直接 HLS 保证兼容。同一份代码，同一套 URL。

我的关注点：降级链要有终点，不能无限尝试。HLS 是最后一道兜底——它延迟最高但几乎什么浏览器都认，只要它还在，用户就不会看到黑屏。

实现：分屏容器的按需装载

分屏的核心不是布局，而是「布局变了，解码器要跟着增删」。下面的实现让分屏数量成为唯一状态源：数量一变，播放器实例就同步对齐，多出来的销毁、缺的补上。 

// 分屏播放器：以 screenCount 为唯一状态源，实例数量与之严格对齐
const screenCount = ref(4);                     // 1 / 4 / 9 / 16
const visible = computed(() => streams.value.slice(0, screenCount.value));

// 布局列数由分屏数推导，不写死四套 CSS 类
const gridClass = computed(() => `grid gap-2 cols-${Math.sqrt(screenCount.value)}`);

// 关键：屏幕数变化时同步销毁多余实例，避免解码器泄漏
watch(screenCount, async (n) => {
  await nextTick();
  playerPool.resize(n);                          // 内部对多出的实例 close()
});

// 双击放大：只是把分屏数切成 1，不新建播放器
const focusOne = (idx) => {
  activeStream.value = visible.value[idx];
  screenCount.value = 1;
};

闭环：一路输入，三段分发

摄像头 RTSP

FFmpeg 转码

ZLMediaKit

WebRTC / FLV / HLS

分屏 / 手机端

这条链上只有一个地方会「放大」资源：观看端。摄像头侧永远只有一路连接，转码侧靠复用进程摊平，分发侧靠 ZLM 的多协议输出。所以 100 个人看同一路，代价是 100 个播放连接，不是 100 次拉流。

  • 接入：RTSP over TCP，避免 UDP 丢包造成的花屏与卡顿；
  • 转码：zerolatency + GOP 25，GOP 缓存让新观众秒出画；
  • 分发：一次输入产出三档出口，按终端能力选；
  • 观看：分屏数即实例数，切换时同步回收解码器。

行业背景（一句话）

「实时看画面」在安防行业是刚需但极少被自研：主流做法是买 NVR 厂商的客户端或平台，代价是按路授权 + 只能在特定网络环境使用。自研实时直播的真正门槛，不在播放器，而在把并发观看的成本从摄像头和 CPU 上挪走。

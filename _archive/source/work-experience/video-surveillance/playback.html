录像回放

Playback — 事情发生之后，用时间轴把那一刻「倒回去看」，而不是在文件夹里翻 MP4

时间轴检索 0.5x–8x 倍速 告警片段高亮 预签名 URL

场景背景：回放的真实用法不是「看一段录像」，而是「在一段时间里找一件事」。事故/纠纷/丢货之后，用户手里只有一句模糊的时间点（「昨天下午三点左右」），要在几十小时录像里定位到那一分钟。如果只能按文件名一个个点开拖进度条，这件事的耗时是小时级；如果有时间轴 + 倍速 + 告警标记，就是分钟级。差别不在播放器，在检索模型。

我的角色：回放链路的方案设计与实现。关键决策是「元数据与文件分离」：录像的「记录」（哪台设备、几点到几点、存在哪、有没有告警）进 MySQL，MP4 本体进 NAS / OSS，检索只查元数据。第二个决策是播放地址不直连存储，改发预签名 URL，既控制了权限也控制了有效期。

四个模块

1. 时间轴检索

选设备 + 选日期，一天 24 小时的录像在一根时间轴上连续呈现，有录像的段落上色、没录像的留空。点哪跳哪，不用猜哪个文件是几点。

我的关注点：时间轴数据是「片段列表」而不是「文件列表」——一条记录 = 起止时间 + 告警标记 + 存储类型，前端拿到的就是可直接渲染的段。不把「文件怎么切片」的逻辑漏到前端，切片规则以后改了前端不用动。

2. 倍速与快进快退

0.5x / 1x / 2x / 4x / 8x 倍速，±30 秒跳跃，拖拽时间轴定位。找人找车的时间从「一小时一小时看」压到「几倍速扫一遍」。

我的关注点：倍速直接改 playbackRate，但进度要按「绝对时间」算而不是按「文件内偏移」算——否则跨片段边界一换文件，时间轴就会跳回 0，用户以为录像丢了。这是回放体验里最容易被忽略的一处。

3. 告警片段标记

移动侦测 / 告警触发的录像在时间轴上高亮，可以直接跳到告警发生的那几秒，不用整段看完。

我的关注点：告警标记跟录像记录一起存（hasAlarm 字段），不依赖外部告警系统在线。告警系统挂了，历史标记照样能查——这是「事后回溯」和「实时告警」必须解耦的地方。

4. 存储与播放地址

本体 MP4 存 NAS 或 OSS：本地的走 Nginx / 应用服务直出，云上的发预签名 URL（1 小时有效），前端拿到的永远是一条带权限的临时地址。

我的关注点：播放地址绝不把存储桶路径透给前端——一旦暴露，URL 会被复制外传，录像就是公开资源了。预签名 URL 把「谁能看、能看多久」交给签名表达，过期自动失效，也不需要为播放再造一套鉴权。

实现：把「一天」切成可直接渲染的片段

时间轴渲染的最小单元是片段，不是文件。下面这段是检索入口：按天圈定范围、按开始时间升序返回、顺带把告警标记带出来——前端拿到就能画，不需要二次加工。 

@Service
public class RecordingSearchService {

    /** 时间轴片段：前端唯一的渲染输入，不含存储细节 */
    public List<TimelineSegment> timeline(Long cameraId, LocalDate day) {
        LocalDateTime from = day.atStartOfDay();
        LocalDateTime to = from.plusDays(1);

        return recordingRepository
            .findByCameraIdAndStartTimeBetweenOrderByStartTimeAsc(cameraId, from, to)
            .stream()
            .map(r -> TimelineSegment.builder()
                .recordingId(r.getId())
                .startTime(r.getStartTime())
                .endTime(r.getEndTime())
                .hasAlarm(r.getHasAlarm())        // 告警标记随记录一起返回
                .build())
            .collect(Collectors.toList());
    }

    /** 播放地址：OSS 发预签名（1 小时），本地走应用代理，前端只见临时地址 */
    public String playbackUrl(Long recordingId) {
        Recording r = recordingRepository.findById(recordingId)
            .orElseThrow(() -> new NotFoundException("录像不存在"));

        return r.getStorageType() == StorageType.OSS
            ? ossService.generatePresignedUrl(r.getFilePath(), 3600)
            : "/api/recordings/play/" + recordingId;
    }
}

回放这条链的价值在「收敛搜索空间」：从「几十小时」收敛到「有告警的那几分钟」。告警标记、倍速、时间轴三件事各自只解决一段，合起来才把定位时间压到可用。

  • 定位：按设备 + 日期圈定，缺口在时间轴上直接可见；
  • 收敛：告警片段高亮，先看有事的、后看没事的；
  • 确认：倍速扫看 + ±30s 微调，落在具体秒级；
  • 留证：截图或转下载，进入取证流程（见「视频下载」）。

行业背景（一句话）

监控系统的价值有 90% 发生在「事后」：出了事才有人打开它。所以回放的检索效率直接决定了这套系统在客户心里的价值——一个找不到录像的监控平台，等于没装。

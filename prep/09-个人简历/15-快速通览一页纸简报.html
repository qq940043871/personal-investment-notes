行业四大特点（⭐必须能说）

  1. 交易金额大、决策链长——单笔合同几十万到几千万，客户对"信任"的敏感度远高于"价格"
  2. 高度依赖线下关系链——电话+微信+饭圈做生意，数字化意愿有但习惯迁移难
  3. 资金敏感——账期、垫资、融资成本是命门，供应链金融是留客杀手锏
  4. 参与方多、单据杂——一笔交易涉及买卖双方+仓库+物流+银行+质检，任何一方掉链子全链卡壳
加分句："我们平台上一个小采购经理的真实处境是：打四个电话比价，问到第四家时第一家的价格已经作废了——这就是我们要服务的人和我们要解决的场景。"

核心架构一：合同域与履约域解耦 ⭐

"合同域（谁、什么、多少、什么价）与履约域（付款、发货、收货、开票）彻底解耦。大宗贸易合同变更极其频繁——耦合在合同上，每次变更都是数据迁移事故。解耦后：合同是版本链（原合同+N 补充协议），履约是独立计划与任务流，两者通过事件总线联动。核心表：contract / contract_item / contract_party / fulfillment_plan / payment_order / shipment_order / receipt_settlement / fund_pool / invoice / refund_order。"

核心架构二：双轨履约引擎 ⭐⭐

由合同上的 delivery_mode 决定走哪条轨：
① 顺序交收——状态机强制有序（先款后货类），强一致，适合标准化高风险交易；
② 自由交收——事件驱动+规则引擎并行流转，适合长期合作客户灵活交收；
③ 两轨共用同一套底层履约任务数据结构，监控风控视角统一；
④ 之上叠加五种交收模式：款到发货、货到付款、定金+尾款、分期付款、信用证。
Trade-off："顺序轨用状态机换确定性，自由轨用事件驱动换灵活性——代价是自由轨异常补偿复杂，我们用规则引擎把补偿策略配置化，而不是硬编码。"

SaaS 化技术难点（多租户架构攻坚）

8 大架构挑战
  • 客户场景化参数配置千差万别
  • 参数组合爆炸陷阱（致命）——配置项组合呈指数增长
  • 能力集治理——按租户裁剪功能能力
  • B2B 平台7 大架构遗留问题
方案与路径
  • 多运营商架构——一个平台服务多个运营主体
  • 独立门户方案——租户自有域名/品牌门户
  • 数据隔离——租户级数据隔离与安全边界
  • 实施演进路径——从专有部署到多租户 SaaS 的渐进路线

核心服务沉淀（SaaS 化的产物）

  • 统一账户模块（B2B 支付）· 统一订单服务 · 统一商品服务——三大统一服务是"管理端 → SaaS 运营端"产品化的地基
  • 关键判断："参数组合爆炸是 SaaS 化的致命陷阱——解法不是加配置项，而是能力集治理：把'功能可配'收敛为'能力可裁剪'，配置爆炸从根上消掉。"

STAR 战绩 · 技术经理解决了什么（每案例 90 秒）

① 河南能源双平台交付（主战故事 ⭐）

A：承建大宗商品交易平台（竞价/挂牌/长协/专场）+ 中原云商阳光采购平台，销售端多模式交易状态机+异常出价风控，采购端全流程留痕+电子签约
R：累计成交 1.1 亿吨 / 673 亿元，竞价溢价增收累计 8 亿；采购周期 20 天 → 7 天，成交项目破万；客户 2026 转型方向与四层架构判断一致

② ICC 系统重构

A：参数从本地配置文件迁到 HTTP 按 deviceId 实时获取，设计降级路径（本地缓存兜底）+ 分环境灰度
R：配置生效从"重启级"降到"秒级"，排障时间大幅缩短。金句："任何去中心化方案必须先设计好降级路径。"

③ Postman 接口资产自动化

A：870 个业务请求/244 个文件夹手工集合 → Python 工具一键生成，统一参数展开与 directives 包装两种格式
R：接口资产从"手工维护的负债"变成"一键重建的资产"，联调成本显著下降

④ 期货套保风控子系统

A：设计 strategy/risk/balance/config/report 五模块——套保策略绑定现货合同、敞口实时计算、风险限额分级预警
R：期现联动从"Excel 手工台账"升级为系统化管控

⑤ AI 工程化能力（差异化故事）

LangChain/LangGraph 流水线、Agent Harness 架构（FastAPI+Vue3+PyQt6）、自动绘本生成智能体——"我同时在做 AI 工程化落地，知道 LLM 能力和工程约束的边界在哪。"
落地原则：智能推荐/单据识别/风控辅助 = "AI 提效、人兜底"；资金操作、合同生效等强一致场景 AI 只做提示不做决策。

STAR 使用提醒：R 必须有数字或可感知的变化；A 里必须有一个"我拍板的关键决策"——面试官在验证是"你带队"还是"你参与"。

半年规划 · 优先级判断（2 分钟）

⭐ 按"先止血、再还债、后增值"排：
  1. 第 1 个月（止血）：统一图表库与公共组件库，建立前后端契约（OpenAPI）和自动化对账——不解决，每加一个功能都在放大技术债
  2. 第 2-3 个月（还债+补短板）：履约链路 trace 与事件回放；跨端从 iframe 向微前端演进的技术验证；司机端补齐最小闭环
  3. 第 4-6 个月（增值）：基于可信履约数据把供应链金融做深（平台商业护城河）；试点 AI 接入（智能推荐、单据识别、风控辅助）
收尾句（⭐）："优先级的底层逻辑只有一个：先保证平台数据可信（履约/结算/仓单），再谈金融增值——信任是这个行业的货币。"

9.3 异构四层架构 · C 撮合 + Java 业务（交易核心底座 ⭐）

"交易核心是C 语言单线程内存撮合引擎，业务是 Java 微服务体系，两者之间用自研的 DS 数据中心做协议转换与防腐。一句话：性能关键路径用 C 换确定性，业务复杂度用 Java 换可维护性，异构摩擦全部收敛在 DS 这一层。"
L1 · 接入与网关层

三类终端（外部大屏 / 普通客户 / 机构客户，均覆盖 PC + 移动）→ 自研网关 midservice 多实例 + midmon 监控：统一鉴权、限流、租户路由、请求日志；多实例保证单节点故障不影响整体可用性。

L2 · Java 业务中台（12+ 微服务 · 双核之一）

管理系统 10+ 模块（客户 / 超级账本 / 商品类目 / 交易 / 合同 / 门户 / 权限 / 交易风控）+ 业务服务集群 12+ 服务（认证 / 用户 / 账本 / 合同 / 资金 / 运力 / 创新挂牌 / 自由竞价）；服务间 Hessian RPC，Canal 监听 binlog 同步至独立缓存服务（Redis）加速读。

L3 · DS 数据中心（Java 自研 · 防腐层 ACL）⭐

C↔Java 的唯一桥：下层 TCP + 自定义二进制报文，上层 Hessian over HTTP（同步）/ Socket（异步）。承担连接管理、心跳保活、断线重连、熔断降级、超时与请求 ID 追踪、协议版本兼容。选 Hessian 不选 JSON——高频二进制交互，序列化/解析开销低得多。

L4 · C 撮合引擎（性能底座 · 双核之二）

单线程纯内存撮合（价格优先·时间优先）+ 异步落库。选 C 换的是延迟确定性——Java 一次 Full GC 就可能让撮合中断几十毫秒；单线程无锁 + CPU 亲和，纳秒级延迟。对外只暴露"标准化指令输入 / 撮合事件输出"，撮合算法本身对业务团队是黑盒。

存储与外部生态（底座两侧）

存储：MySQL 双实例（读写分离 + 容灾备份）· MinIO 对象存储（合同 PDF / 仓单扫描件 / 质检报告 / 发票影像等履约凭证）· 文件服务统一管理上传下载与权限。生态：9+ 外部系统——银行（支付/融资）、短信、CA 证书、物流仓储、CTRM、开票、企查查、供应链金融；每接一个接口都是熔断降级（连续失败切备用通道）+ 异步回调 + 日终对账三件套。

选型 Trade-off（⭐）："为什么不让 Java 直接做撮合？不是 Java 慢，是 GC 停顿不可控——撮合要的是延迟确定性，不是平均速度。代价是 C 可维护性差、内存要手工管，所以解法不是'换语言'，而是给 C 核心外面建三层护栏：① 只暴露指令/事件契约；② 所有调用必须过 Java 桥接层（DS）；③ 撮合 TPS / 积压队列 / P99 延迟结构化输出接入监控。更关键的是不把 Java 写进 C、也不让 C 逻辑外泄到 Java，C 团队与 Java 团队各自独立演进、互不阻塞。"
管理抓手（⭐）："我不写 C 代码，但 DS 是 Java 写的，正好在我的技术栈覆盖范围内——用'接口契约治理 + DS 协议转换逻辑 review + 可观测性指标'三件套，管住一个我不写代码的 C 撮合引擎。你能管住的边界，就是你能负责的边界。"（§7 故事①河南能源双平台就建在这套底座上）

详见：异构四层架构图（需能脱手画） · 异构架构叙事手册（协议选型 / 桥接 SDK / 30 秒·2 分钟话术）

9.4 关键技术突破

  • 双轨履约引擎——业内没有统一的履约节奏标准，用"状态机轨（确定性）+ 事件规则轨（灵活性）"双轨并存、底层数据结构统一，解决强顺序与自由交收两类客户的兼容难题；自由轨异常补偿用规则引擎配置化。
  • 资金预检 2PC——大额资金场景"宁可慢不可锁"，跨域用事件+每日对账兜底，唯独资金预检这一跳用两阶段提交思路，保证资金操作零中间态。
  • 支付渠道适配器——平台不碰资金池（二清红线），统一适配器接口 + 渠道插件化（银行直连/银企直联/第三方持牌），到账时效与回单格式差异在适配层抹平。
  • 期现敞口实时轧差——点价量/在途量/已点未发/期货头寸实时联动计算，套保策略绑定现货合同，自研才能把"现货合同→敞口→期货头寸"做成一条链（通用风控软件拿不到一手数据）。
  • 合同版本链 + 电子仓单货权链——版本混乱与货权不清这两个行业死结的架构级解法：原合同+N 补充协议全留痕存证；仓单全生命周期 + 货权流转留痕 + 质检扫码溯源。
  • SaaS 能力集治理——破解"参数组合爆炸"陷阱：把"功能可配"收敛为"能力可裁剪"，配置爆炸从根上消掉。

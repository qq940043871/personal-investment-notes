技术经理自我提升计划

从 L2 到 L3/L4 · 站位升级 + 临时方案治理 ｜ A4 打印版
一句话定位：我不是能力不够，是站在需求下游 + 没有治理机制。破局 = 换站位（进业务上游）+ 建机制（债台账 / 标准件）+ 向上换资源。核心不是加技能，而是换"信息位置"。本周先做三件事：建技术债台账、约业务负责人做季度预判对齐、把一个高频临时方案沉淀成标准件。

一、看清困境本质（诊断）

1. L2 → L4 差在哪？—— 不是技术，是"站位"

层级业务理解典型状态信息位置
L1听懂需求文字"PM 让做什么我做什么"需求最下游
L2（现在）理解功能逻辑"知道怎么实现、大概为什么做"需求下游，被动接单
L3预判业务影响"这么做有隐患，我建议改…"进业务讨论，能反向影响
L4引导业务方向"基于技术能力可开新模式"业务上游，参与战略
分水岭：你出现在"需求被决定之前"还是"之后"？需求定稿才到你手里 = 永远是 L2；需求会上能发声 = 摸到 L3。

2. "资源不足 → 临时方案"的恶性循环

资源不足 → 打补丁 → 技术债累积 → 救火占满时间 → 更没时间建设 + 更没底气要资源 → 资源更少（回到起点）。

破局点不在"要更多资源"（要不到），而在打断循环一环：让临时方案"可治理"，把救火时间省出来换建设。临时方案不是罪，"没归档、没偿还计划"才是罪。
三个关键杠杆：① 建技术债台账（隐性 → 显性）② 临时方案三军规（必留退路 / 必进台账 / 必设触发线）③ 标准件复用（救火时间递减）。

3. 中小公司特殊约束（别自我内耗）

  • 没有专职架构师 = 这正是你上位 L4 的空位
  • 没有基础设施团队 = 你攒的每个标准件都是个人资产
  • 业务变化快 = 临时方案是合理生存策略，关键别"野蛮生长"
  • 老板要结果不是架构美学 = 改善都要翻译成"少出事故 / 快上线 / 省人力"

二、业务理解升级：换站位（三动作，零成本）

动作① 业务预判对齐机制（撬动 L3 的关键）

每季度约业务负责人 30 分钟，只问三句：

  • "下季度业务重点想打什么客户 / 交易模式？"
  • "现在业务上最卡、最想解决的痛点是什么？"
  • "如果技术不是瓶颈，你最想要什么能力？"
话术："王总，我想每季度花半小时了解业务重点，提前把技术底子铺好，而不是需求下来才发现架构不支持、临时赶工出问题。"—— 让业务方觉得你"靠谱、有前瞻性"。

动作② 需求翻译 → 需求挑战

L2 做法L3/L4 做法
收需求 → 估工时 → 排期先问"为什么做 / 解决什么业务问题 / 成功指标是什么"
"能做，要 5 天""改成 XX 方式，能同时解决你下月要做的 YY，省一次开发"
只对"怎么做"负责对"该不该做、做了有没有效果"也发声
每次需求评审强迫自己问："这需求成功了，业务指标会怎么变？" 问多了，脑子从"功能思维"切到"业务思维"。

动作③ 业务-技术映射地图

周末把平台核心业务链路画出来，每环节标三件事：① 业务在干嘛（业务语言）② 对应哪个技术模块（技术语言）③ 一旦出问题业务损失是什么（钱 / 客户 / 合规）。→ 一眼看清资源投哪、债先还哪；面试 / 汇报用业务价值讲技术。

三、临时方案治理：让系统持续变好（四招）

招① 技术债台账（第一杠杆，零成本）

债务项模块临时方案风险偿还成本优先级
对账靠人工结算每天导 Excel漏账 / 资损3 人日P0
作用：① 隐性债 → 显性可控；② 向上要资源的弹药（"3 项 P0 不还会导致资损"）；③ 团队有共识，别在债上加债。本周花 2 小时倒出所有债排优先级，从"焦虑救火队长"变"心里有数的操盘手"。

招② 临时方案三军规（让补丁不失控）

  • 必留退路：能被替换，不集中硬编码挖坑
  • 必进台账：打完立即登记，标"何时该还"
  • 必设触发线：写清"调用量超 N / 出第 2 次事故 → 启动正式方案"（给补丁死亡时间）

招③ 标准件复用（四两拨千斤，复利效应）

第一次救火写死 → 第二次抽成通用工具类 → 第三次直接复用（5 分钟）。维护团队"标准件清单"：熔断 / 重试 / 幂等 / 对账 / 日志规范。救火时间随时间递减，省出 = 建设时间。

招④ 绞杀者模式（渐进重构，不推倒重来）

老方案继续跑 → 新流量走新标准实现 → 老流量逐步迁移 → 老方案归零自然下线。不停机、可回滚、风险低，是资源受限团队唯一现实的重构方式（面试加分：演进式架构）。

四、团队管理 + 向上沟通（"创造"资源）

团队：你救火 → 团队救火

  • 救火 SOP 文档化，初级也能处理
  • on-call 轮值（哪怕 2 人）
  • 评审强制问"这是临时方案吗？进台账了吗？"

向上：技术语言 → 老板语言

  • "重构结算" → "人工对账 Q4 可能资损，5 人日自动化杜绝"
  • "技术债多" → "3 隐患不处理明年翻倍会宕机影响签约"
  • 公式：风险（量化）+ 方案（低成本）+ 收益
技术健康度季度汇报：还了几项债 / 避免几次事故 / 稳定性指标变化 / 沉淀几个标准件 —— 让"看不见的建设"可见、可量化，是建立老板信任最快的动作。

五、90 天改善路线图

阶段时间关键动作目标
止血期第 1-2 周建技术债台账 + 定三军规债显性化、可控
换站位期第 3-6 周业务预判对齐 + 需求评审问"为什么"挤进上游，摸 L3
建机制期第 7-10 周沉淀 2-3 标准件 + 救火 SOP / on-call救火时间下降

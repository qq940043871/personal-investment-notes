# 第一部分：心态建设 — 先破心魔

## 1.1 你不需要什么都懂

技术 Leader 面试焦虑的三个来源，以及为什么它们不成立：

| 焦虑来源 | 为什么不用怕 |
|---------|------------|
| "他会不会问我没听过的技术？" | 你是技术 **Leader**，不是技术 **专家**。Leader 面试的核心考察点是**决策力、治理能力、业务理解、团队管理**。你不懂 C 语言细节，但你管得住 C 引擎。 |
| "万一问到盲区怎么办？" | 面试是双向选择，不是考试。敢于说"这块我不深，但我有另一种思路"比硬撑强 100 倍。 |
| "需要准备的东西太多了" | 实际上你只需要准备好**三个主场**——剩下的都是客场，客场不需要赢，不丢分就行。 |

> **核心心法**：Leader 面试不是"回答所有问题"，是"把 80% 的面试时间花在自己最强的 3 个主场上"。

```
不慌 = 知道什么不必准备（减负）
     + 把必准备的主场练到肌肉记忆（聚焦）
     + 有不会的问题时的兜底话术（安全感）
     + 相信不是审判而是双向选择（心态）
```

## 1.2 你的三个主场（画清楚边界）

基于你的真实经验，你的不可替代性集中在三个方向。凡不在这三个方向上的问题，都是客场，及格即可。

### 主场一：驾驭异构架构（技术决策力）

**为什么这是你的主场**：
市面上 90% 的 Java 技术经理只会 Spring Boot 全家桶。你能同时面对 C 撮合引擎 + Java 业务中台 + Vue 前端三套异构系统——这是跨语言、跨范式的治理能力。

**必须脱口而出**：
- 四层架构：接入 → 网关(midservice自研) → 业务中台(DS+交易核心+12微服务) → 数据层
- 双核驱动：C 撮合引擎（单线程内存撮合，纳秒级确定性）+ DS 数据中心（Java 防腐层）
- C↔Java 通信：TCP + 自定义二进制报文；Java↔Java 通信：Hessian
- DS 数据中心的价值：收敛异构复杂度到单一桥接点，业务层完全不感知 C

### 主场二：技术+业务双修（商业思维）

**为什么这是你的主场**：
大多数技术经理说不清自己做的产品到底解决了什么客户问题。你能从挂牌讲到交收、从资金讲到税务、从仓单讲到供应链金融。

**必须脱口而出**：
- 五大业务模块：交易模式 / 履约保证 / 数据服务 / 规则配置 / 生态对接
- 客户价值三层：效率（5天→1.5天）/ 风险（三年零差错）/ 增长（供应链金融）
- 竞争壁垒：数据飞轮 / 配置化引擎 / 外部集成深度 / 行业复合人才 / 信任资产

**快问快答训练**：
- "你们平台解决什么问题？" → "大宗贸易线下交易效率低、风险高，我们让交易周期从5天降到1.5天、三年零资金差错"
- "客户为什么用你？" → "不是因为我们数字化，是因为我们钻进了线下做不了、做不好、做不快的缝隙"
- "和找钢网/1688有什么区别？" → "他们是轻量撮合，我们是重度垂直——一个订单几百万，履约全闭环"

### 主场三：从救火队长到技术操盘手（领导力）

**必须脱口而出**：
- 管理哲学：靠制度管人、靠台账管债、靠流程管风险
- 技术债治理：台账 + 还债比例（每迭代20%时间）+ 向上沟通公式
- 团队机制：On-call 轮值、事故复盘不追责、Code Review 卡债
- 契约治理：跨团队接口SLA、决策权三档（做/建议/知晓）

**必准备的故事**：
> "我刚接手的时候是个救火队长。后来做了三件事：建了 On-call 轮值，逼团队成长也逼系统暴露真问题；建了技术债台账，把隐性的坑全部显性化；推了事故复盘不追责文化。半年后救火时间降了一大截，冬储期一整季零 P0。"

## 1.3 客场生存法则

面试中大概 30% 的问题不在你的三个主场上。客场不需要赢，及格就行。

| 问题类型 | 识别标志 | 策略 |
|---------|---------|------|
| **知识盲区** | 问一个你没用过/不了解的技术 | "这块我不深，但根据我的经验，类似场景下核心考量是 X 和 Y……" |
| **假设性开放题** | "如果你从零设计这个系统……" | 用你已有的经验框架去套：先分层、再定边界、再讲 trade-off |
| **行为面试** | "你有没有遇到过 XX 情况……" | 永远用 PEARL 框架，不要讲理论，讲真实发生过的事 |
| **压力题** | "你觉得你最大的弱点是什么？" | 诚实但策略性——讲一个真实弱点 + 你已经在做的改进 |

**不会就说不懂，但给一个"平移思路"**：
> "这个技术我没直接用过，但如果类比到我们平台的情况，核心问题应该是 X 和 Y 之间的 trade-off。我们之前处理过类似的场景，当时的思路是……"

**把客场问题引导回主场**：
> 面试官："你们怎么做的 A/B 测试？"
> 你："我们没做 A/B 测试。但我们在多租户场景下，通过规则引擎 + 配置化实现了客户的个性化需求——100 多个客户各有不同的计费规则和风控阈值，5 分钟改规则生效。这个跟 A/B 测试的底层逻辑类似。"

## 2.3 PEARL 回答框架（STAR 升级版）

| 字母 | 含义 | 你的打法 |
|------|------|---------|
| **P**roblem | 问题是什么 | 用具体数字："冬储期交易量从日均 1000 笔暴增到 8000 笔" |
| **E**vidence | 有多严重 | "撮合引擎 CPU 冲到 92%，有一次差点崩，所有交易挂起 5 分钟" |
| **A**lternatives | 做过什么比较 | "我们比较了三个方案：加机器（不管用）、拆服务（风险大）、分层降级（可行）" |
| **R**easoning | 为什么这么选 | "C 撮合引擎是单线程的，加机器没用。核心思路是把非关键链路降级" |
| **L**esson | 收获和沉淀 | "事后我们建了冬储预案 SOP，第二年零 P0" |

**PEARL 比 STAR 更锋利的原因**：多了 E（严重性）→ 让面试官感受到真实；多了 A（方案对比）→ 展示决策思维；多了 R（推理过程）→ 展示 trade-off 能力；多了 L（收获）→ 证明有复盘能力。

## 2.4 三个必杀问题

### 必杀 1：为什么 C 撮合引擎不迁移到 Java？

**第一层（技术事实）**：
> "C 撮合引擎是单线程内存撮合，没有 GC 停顿，延迟是纳秒级且确定性的。Java 做撮合，GC 会在不可预测的时间点暂停所有线程，对于金融交易来说，这个不确定性不可接受。"

**第二层（决策思维）**：
> "我们评估过要不要迁。不是不能迁，是不值得迁。C 撮合引擎跑了多年，稳定、零事故。迁移到 Java 不仅可能引入 GC 延迟，还要重新验证所有撮合逻辑——测试成本巨大，收益为零。"

**第三层（管理智慧）**：
> "我一个 Java 技术经理管 C 引擎，听起来矛盾对吧？但恰恰因为我不懂 C 代码，我才更关注它的可观测性——日志、监控、告警。我建了 DS 数据中心做防腐层，把 C 的二进制协议封装成 Java 对象。我不是管 C 代码，是管 C 引擎的健康。"

### 必杀 2：你们的平台和找钢网/1688 有什么本质区别？

> "两个本质区别。第一，我们是重度垂直，不是通用平台。1688 做轻量撮合，品类极多但每个品类很浅。我们做大宗交易，一个订单几百万，履约链条极长——从挂牌到签合同到支付到质检到仓储到物流到开票。"
> "第二，我们的壁垒不是技术本身，是数据和集成深度。五年的交易数据形成的定价模型和风控画像，100 多个客户磨合出来的配置化规则引擎，9 个外部系统的技术适配和商务关系——这些不是写代码能解决的，是时间垒出来的护城河。"

### 必杀 3：你最大的失败是什么？

> "第一年冬储期系统崩了一次，撮合引擎挂了 5 分钟。这不是技术问题——是我作为技术负责人没有提前做容量规划和应急预案。"
> "我学到的不是'怎么修 bug'，是'怎么建体系'。事故之后我做了三件事：建了冬储预案 SOP、推了 On-call 轮值机制、推了技术债台账。第二年冬储，零 P0。"

## 2.5 SCOPE 快速组织框架

拿到一个问题，内心默念五个词，然后开口：

| 字母 | 含义 | 你开口说的 |
|------|------|----------|
| **S**ituation | 问题发生的场景 | "在我们平台，这个问题的典型场景是……" |
| **C**onstraint | 当时有什么约束 | "受限条件是我们只有 XX 资源和 YY 时间窗口" |
| **O**ptions | 考虑过哪些方案 | "当时我们比较了 A/B/C 三个方案" |
| **P**ick | 选了哪个、为什么 | "我们选了 B，因为……"（展示 trade-off 思维） |
| **E**ffect | 结果和收获 | "最终结果是……，这件事教会我……" |

## 3.3 面试前 10 分钟速查卡

### 业务
- 三层价值：效率(5天→1.5天) / 风险(零事故) / 增长(供应链金融)
- 四种价值：信任中介 / 信息聚合 / 交易效率 / 金融服务
- 五大壁垒：数据飞轮 / 配置引擎 / 外部集成 / 复合人才 / 信任资产

### 架构
- 四层：接入(三端) / 网关(midservice多实例) / 中台(DS+交易核心双核) / 数据(MySQL×2+MinIO)
- 双核：C撮合(纳秒级) + DS数据中心(Java桥接/防腐层，Hessian+Socket)
- 9+外部：银行/短信/证书/物流/CTRM/开票/咨询/企查查/供应链金融

### 技术
- Redis：String→价格 / Hash→权限 / ZSet→延迟队列+排行
- MySQL：B+Tree / 聚簇+二级 / 最左前缀 / EXPLAIN
- MQ：本项目统一 Kafka（outbox 本地消息表 + 消费幂等；延迟消息用 Redis ZSet）
- 事务：Saga+状态机+补偿（不用 2PC/Seata：全局锁 3 秒不可接受 + 侵入 + 运维成本）
- 锁：SETNX→Redisson→RedLock→ZK

### 管理
- 三件套：On-call轮值 / 技术债台账 / 接口契约治理
- BOUNDARY：坦诚深度区 → 契约治理 → 风险地图 → 用机制替代亲力亲为

## 3.5 面试当天心态指南

1. **你不是去乞求一份工作，你是去跟一个潜在合作伙伴探讨你能创造什么价值**
2. **面试官问的不是你的 JD，是"你来了之后发生了什么变化"**
3. **诚实比完美重要**——不知道就说"这块是我需要补的，我目前正在通过 XX 方式学习"
4. **B2B 是你的差异化优势**——能驾驭异构系统+懂大宗贸易的人远比只会 Spring Boot 的人稀缺
5. **每个回答都要有结构**——先说结论，再说原因，最后给数据

1我们的产品是做什么的

我们是 B2B 大宗商品在线交易与供应链服务平台——一个让钢铁、煤炭、化工等大宗贸易全链路数字化的产业互联网平台。

核心功能：三位一体

电子交易（基础）

撮合买卖双方，7 种交易模式

现代物流（保障）

仓储 + 物流全程可控，货权清晰

供应链金融（增值）

交易数据变信用资产，解决资金约束

七种交易模式

挂牌交易 双边协商 竞价拍卖 招标 集采拼单 托盘代采 基差点价

技术架构一句话

C 语言单线程内存撮合引擎（纳秒级、无 GC）+ Java 微服务业务中台 + Vue 三端，通过自研 DS 数据中心做异构桥接。C 负责快，Java 负责稳，DS 负责翻译。

3产品有什么特点

全链路线上化

询价→合同→支付→仓储→物流→质检→结算→开票，全程在线。客户不出门，能购天下物。

多租户深度定制

每个大客户的行规不同。我们不逼客户适应系统，用规则引擎 + 配置化适配每个客户。

金融级可靠性

多年零资金差错、系统可用率 99.95%、电子仓单零重复质押事故。

价值主张（一句话）：把大宗贸易从"靠人脉、靠电话、靠运气"的生意，变成"靠数据、靠系统、靠信用"的生意。

4客户为什么要购买

大宗贸易线下有四个"怎么都搞不定"的死结——每一个痛点对应一个买单理由。

痛点一 · 信任壁垒 —"跟陌生人做生意不敢"
  • 交易靠熟人关系，人脉圈就是生意天花板 → 平台担保 + 资金监管账户，钱不过对方手
  • 不了解新供应商靠不靠谱 → 履约率公开 + 交易历史可查："累计成交 2.3 亿，履约率 97.8%"
  • 先款怕不发货，先货怕收不到钱 → 保证金 + 信用评级 + 争议仲裁

本质：把"对人的信任"变成"对系统的信任"。

痛点二 · 信息不对称 —"价格不透明、货不好找"
  • 打 5 个电话才能比价，问到一半价格就变了 → 实时行情 + 一键比价 + 标准化产品编码
  • 供应商说"有货"，下单后发现没货 → 库存与 WMS 实时打通，下单即校验
  • 不知道该卖多少钱 / 该花多少钱买 → 行情中心 + 历史成交价参考
痛点三 · 交易效率 —"一笔交易跑断腿"
  • 合同来回邮寄改 4 版，签约要一周 → 电子合同 + 电子签章：1 周 → 1 天
  • 跑银行柜台打款，跨行 T+1 → 银企直连实时到账：即时
  • 每天电话催"货到哪了" → 物流轨迹实时追踪，像查快递一样
  • 月底 Excel 对账对到崩溃 → 全链路自动勾稽 + 差异高亮：3 人天 → 2 小时

全链路核心数字：一笔交易 5~7 天 → 1.5 天。

痛点四 · 资金约束 —"有好机会但缺钱"
  • 看到低价货但缺采购资金（银行贷款 2 周审批，机会早没了）→ 预付款融资：平台垫资代采，货到仓库质押
  • 货压在仓库，库存就是死钱 → 仓单质押融资：货值 70% 变成流动资金
  • 货卖了款没回，账期 30–90 天 → 应收账款融资：按 80% 提前变现

为什么银行做不了、平台能做：平台有真实交易数据 → 银行敢放款。"没有交易数据的人做金融是在猜，我们是在算。"

三层价值结构（从下往上讲，层层递进）

第三层 · 增长价值（壁垒） — 月交易量翻倍 / 供应链金融开展 / 数据飞轮
第二层 · 风险价值（B2B 独有） — 零资金差错 / 零重复质押 / 合同自动校验
第一层 · 效率价值（最易量化） — 5天→1.5天 / 对账3人天→2小时 / 签约1周→1天

竞争壁垒：五个不可复制

  1. 数据飞轮：交易越多 → 数据越多 → 风控越准 → 金融越便宜 → 更多客户来
  2. 配置化引擎：100 个客户喂出来的抽象能力，新进入者至少需要 2 年
  3. 外部集成深度：已对接 5+ 银行、10+ 仓库、税务、签章等，追赶成本极高
  4. 行业复合人才：既懂技术又懂大宗的人，培养周期 2–3 年，市场极度稀缺
  5. 信任资产：时间 × 零事故 = 不可速成的护城河

6我解决了什么问题，得到了什么结果

面试策略：五个成果挑 2–3 个讲，按"问题 → 方案 → 结果"三段式，配金句收尾。

成果一 · DS 桥接层 — 驾驭 C + Java 异构架构
问题

C 撮合引擎是黑盒，只暴露 TCP 二进制协议；上层 12+ Java 微服务无法直接通信

方案

设计 DS 数据中心作为防腐层（Anti-Corruption Layer）：下层 Java NIO 收 TCP 二进制 → 协议解析；上层 Hessian 暴露标准接口

结果

异构复杂度完全收敛在一层，C 团队与 Java 团队各自独立演进，互不阻塞

"我不写 C 代码，但设计了 DS 这一层让 C 和 Java 能对话。技术经理的价值不是写了多少代码，而是在正确的边界上做了正确的架构决策。"
成果二 · 多租户配置化 — 打破"每客户一套代码"的死循环
问题

每接一个大客户，开户/挂牌/合同交收全流程都要改代码。100 个客户 = 100 套大同小异的代码

方案

策略模式 + Drools 规则引擎 + 配置化模板。不变的部分做成统一引擎，可变的部分（报价方式/结算节奏/审批层级/合同格式）做成按客户配置

结果

新客户上线：2 个月 → 1 周，代码不再膨胀

"大宗行业的铁律是每个大客户都有自己的玩法。正确的策略不是压住差异化，而是让引擎支持差异化——不变的部分写死，可变的部分配出来。"
成果三 · 跨月长事务一致性 — 多年零资金差错
问题

一笔交易跨 1–3 个月，十几个状态变迁（签约→保证金→备货→发货→质检→结算→开票），每个状态要同步 4–6 个系统。电商的秒级事务方案完全不适用

方案

Saga + 状态机 + 事件溯源。每个操作定义正向 + 补偿动作；每个状态定义前置条件 / 触发事件 / 副作用 / 补偿 / 超时处理

结果

运行多年，零资金差错

"做一个'能跑'的状态机只需 1 个月，做一个'不会出事'的状态机需要 2 年——因为你要见过所有异常场景，才知道补偿路径怎么写。"
成果四 · 管理三件套 — 从救火队长到技术领导者
机制做什么效果
On-call 轮值主副双岗按周轮换，P0–P3 四级 SLA团队独立处理 80% 线上问题，凌晨叫起从月均 8 次 → 2 次
技术债台账债务项 / 风险 / 成本 / 优先级可视化管理隐性债务 → 显性 → 可控
20% 带宽原则每迭代固定 20% 产能用于技术债偿还被动响应占比从 45% → 15%
"临时方案不可怕，没有退路、没有记录、没有终点的临时方案才可怕。"
成果五 · 场景化工作台 — 从"功能菜单"到"任务向导"
问题

左侧导航几十个入口，客户不知道点哪里，新客户培训要半天

方案

按客户任务组织界面：我要买货 / 我要卖货 / 我要发货 / 我要对账。一个任务一条线性引导流 + 角色视图自动过滤

结果

新客户培训：半天 → 30 分钟，客服咨询量下降 60%

"客户来平台是带着明确任务来的，不是来'逛'的。你按功能堆菜单，等于把说明书甩给客户让他自己研究。"

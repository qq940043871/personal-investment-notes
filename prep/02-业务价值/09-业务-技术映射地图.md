## 1. 全景链路图（一屏看懂）

```
【准入 / 入口】          【交易】                                  【成交后：履约与收尾】
E1 开户准入 → E2 登录鉴权 → E3 挂牌报价 → E4 询价撮合 → E5 订单聚合
                                                          │ 成交事件（outbox → Kafka）
                                                          ▼
   E6 合同签署 → E7 保证金冻结/履约编排 → E8 支付结算与对账 → E9 仓储仓单/物流交收 → E10 发票税务
                                                                                    │
                                                                                    ▼
                                                             E11 风控告警与违约处置 → E12 客户运营与续费

贯穿全链路（横切能力）：
  · 行情数据分发：C撮合 → MySQL → Canal → 缓存服务 → Redis → 三端（大屏/PC/移动）
  · 统一入口：midservice 网关（鉴权/限流/租户路由/灰度）+ midmon 监控
  · 异构翻译：DS 数据中心（Java↔C Hessian/Socket + 9+ 外部接口适配器）
  · 业务可变：规则配置中心（交易/计费/风控/保证金规则可配置）
  · 全程留痕：操作审计 + 归档（四流合一证据链）
```

> 🔴 = 红线环节（挂了不只是"业务受阻"，而是直接资损/违约/监管问题）：**E4 撮合、E7 保证金与履约、E9 仓单交收**。
> 这三个环节的共同点：**它们管理的都是"真金白银与货权"，不是信息和展示。**

## 2. 主表：环节 × 业务语言 × 技术模块 × 业务损失

**读法**：一行 = 一个业务环节；最后一列括号里是代价性质（钱 / 客户 / 合规）与等级（🔴P0 / 🟠P1 / 🟡P2）。

| # | 业务环节 | 业务上在干嘛（业务语言） | 对应技术模块（技术语言） | 一旦出问题：业务损失 |
|---|---------|------------------------|------------------------|---------------------|
| **E1** | 开户与准入 | 企业客户带营业执照、法人身份证来入驻，平台核验资质、开对公账户、给交易权限 | 客户中心（MDM）+ 9+ 外部接口（企查查工商核验 / 银行对公账户 / OCR 卡证识别）+ midservice 网关。机制：三路核验**异步并行** + 结果缓存（痛点 1） | 开户卡住 = 客户签不进第一单而流失；核验放水 = KYC/反洗钱不合规（**客户 🟠 + 合规 🔴**） |
| **E2** | 登录与权限 | 同一家客户公司里，采购能下单但不能看价格底牌，财务能付款但不能下单，老板看全局不能改数 | midservice 网关（统一鉴权）+ RBAC + 业务角色层（token/claim 下发菜单与数据范围）+ Redis（会话/Token）。前端按角色动态加载路由（痛点 3、2） | 越权操作 = 内部风险事件 + 审计不通过；鉴权挂 = 三端全登不进，业务整体停摆（**合规 🔴 + 客户 🔴**） |
| **E3** | 商品建模与挂牌报价 | 卖方把货挂出来（品种/规格/数量/交收地/价格），买方浏览选货；价格跟着期货行情实时在动 | 商品中心（大类→品种→规格/SKU 三层品类编码，痛点 24）+ 挂牌服务 + 行情中心（接 CTRM/交易所行情，痛点 20）+ Redis 实时价缓存 + MinIO（商品图片/资料） | 挂不上 = 当天没生意、无单可成；商品编码不统一 = 交收配货人工核对、错配发错货（**钱 🔴 + 客户 🟠**） |
| **E4** 🔴 | 询价与撮合成交 | 买方摘单/出价，平台在毫秒内判定"谁先谁得、按什么价成交"，稀缺批次几十个买家同时抢 | midservice → 交易服务（规则校验 + 风控/保证金预检 + Redisson 防重提交）→ **DS 数据中心**（Hessian 同步 / Socket 异步）→ **C 撮合引擎**（单线程内存撮合 + CAS + WAL 兜底）→ 异步落库 MySQL。三道超卖防线：C 引擎 CAS / DS 熔断幂等 / Java 层 `resource_id+version` 乐观锁（痛点 4、5） | 超卖 = 卖方拒单、平台信用崩塌；撮合停顿 = 客户报价窗口失效，**真金白银的价格损失**；公平性被质疑 = 平台立身之本动摇（**钱 🔴 + 客户 🔴**） |
| **E5** | 成交落库与订单聚合 | 成交后要能查出"我一共多少单、走到哪一步了"，远期跨月订单还能一屏看全 | DS 消费成交事件 → outbox 本地消息表 → Kafka 事务消息；交易核心（Java）状态机 + 幂等；统一订单中心（事件驱动聚合，**不替代业务系统**，痛点 8） | 订单状态错乱/丢单 = 客户与运营对不上账、重复发货或漏发货；答疑量暴涨（**钱 🟠 + 客户 🟠**） |
| **E6** | 合同生成与电子签署 | 口头谈成后落成有法律效力的电子合同，走法务→风控→总监审批链，双方在线盖章 | 合同中心（模板引擎，成交即生合同，痛点 7）+ Flowable 工作流（多级审批）+ 电子签章 SDK（CA 机构）+ MinIO/ES（合同归档与全文检索） | 签不了 = 前面撮合白干、前功尽弃；条款生成错 = 后续纠纷与赔付；审批断 = 大单停在最后一公里（**钱 🔴 + 客户 🟠 + 合规 🟠**） |
| **E7** 🔴 | 保证金冻结与履约编排 | 签约后要把客户保证金冻住、再串起"签合同→发货→过户→验收→结算→释放保证金"这条跨月长流程 | **Saga 编排器**（Java 层，7+ Steps 编排 + 补偿 + 状态机，不放在 C 层）+ 资金服务 + outbox 事务消息（Kafka）+ 履约状态机（编译期禁止非法跳转）+ 履约工作台时间轴（痛点 9、10） | 钱扣了单没成 / 单成了钱没冻 = **资金安全事件，平台兜底赔付**；长事务断在半路 = 货已发出无法回滚，跨月纠纷（**钱 🔴 + 客户 🟠**） |
| **E8** | 支付结算与对账 | 保证金、进度款、尾款分批付，走银行存管；财务每月对账核销 | 资金服务 + **银行存管接口**（5 家银行统一 `BankGateway` 适配层，痛点 16）+ 对账引擎（T+1 全量自动对账 + 差错工单，痛点 18）+ 幂等唯一键（订单号+操作类型+日期） | 付不了/付错 = 直接资损；资金走平台账户 = **二清违规（央行 217 号文）**；对账差异 = 财务成本与客诉（**钱 🔴 + 合规 🔴**） |
| **E9** 🔴 | 仓储、仓单与物流交收 | 货在哪个仓库、多少吨、归谁；仓单在贸易商之间流转；质押期间不能被偷偷提走；运输轨迹客户要能实时看到 | 仓单服务（唯一码 + 区块链/第三方存证 + 状态机，链上链下双校验，痛点 13）+ 仓储服务（多 WMS 数据归一 + 事件驱动，痛点 14）+ 物流接口（多物流商 API 聚合 + 实时推送 + 延误预警，痛点 15）+ MinIO（质检报告） | 一货多押/假仓单 = **银行被骗贷、平台失信、监管处罚**；提错货/超发 = 直接资损；轨迹黑箱 = 客户流失与纠纷（**合规 🔴 + 钱 🔴 + 客户 🟠**） |
| **E10** | 发票开具与税务合规 | 每笔交易开增值税专票，品名规格金额必须跟合同和实物完全一致，不一致要冲红重开 | 发票服务 + 四流合一数据底座（合同/仓单/付款单/业务数据）+ 进项管理（开票/红冲/抵扣全生命周期，痛点 19）+ 税务系统电子发票接口 | 票货不一致 = 客户进项不能抵扣、**被税务稽查**；开票慢 = 影响客户回款与关系（**合规 🔴 + 客户 🟠**） |
| **E11** | 风控告警与违约处置 | 事前给客户定授信额度与保证金比例，事中盯异常交易，事后对不发货/不付款的自动判违约、自动扣罚保证金 | 风控引擎（Drools/规则引擎**热更新不发版** + 实时引擎毫秒级 + 离线引擎 T+1，痛点 22、12）+ 规则配置中心（痛点 6）+ 风控 ODS 数据底座（从 midservice 与 DS 采集全链路事件）+ 通知中心（三通道） | 风险发现滞后 = 坏账、关联账户对倒/虚假交易发现不了；规则硬编码 = 市场变了改不动（**钱 🔴 + 合规 🟠**） |
| **E12** | 客户运营与续费 | 客户签约后用没用起来、会不会流失；健康度低就安排客户成功介入 | 客户健康度评分模型（登录频率/核心功能使用率/交易完成率/问题响应满意度加权）+ 客户数据批量导入工具 + 报表与埋点（`02-业务全链路场景手册.md` 场景 9） | 沉默客户到期不续 = 收入断档；上线慢 = 交付成本高、口碑差（**客户 🟠**） |

### 横切能力（不属单一环节，但全链路依赖）

| 能力 | 业务上在干嘛 | 技术模块 | 一旦出问题：业务损失 |
|------|-------------|---------|---------------------|
| **行情分发** | 大屏、PC、手机看到的必须是**同一份最新价格**，不能一个涨一个没刷 | C 撮合 → MySQL → **Canal** → 缓存服务 → **Redis** → 三端（大屏 WebSocket 全量 / PC SSE 增量 / 移动轮询，痛点 21） | 三端不同步 = 交易决策错位、客户投诉；Canal/缓存链路挂 = 页面价格与成交价长期不一致的**永久脏数据**（**客户 🔴**） |
| **统一入口** | 三端所有请求的鉴权、限流、租户路由、灰度都在一个口子上 | midservice 网关（多实例 midservice1/2/3 + DNS 轮询 + 下游降级）+ midmon 监控（一秒内告警定位实例） | 网关挂 = 全平台三端不可用，业务整体停摆（**客户 🔴 + 钱 🔴**） |
| **异构翻译** | Java 业务中台与 C 撮合引擎、9+ 外部接口之间的"翻译官" | DS 数据中心（Hessian over HTTP 同步 / Socket 异步；适配器模式隔离每家银行/物流/CA） | DS 挂 = 两边都受影响、交易链路断；新增外部接口不能快速接入（**钱 🔴**） |
| **规则可变** | 保证金比例、计价方式、审批链按客户/品类/模式随时调 | 规则配置中心（Drools/自研 DSL + Nacos 动态下发） | 改规则要发版 = 市场变化时反应不过来、错过行情窗口（**钱 🟠**） |
| **全程留痕** | 监管要"四流合一 + 可追溯"，每个关键操作有时间戳/操作人/业务单号 | 统一订单中心 + 操作审计 + 归档到只读存储（痛点 23） | 审计时拼不出数据 = 监管检查耗时、合规问题暴露（**合规 🔴**） |

## 3. 故障代价三维分级

把上表的代价按**性质**归堆，回答"到底丢的是钱、客户还是合规"。

### 3.1 钱（直接资金损失 / 赔付 / 坏账）

| 环节 | 损失形态 | 等级 |
|------|---------|:---:|
| E4 撮合 | 超卖→卖方拒单赔付；撮合停顿→价格窗口失效 | 🔴 |
| E7 保证金/履约 | 钱扣了单没成、单成了钱没冻→平台兜底 | 🔴 |
| E8 支付结算 | 付错付重、资损 | 🔴 |
| E9 仓单交收 | 超发/提错货、一货多押骗贷 | 🔴 |
| E11 风控 | 坏账、虚假交易 | 🔴 |
| E3 挂牌 / E5 订单 | 无单可成、错配发错货 | 🟠 |

### 3.2 客户（流失 / 信任崩塌 / 体验）

| 环节 | 损失形态 | 等级 |
|------|---------|:---:|
| E2 登录 / 横切-网关 | 全端不可用，业务整体停摆 | 🔴 |
| E4 撮合 | 公平性被质疑 = 平台立身之本动摇 | 🔴 |
| 横切-行情分发 | 三端价格不一致、决策错位 | 🔴 |
| E1 开户 / E6 合同 / E9 交收 | 第一单流失、大单卡在最后一公里、纠纷 | 🟠 |
| E10 发票 / E12 运营 | 影响回款关系、沉默客户不续费 | 🟠 |

### 3.3 合规（监管处罚 / 审计 / 税务 / 二清 / KYC）

| 环节 | 损失形态 | 等级 |
|------|---------|:---:|
| E1 准入 | KYC / 反洗钱不合规 | 🔴 |
| E2 权限 | 越权、审计不通过 | 🔴 |
| E8 支付 | **二清违规（央行 217 号文）** | 🔴 |
| E9 仓单 | 假仓单骗贷、平台失信被处罚 | 🔴 |
| E10 发票 | 票货不一、被税务稽查 | 🔴 |
| 横切-留痕 | 监管要数据拼不出 | 🔴 |

> **🔴 出现频次最高的三个环节：E4 撮合、E8 资金、E9 货权。**
> 一句话记住：**钱、货、权——这三样东西的技术模块如果挂了或算错了，代价是"不可挽回"的；其他环节挂了，大多还能人工补。**

## 4. 反向倒查表：模块 → 支撑环节 → 挂了影响谁

排障时从"哪个模块报警"反推"业务损失是什么"，决定处置优先级。

| 技术模块 | 支撑哪些环节 | 挂了直接影响 | 处置优先级 |
|---------|-------------|-------------|:---:|
| **C 撮合引擎** | E4 | 撮合停顿、超卖风险 | 🔴 P0 |
| **DS 数据中心** | E4/E5/E7 + 全部外部接口 | 交易链路断、外部能力全失效 | 🔴 P0 |
| **midservice 网关** | 全环节入口 + E2 | 三端全不可用 | 🔴 P0 |
| **资金服务 + 银行存管** | E7/E8 | 资损、二清合规风险 | 🔴 P0 |
| **仓单服务 + 存证** | E9/E10 | 货权纠纷、骗贷、合规 | 🔴 P0 |
| **Saga 编排器**（关键单点） | E7 | 长事务卡死、补偿需人工介入 | 🟠 P1 |
| **Kafka / outbox** | E5/E7/E8 | 最终一致断链、资金状态不一致 | 🟠 P1 |
| **Canal + 缓存服务 + Redis** | 横切行情 + E2 会话 | 页面数据脏、登录态失效 | 🟠 P1 |
| **合同中心 + 电子签章** | E6 | 大单签署中断 | 🟠 P1 |
| **规则配置中心** | E3/E6/E11 | 规则变更无法生效 | 🟡 P2 |
| **商品中心** | E3/E9/E10 | 编码错配、交收对不上 | 🟡 P2 |
| **发票服务 / 税务接口** | E10 | 开票延迟、抵扣受影响 | 🟡 P2 |
| **订单中心 / 履约工作台** | E5/E7/E11 | 查询聚合失效（不阻断交易） | 🟡 P2 |
| **前端构建体系 / 首页接口** | 全环节入口 | 首屏慢、下单时机受影响 | 🟡 P2 |
| **midmon 监控** | 全环节 | 故障发现变慢，MTTR 上升 | 🟡 P2 |

> **注意"不阻断交易"的模块**：订单中心被刻意设计为"只做聚合、不替代业务系统"（痛点 8），所以它挂了是查询体验问题，不是资金问题——**这是设计上的爆炸半径控制，讲架构决策时可以直接用。**

## 5. 三个红线环节的深挖（各一句话说清"为什么不能挂"）

### E4 撮合——不能有 GC 停顿

- **业务上**：几十个买家同时抢一批货，谁先谁得、按什么价成交，必须在毫秒级判定。
- **技术上**：C 单线程内存撮合 + CAS 替代锁 + WAL 兜底；撮合主路径**不引入 Java 服务**（避免 GC/STW 毛刺）。
- **掉了什么**：手工交易还是"报价 100 万/吨、500ms 后成交时市价已变"，撮合停顿直接变成客户的亏损和平台公平性危机。
- 对应的权威痛点：**痛点 4（超卖）、痛点 5（撮合时延）**。

### E7/E8 资金——不能出现"钱和状态不一致"

- **业务上**：保证金先冻住，跨月长流程里"签合同→发货→过户→结算→释放保证金"逐步推进。
- **技术上**：outbox 本地消息表（业务操作与消息同一本地事务）+ Kafka + 幂等 key 去重 + 定时扫表兜底 + 状态机禁止非法跳转；长事务由 Java 层 Saga 编排（**不放 C 层**）。
- **掉了什么**：钱扣了单没成、单成了钱没冻——这是"平台兜底赔付"级别的事故；资金过平台账户还会撞上二清红线。
- 对应的权威痛点：**痛点 9（保证金不一致）、痛点 16（资金不过夜/二清）、痛点 18（对账）**。

### E9 货权——不能让"一张仓单抵押两次"

- **业务上**：货在仓库里不动，但仓单可以在贸易商之间流转，还能拿去质押融资。
- **技术上**：仓单唯一码 + 区块链/第三方存证 + 链上链下双校验 + 状态机（未质押/已质押/已解押/已转让）。
- **掉了什么**：假仓单/一货多押 → 银行被骗贷、平台失信、监管处罚；这类损失是**不可逆的信用损失**。
- 对应的权威痛点：**痛点 13（仓单造假）、痛点 14（多仓库存）、痛点 17（应收账款融资确权）**。

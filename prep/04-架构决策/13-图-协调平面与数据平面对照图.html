外部协调（ZK 式） 内嵌共识（KRaft 式）

对 C 核心的推论

倾向 外部协调——C 核心命门是"撮合线程内绝不阻塞"（§3），别把共识代码塞进撮合进程；但"外部"可复用已有 etcd / DB 租约表，不必自造 ZK。协调是独立角色，但不是非得是独立系统。

五

类比断点 · 别讲过头

两处必须说清楚，否则会误导

并行度不同

分区并行 vs 全局串行
Kafka：分区并行（每 partition 各有 leader，靠分区数换吞吐）
C 核心：全局串行（单线程 + 单主）
→ C 核心 ≈ 只有一个 partition 的 Kafka

一致性语义不同

拼出来的 vs 直接的
Kafka：at-least-once + 幂等生产者拼出 exactly-once
C 核心：确定性重放直接得到，语义更强

一句话

该学的到底是哪一层
ZK / Kafka = 两套系统分饰两角
KRaft = 一套系统分饰两角
C 核心要学的是——先把两角分清楚，至于合不合体，看谁的纯度更不能脏

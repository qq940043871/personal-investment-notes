## 第一章 项目理解与总体需求分析

### 1.1 项目背景
在国资委推动国有企业数字化转型、加快建设世界一流企业的战略背景下，大宗商品的交易模式正从线下分散、信息不透明，向线上化、平台化、生态化加速演进。招标方作为行业重要的国资平台主体，建设一套集交易撮合、供应链协同、风控结算、数据服务、生态对接于一体的大宗商品交易供应链平台，既是落实数字中国战略的具体举措，也是提升要素资源配置效率、强化国有资产监管能力的必然要求。

### 1.2 对招标需求的理解
结合招标文件的建设目标，我司认为本项目的核心诉求可概括为"三化、两控、一贯通"：
- 交易线上化：将挂牌、竞价、撮合等交易模式迁移至线上，提升成交效率与透明度；
- 履约协同化：合同、物流、仓储、结算一体化闭环，打通交易与履约的"最后一公里"；
- 数据资产化：沉淀交易与行情数据，形成可分析、可监管的数据资产；
- 风险可控：对交易对手、资金、履约全过程进行风险监控与预警；
- 资金可控：规范保证金、清算、对账流程，确保资金安全；
- 生态贯通：与银行、税务、物流、监管系统安全对接，形成产业互联网生态。

### 1.3 建设目标与原则
- 建设目标：建成"合规、安全、高效、可扩展"的大宗商品交易基础设施，支撑多品种、多模式、多角色的业务开展。
- 建设原则：统一规划、标准先行；自主可控、安全合规；业务驱动、循序渐进；开放集成、生态共赢。

## 第二章 总体建设方案

### 2.1 总体设计思路
遵循"一个平台、N 个业务中心"的设计理念，以微服务架构解耦业务能力，以统一技术中台支撑共性能力，以数据底座贯通全域数据，最终形成"交易—履约—风控—数据—生态"五位一体的数字平台。

### 2.2 总体架构（五视图）
- 业务架构：面向交易商、平台运营方、监管方三类角色，覆盖交易、履约、监管全链路；
- 应用架构：门户层、业务中心层、能力中台层、数据层、基础设施层；
- 技术架构：前端微前端 + 后端微服务 + 云原生基础设施；
- 数据架构：主数据+交易数据+行情数据，经数据湖仓形成指标体系；
- 部署架构：支持私有化/专有云集中部署，兼容信创环境。

### 2.3 业务架构
平台业务划分为五大中心：交易撮合中心、供应链协同中心、风控结算中心、数据服务中心、生态对接中心，各中心通过统一门户与工作台对外服务。

### 2.4 数据架构
建立统一主数据管理（MDM），规范交易商、商品、合约、仓单等核心主数据；交易流水、行情 tick、履约单据等进入数据中台，构建经营分析、监管报送、风险预警三类数据应用。

### 2.5 部署架构
采用容器化部署，生产环境建议为"2 中心（双活）+ 1 灾备"结构；支持在国产化软硬件底座上整体平移，满足信创要求。

## 第三章 平台功能建设方案

### 3.1 交易撮合中心
#### 3.1.1 挂牌交易
支持协商挂牌、挂摘牌、要约应约等模式；提供挂牌审核、价格区间、数量拆分、自动摘牌等配置。

#### 3.1.2 竞价交易
支持竞买/竞卖方向、公开/密封方式、阶梯报价与限时竞价。以"竞价交易室"为载体，提供实时报价面板、价格走势、倒计时、自动延时（熔断）、成交结果公示等交互能力，保障竞价过程公开、公平、可追溯。

#### 3.1.3 撮合引擎
基于内存撮合与异步落库，支持多品种并行撮合、价格优先/时间优先撮合规则、涨跌幅限制、异常熔断与人工干预，保障高并发下的撮合正确性与低时延。

### 3.2 供应链协同中心
实现合同电子化签署、物流轨迹跟踪、仓储交收管理、结算对账一体化：交易达成自动生成合同草案，关联仓单与物流单，驱动结算指令，形成履约闭环。

### 3.3 风控结算中心
- 准入管理：交易商资质审核、黑白名单、信用额度；
- 履约保证：保证金冻结/释放、履约担保；
- 资金清算：T+N 清算、多方分账、自动对账；
- 风险监控：价格异动、异常交易、集中度预警，支持阈值配置与多级告警。

### 3.4 数据服务中心
提供行情发布、价格指数编制、领导驾驶舱与大屏可视化。大屏支持交易概览、品种分布、实时成交、风险态势等多维度动态展示。

### 3.5 生态对接中心
通过统一开放平台对接银行（资金存管/清算）、税务（发票）、物流（运踪）、监管（报送）系统，采用 OAuth2.0 + 报文加密 + 签名验签保障对接安全。

### 3.6 门户与统一工作台
- 会员门户：开户、交易、履约、对账一站式服务；
- 管理后台：运营、风控、结算、系统管理；
- 移动端：uni-app 发布 H5/小程序/App，支持行情查看与业务审批。

### 3.7 系统管理与权限体系
提供组织、角色、用户、菜单、审批流管理，全量操作审计日志，满足分级授权与责任可追溯。

## 第四章 技术路线与关键技术

### 4.1 技术选型总览
- 前端：Vue 3 + TypeScript + Vite + Element Plus；微前端 qiankun；可视化 ECharts + DataV；移动端 uni-app；
- 后端：Java 17 + Spring Boot 3 + Spring Cloud Alibaba（Nacos/Sentinel/Gateway/Seata）；
- 撮合：Netty 长连接 + 内存撮合 + 异步落库；
- 存储：MySQL 8（信创替代达梦/金仓）、Redis Cluster、Elasticsearch、MongoDB、TDengine、StarRocks；
- 中间件：RocketMQ + Kafka；
- DevOps：Docker + Kubernetes + GitLab CI + Prometheus/SkyWalking/ELK。

详见大纲第四章 4.1.1–4.1.6，含信创国产化适配矩阵。

### 4.2 高并发交易关键技术
采用"长连接推送 + 内存撮合 + 消息削峰 + 分布式锁"的组合方案：Netty 维持万级并发连接，撮合核心在内存完成并异步批量落库，报价洪峰通过 RocketMQ 削峰，Redisson 分布式锁保障关键资源一致性，确保撮合时延毫秒级、撮合正确率 100%。

### 4.3 信创国产化适配
对 CPU（鲲鹏/飞腾/海光）、操作系统（麒麟/统信 UOS）、数据库（达梦/金仓）、中间件（东方通/宝兰德）提供多架构镜像与配置级切换，前端完成主流国密浏览器兼容测试。

### 4.4 性能指标承诺
| 指标 | 承诺值 |
|------|--------|
| 并发在线用户 | ≥ 10,000 |
| 撮合时延 | ≤ 50 ms |
| 关键交易响应时间 | ≤ 1 s |
| 系统可用性 | 99.9% |
| 数据备份 RPO | ≤ 5 min |

### 4.5 与现有系统对接
通过标准 API 网关与集团统一认证（如 CAS/OAuth）、ERP、OA 等系统对接，提供字段映射与报文转换，保障数据一致。

## 第五章 安全与合规体系

### 5.1 等级保护三级
依据 GB/T 22239-2019 第三级要求，从物理、网络、主机、应用、数据五层建设安全防护，配合测评机构完成定级备案与整改。

### 5.2 数据安全合规
落实《数据安全法》《个人信息保护法》，对数据分类分级，敏感字段加密存储与动态脱敏，建立数据全生命周期管理。

### 5.3 应用与账户安全
统一身份认证、多因子登录、CA 电子签章与防抵赖；关键操作二次确认与全程审计。

### 5.4 密码应用（国密）
采用 SM2/SM3/SM4 国密算法实现签名、摘要、传输加密，满足商用密码应用安全性评估要求。

### 5.5 容灾备份
提供本地双活 + 异地灾备，明确 RTO ≤ 2 h、RPO ≤ 5 min 的容灾指标与演练机制。

# 07 · 规范传达与团队赋能（缓存规范如何进团队）

> **定位**：本文件答一类特定的管理追问——「你向团队成员传达最佳实践 / 安全措施时怎么做」。它不是缓存技术文档，缓存（以及资金锁、幂等）在这里只是**载体**，考的是「规范怎么从一个人脑子长成团队能力」。与 `06-技术管理常遇问题与应答.md` 互补：06 答「怎么审代码」，本件答「怎么让不审也会做对」。
> **原题**：团队管理方面，是如何向团队成员传达缓存相关的最佳实践和安全措施的？
> **收录**：2026-11-26，两轮口述合并沉淀。

> **证据等级（先分清再说）**
> - 【实证·现状】三层机制中的规范层与工具层：缓存红线、收益公式 + 五判据、声明式配置（加缓存 = 加一条配置）、Sonar 静态扫描 + 自研 jar 包检测四项（事务 / Redis 锁 / 日志 / 幂等）、六道评审闸门、资金改动双人审、技术常见坑表、早会制度、周技术分享轮流主讲。
> - 【规划·在推】CI 门禁 / CD 自动检测 / 制品库全链路（P0 阻断 / P1 记录限期整改，试运行先告警校准误报率再转强制）——**不是已在跑**，见 `06` 号护栏 3。
> - 【目标线·非达成值】节省工作量 ≥5 人月、团队整体自动化测试覆盖率 ≥20%、核心模块单测 CI 门禁起始线 ≥30%（20% 是「面」、30% 是「点」，两个数都要报但别混）。
> - 【通用方案·无实战】专项反爬、布隆过滤器（本平台 ID 空间有限未落地）——只作对照，不讲成战绩。

## 0. 一句话口径（先背这句）

> 我不靠发文档开个会传达——那种方式三周后没人记得。做法是三层：**规范文档写清「应该怎样」，工具门禁强制「必须怎样」，人工评审判断「是否合理」**，再让事故复盘不断往里补规范。日常靠三样东西让它活起来：**早会只过阻塞点、周分享只讲真问题、技术常见坑表把教训变成可勾选的清单**。核心一句：**规范不能被工具强制就只是文档，工具没人审设计就只能挡低级问题，三层缺一层就退化成形式主义。**

## 1. 三层落地机制（骨架，别答成三板斧）

> 高分答案的关键是「传达靠机制，不靠宣讲」。下面每层的权威源都是 `02A` 第二部分 §十 与 `06` 号问题 2。

| 层 | 作用 | 缓存载体（讲「我们」时挂这儿） | 证据 |
|---|---|---|---|
| ① 规范文档层 | 定义「应该怎样」 | 缓存红线（QPS>100 必须缓存 / 命中率 ≥90% / TTL ±10% 抖动 / 写协议绝不缓存）+《读接口缓存判断方法》收益公式与五判据 | 【实证】 |
| ② 工具门禁层 | 强制「必须怎样」 | 声明式缓存配置（加缓存 = 加一条 `{API_ID, CACHE_KEY, CACHE_TYPE, CACHE_EXPIRE}`，零代码）；Sonar + 自研 jar 包检测扫事务 / Redis 锁 / 日志 / 幂等；命中率进看板 | 【实证】；CI 门禁【规划·在推】 |

## 2. 缓存规范的三层落地（这题的「具体答案」）

**① 规范层——写可判定的红线，不写「注意缓存安全」这种正确的废话。**
- 红线：读接口 QPS > 100 必须有缓存层、命中率 ≥90%、TTL ±10% 随机抖动防雪崩、**写协议（撮合 / 下单 / 资金）绝不缓存**。
- 载体：《读接口缓存判断方法》——收益公式 `QPS × 命中率 × (后端RT − 缓存RT)` + 五个判据（读写 / QPS / 命中率 / 穿透成本 / 一致性），把「该不该加缓存」从个人经验变成人人能套的判断表。
- 一致性口径：本地缓存 30s 是**有界陈旧**，用短 TTL 换逃生能力；写后读强制走主库；资金类不以缓存为准。

**② 工具层——把能检查的全部下沉，让人为漏掉的空间变小。**
- 缓存是**声明式配置**：加缓存就是在配置源加一条配置、零代码（不是往代码里手写 get/set）——这是「规范下沉到工具」最直接的证据。
- **Sonar 静态扫描 + 自研 jar 包检测已实现**：四项扫描判定——事务（该原子的同事务、跨服务不在事务内）、**Redis 锁（资金操作必须加，很少用数据库锁）**、日志（级别合理、含业务标识、无敏感信息）、幂等（重试不重复扣款发货）。
- 处置：P0 阻断合并、P1 进台账限期整改；试运行阶段先只告警校准误报率，再转强制。
- ⚠️ **CI 门禁是规划 + 在推，不是已在跑**——这一条说错就是过度声明。

**③ 人工层——工具判不了「该不该缓存、TTL 多少、会不会破坏一致性」。**
- 六道闸门：需求收口 → 设计 → 技术 → QA 验收 → 发布 → 移交，**不通过不流转**。
- Code Review：普通改动模块 owner 主审，**涉及资金双人审**；按坑表逐项排查留痕；评论分 `[blocking] / [suggest] / [question] / [nit]`，`[nit]` 不得阻塞合并。

**闭环：事故复盘 → 转规范。** 扩容横扩 5 实例打穿 DB 那次，产出不是事故报告，而是**缓存红线 + 容量申报 + 扩容前核出口容量的 SOP**——「读接口 QPS>100 必须缓存」就是这么来的。**复盘的产出永远是防再发**，规范因此持续自我进化。

## 3. 日常三节奏（用户口述补充，填进「带人层」）

> 口述原词有两处口误，已纠正：**「技术鲳鱼问题列表」= 技术常见坑列表（技术常见坑表）**；**「密封考虑」= 幂等考虑**。面试讲错术语会被当场打断。

| 节奏 | 做法 | 为什么是传达 | 证据 |
|---|---|---|---|
| **早会**（每日站会） | **只过阻塞点，不汇报进度** | 缓存落地卡住的问题当天暴露当天定——「这个读接口 QPS 上来了要不要加缓存」「加缓存后一致性怎么保证」，不拖到上线前爆雷 | 【实证】早会制度 |
| **周会 / 周技术分享** | **只讲真问题，不讲概念**；轮流主讲 | 缓存三难（穿透 / 击穿 / 雪崩）、扩容打穿 DB 让人**自己讲一遍**——讲得出来才是真懂；**分享不是目的，沉淀才是**，讲完进团队知识库 | 【实证】 |
| **技术常见坑表** | 通用 / Java 后端 / 数据库 / 前端 / 测试五组可勾选清单 | 新人不用靠师傅口传，对照自查就知道入参校验齐没齐、**缓存更新顺序**对不对、事务边界对不对；并与自研扫描四项打通 | 【实证】`02A` §9.6 |

**注意坑表与扫描项的关系**：口述列的「事务注解、加锁、日志完善、幂等考虑」**正好就是自研 jar 包检测的四项扫描**（事务 / Redis 锁 / 日志 / 幂等），不是泛泛的「问题列表」。把这层对应关系讲出来，是本件最硬的实证——**规范下沉到工具，工具判不了的才交给人**。

**带人配套**：师徒制（新人配导师，3 个月独立接模块）+ 主链路强制代码评审 + 周技术分享 + 调研沉淀进知识库。目标线（非达成值）：节省 ≥5 人月、团队整体自动化覆盖率 ≥20%。

## 4. 项目版 90 秒速答（可直接背）

> 我不靠发文档开会传达，靠三层机制。第一层**规范文档**：把缓存写成可判定红线——QPS>100 必须缓存、命中率 ≥90%、TTL ±10% 抖动、写协议绝不缓存——配一份《读接口缓存判断方法》的收益公式加五判据，人人能套。第二层**工具门禁**：缓存是声明式配置，加缓存就是加一条配置、零代码；Sonar 加自研 jar 包检测已经落地，扫事务、Redis 锁、日志、幂等四项，命中率进看板；CI 门禁还在规划推进中。第三层**人工评审**：六道闸门不通过不流转，Code Review 分层、资金双人审、按坑表排查。
>
> 日常节奏靠三样东西让规范活起来：**早会**只过阻塞点，缓存落地卡住当天暴露当天定；**周技术分享**只讲真问题不讲概念，缓存三难让人自己讲一遍、讲完沉淀进知识库；**技术常见坑表**把教训变成可勾选清单，新人对照自查，并与那四项自动扫描打通——规范下沉到工具，工具判不了的才交给人。补一句核心：**规范不能被工具强制就只是文档，工具没人审设计就只能挡低级问题，三层缺一层就退化成形式主义。**

## 5. 口径护栏（本题专属，四条红线）

1. ✅ **讲「加锁」守住资金口径**：**所有资金业务操作都用 Redis 锁，很少用数据库锁**（本人 2026-11-26 确认）。旧稿「资金用 DB 行锁、不用 Redis 锁」已废止。⚠️ 「批次号认领不用分布式锁」是派发器扫表的**原子认领机制**，与资金并发控制是两码事，别混。
2. ✅ **工具状态分开讲**：**Sonar 静态扫描 + 自研 jar 包检测 = 已实现**；**持续集成（CI）= 正在规划**。CI 门禁 / Code Review 全链路按「规划 + 在推」讲，不包装成已在跑。
3. ✅ **指标带限定语**：节省 ≥5 人月、覆盖率 20% / 30%、故障次数线、并发 ≥1000/秒都是**当时设定的目标 / 考核线**，不是长期达成值；`99.95%`、`3 年零资金差错`、`2 个月 → 1 周` 属运行结果可直说。⚠️ 两个「15%」别串：团队被动响应占比 45% → 15%（导览 / 简历），个人救火时间占比 70% → 15%（`02B` 六阶段推演），被问先说清主体。
4. ✅ **技术栈不混**：平台 = Java 微服务业务中台 + C 单线程内存撮合引擎 + 自研 DS 桥接（Hessian + Socket）+ Vue3；**FastAPI / Python 仅个人 Agent Harness 储备，绝不混进平台栈**。

## 5.5 掌握程度检查（追问原题：怎么确认团队真的掌握，有什么检查手段）

> **原题**：如何检查团队是否真正掌握这些最佳实践，有没有具体的检查手段？
> **口述答案**：通过 Code Review + 检测前的 Sonar 扫描 + 自研扫描 jar。
> **先纠正一个认知陷阱**：这三样查的都是**代码是否合规**，而面试官问的是**人是否真正掌握**——照着清单写出合规代码、但完全不懂为什么，工具照样放行。所以必须把「检查掌握」拆成三层：**工具查代码合规 → 评审查设计理解 → 复述查认知内化**。只答工具层，会被追一句「怎么确认他是真懂，不是照猫画虎？」

| 层 | 查什么 | 具体手段 | 证据 |
|---|---|---|---|
| ① 代码合规 | 做没做对 | **Sonar 静态扫描**（通用：空指针 / 资源泄漏 / SQL 拼接 / 圈复杂度 / 硬编码密钥）+ **自研 jar 包检测**（事务 / Redis 锁 / 日志 / 幂等四项）；P0 阻断合并、P1 记录限期整改，试运行先只告警校准误报率再转强制 | 【实证】已实现；CI 门禁【规划·在推】 |
| ② 设计理解 | 为什么这样做 | **Code Review 分层**：作者对照检查清单自查 + 结构化描述（改了什么 / 为什么改 / 影响范围 / 如何验证，缺项直接退回）；模块 owner 主审、资金双人审、技术经理看设计与兼容性；评审人从「能不能讲清为什么」反推掌握程度 | 【实证】 |
| ③ 认知内化 | 是不是真懂 | **复述检验**（`02B` 成长手册的检验问题）：不查资料能讲清一笔交易从挂牌到结算的完整链路吗？被追问三个「为什么」能接住吗？能说出使用场景 + 2 个常见坑 + 监控指标 + 什么情况下会挂吗？载体 = 周分享轮流主讲、师徒制 3 个月独立接模块的验收、场景化答辩 | 【实证】 |

**关键收口**：三层查的都是「规范」，但**只有第三层能回答「是否真正掌握」**。工具挡住低级错误、评审判断设计合理性、复述确认认知内化——**缺一层，要么规范停在文档，要么只能查出「做没做对」查不出「懂不懂」**。

**缓存场景的复述检验示例**（现场能举出来才像真做过）：随便拉一个开发，问「这个读接口为什么加缓存 / TTL 定多少 / 缓存和 DB 不一致怎么办 / 空值缓存的 TTL 为什么必须短」——答得上来 = 真懂；只会说「配置里写了」= 照猫画虎，回炉。

## 6. 追问预案

| 追问 | 应答骨架 |
|---|---|
| 规范落地了怎么验证？ | 关键节点强制过审 + 表单留痕（评审表 / 发布记录 / 移交记录），不通过不流转；缓存有命中率看板可观测 |
| 规范会不会拖慢交付？ | 规范目标是**减少返工**：需求不清 / 设计不足 / 测试遗漏三类返工才是最大成本；配置化把「写代码」变成「做配置」反而提速 |
| 早会和周会重复吗？ | 早会只过阻塞点（当天清障），周分享只讲真问题并沉淀（把个案变团队能力），一个管执行节奏、一个管能力沉淀 |
| 分享怎么保证不是念 PPT？ | 只讲真问题不讲概念；轮流主讲、讲完沉淀进知识库；讲不出来说明没真懂 |
| 「技术常见坑表」长啥样？ | `02A` §9.6：通用 / Java 后端 / 数据库 / 前端 / 测试五组可勾选清单；Java 后端组含入参校验、事务边界、并发安全（缓存更新顺序）、幂等、索引、分页与接口兼容 |
| 扫描工具扫出的问题怎么闭环？ | P0 阻断合并、P1 进台账限期整改；试运行先只告警校准误报率再转强制（`02A` §5.1 / §8 W7–W8） |
| 双人审资金代码会不会走过场？ | 资金改动双人审 + 坑表逐项排查留痕 + 事务 / 幂等 / 本地消息表三项必查，缺一项不放行 |
| 带人拿过什么结果？ | 结对 + 周分享 + 调研沉淀；目标线：节省 ≥5 人月、团队整体覆盖率 ≥20%（核心模块单测 CI 门禁 ≥30%），专利软著按实际项数 |
| 缓存安全规范怎么来的？ | 主要来自事故复盘——扩容打穿 DB → 缓存红线 + 容量申报 + 扩容 SOP；不是拍脑袋定的 |
| 怎么确认团队真的掌握，不只是照做？ | 三层查：① 工具（Sonar + 自研 jar 包）查代码合规；② Code Review 查设计理解（结构化描述 + 评审反推）；③ **复述检验查认知内化**——不查资料讲清链路 / 追问三个为什么 / 说出 2 个坑 + 监控指标 + 什么情况下会挂。只有第三层答「是否真正掌握」 |
| 扫描 green 就说明掌握了吗？ | 不。扫描只查「做没做对」，查不出「懂不懂」——照清单写合规代码也会 green；所以要叠加复述检验，讲不出来 = 照猫画虎 |
| 复述检验具体怎么落地？ | 周分享轮流主讲（只讲真问题）、师徒制 3 个月独立接模块的验收、场景化答辩；缓存场景就问「为什么加缓存 / TTL 多少 / 不一致怎么办 / 空值 TTL 为什么短」 |
| 评审能反推掌握程度吗？ | 能——结构化描述（改了什么/为什么/影响/怎么验）缺项直接退回；评审人看设计与兼容性，答不出「为什么」的评审现场就暴露了 |

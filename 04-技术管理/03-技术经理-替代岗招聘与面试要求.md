# 技术经理（Java 架构负责人）替代岗 · 招聘要求与面试评估手册

> **定位**：用于 1:1 替换现有岗位（B2B 大宗商品交易平台 · Java 侧负责人）的招聘执行件。三部分可直接拆用——**§1–2 发 JD**、**§3–4 筛简历与排面试**、**§5–8 现场打分与决策**。
> **依据**：`../01-个人简历/00-完整简历-精修版.md`（职责与量化口径）、`../00-面试计划/02-项目叙事-B2B.md`（技术骨架）、`04-技术管理/00-技术管理索引.md`（管理机制口径）。
> **纪律**：对外 JD 与对内评估表分开使用；JD 中不出现客户名、内部系统名与具体金额；所有"年限/人数"按真实编制校准后再发布。

## 一、岗位说明书（可直接发布）

### 1.1 基本信息

| 项 | 内容 |
|---|---|
| 岗位名称 | 技术经理 / Java 架构负责人（业务中台方向） |
| 汇报对象 | 副总（或技术总监） |
| 带团队 | 20 人左右：3 C 撮合内核 / 6 Java 业务中台 / 5 前端 / 5 测试 |
| 工作地点 | 郑州（需接受客户现场短期出差） |
| 薪资区间 | 待定（按公司职级带宽，建议不低于现岗同级的 0.9 倍，否则招不到同能力人） |
| 招聘紧迫度 | 建议留足 2 个月交接期；到位前由现岗兼任架构决策，避免决策真空 |

### 1.2 岗位职责（按重要性排序）

1. **业务中台架构负责**：负责 12+ 微服务的边界划分、领域建模与技术决策，对交易、履约、结算、规则配置、生态对接五条主链路的架构一致性负责。
2. **异构系统治理**：在 C 内存撮合引擎与 Java 微服务之间定义并守住边界（协议契约、防腐层、灰度与回滚），保证两侧团队独立演进、互不阻塞。
3. **资金链路正确性**：对跨月长事务（Saga / 状态机 / 事件溯源）、幂等、对账兜底的技术方案拍板，对"不丢、不重、可回溯"负责。
4. **多租户交付**：把客户差异化需求收敛到配置与规则（能力集 / 套餐 / 授权码 / 规则引擎），控制主链路定制分支，对新客户上线周期负责。
5. **外部集成治理**：统一银行、物流、税务、电子签章等外部系统的接入标准（鉴权 → 请求 → 重试 → 熔断 → 结果转换），对接口可用率与对接工期负责。
6. **稳定性与容量**：主导大促/冬储高峰的容量规划、压测、限流削峰与 On-call 机制，对 P0 事故数与核心接口时延负责。
7. **研发管理**：落地评审闸门、技术债台账、接口契约规范、绩效与梯队机制；带出至少 2 名能独立负责模块的骨干。
8. **跨部门协作**：与产品、业务、测试、运维及外部机构对齐目标与排期，在"业务要快"与"架构不允许"之间给出可执行的替代路径。

### 1.3 硬性要求（不满足不建议进入技术面）

- **年限**：8 年以上 Java 后端，其中 3 年以上技术管理（直接带 10 人以上团队，含跨技能栈）。
- **系统复杂度**：主导过 10+ 微服务、或单日 10 万+ 笔交易量级的 B 端系统架构；有资金/交易/清算/供应链任一强一致场景经验。
- **一致性功底**：能独立讲清 Saga、本地消息表、幂等、对账四件套的适用边界与代价，而不只是名词。
- **数据层**：MySQL 分库分表（含扩容与跨分片查询取舍）、Redis 缓存与锁、Kafka 生产消费与削峰，均有生产落地经验。
- **异构集成**：有跨语言/跨协议系统对接经验（RPC、Socket、二进制协议任一），理解防腐层与契约版本管理。
- **稳定性**：做过容量规划与全链路压测，主导过线上故障定位与复盘闭环（能讲出命令级排查顺序）。
- **管理证据**：能说出自己设计的至少 2 项机制（评审、值班、技术债、绩效），并给出机制前后的可对比数据。

### 1.4 加分项（有则优先，无则不否决）

- 大宗商品、现货/期货、供应链金融、支付清算行业背景。
- 多租户 SaaS 或"一套产品交付 N 个客户"的配置化改造经验（规则引擎、授权码、国际化词库）。
- 等保三级、信创适配、数据脱敏等合规改造经验。
- AI 应用落地经验（Dify / RAG / 文档解析 / 向量库），能判断"哪里该用 AI、哪里不该"。
- PMP 或同等项目管理认证。

### 1.5 明确不要求（避免误筛）

- **不要求会写 C**。原岗同样不写 C，要求的是能把 C 当黑盒管住边界；面试只考"你怎么和 C 团队定契约"，不考 C 语法。
- 不要求前端开发能力，但要求能判断前后端接口契约与联调效率问题。
- 不要求算法竞赛级编码，现场编码环节只考"能否把一段并发/事务代码写正确"。

## 二、能力模型与权重

| 维度 | 权重 | 判什么 | 对应面试环节 |
|---|:--:|---|---|
| A. 架构与异构治理 | 30% | 边界划分、取舍论证、契约与防腐层 | 技术面一（90 min） |
| B. 资金与数据一致性 | 20% | 强/最终一致的选型与兜底 | 技术面一 |
| C. 稳定性与排障 | 15% | 容量、压测、限流、故障定位 | 技术面一 |

| E. 业务与客户价值 | 10% | 能否把技术改进换算成钱/工期/风险 | 管理面 + 终面 |

**通过线**：加权 ≥ 3.5 / 5，且 **A、D 均 ≥ 3**。A 或 D 任一项低于 3，直接否决——这两项是这个岗位不可培养的部分。

## 三、简历筛选（15 分钟判断）

### 3.1 三条硬筛（任一不满足即淘汰）

1. 管理幅度：写"带团队"但说不出人数与构成，或实际只带 3–5 人 → 淘汰（本岗要带 20 人、三种技能栈）。
2. 系统量级：只做过内部管理系统 / 单体应用 / 外包驻场 CRUD → 淘汰。
3. 一致性：简历出现"用了 Kafka/Redis"但没有任何事务、幂等、对账、补偿的描述 → 降级为"高级开发"，不进管理岗。

### 3.2 五个必问的简历疑点（电话初筛就问）

- "12+ 微服务"是你划分的还是接手时就这样？哪几个是你拆的，为什么这么拆？
- "3 年零资金差错"怎么统计的？差错定义是什么？有没有靠人工对账兜住的？
- "2 个月 → 1 周"的分子分母各是什么？是配置化带来的，还是把测试环节砍了？
- 团队 20 人里，你直接管理几人？绩效是你打还是你上级打？
- 最近一次你**否决**的技术方案是什么？对方是谁，为什么最后听你的？

### 3.3 一眼淘汰信号

- 通篇"负责/参与/主导"没有任何数字与代价。
- 把团队成果全部写成个人成果，问细节就转"我们团队"。
- 只谈技术先进性，不谈上线风险、回滚、成本。
- 5 年内换 4 家公司且每次都是"公司不行"。

## 四、面试流程（总时长约 4 小时，可分两天）

| 轮次 | 时长 | 面试官 | 考什么 | 产出 |
|---|:--:|---|---|---|
| 0 电话初筛 | 20 min | HR / 用人经理 | 硬性条件、动机、薪资、到岗时间 | 过/不过 |
| 1 技术深度 | 90 min | 用人经理 + 1 名架构师 | A/B/C 三维，白板画架构 | 技术评分表 |
| 2 管理面 | 60 min | 用人经理 + 上级 | D/E 两维，场景题为主 | 管理评分表 |
| 3 终面 | 45 min | 副总 | 业务判断、稳定性底线、资源争取 | 录用建议 |
| 4（可选）背景核实 | 20 min | HR | 团队规模、量化口径、离职原因 | 核实记录 |

**规则**：每轮独立打分、独立提交，不许面试官之间先对口径；终面前只看分数与评语，不看前一轮结论，避免锚定。

## 五、面试题库（按维度，含追问链与评分锚点）

> 用法：每个维度挑 2–3 题，**至少追到第二层**。只答第一层（背概念）记 3 分；能给出取舍与代价记 4 分；能给出自己踩过的坑与验证方式记 5 分。

### A. 架构与异构治理（30%）

**A1｜画图题（必考，15 min）**
"画一个你负责过的系统：两种以上技术栈、两个以上团队、有外部系统接入。标出边界、协议、谁负责哪块。"
- 追问 1：这个边界上出过什么事故？怎么发现的？
- 追问 2：如果一侧要改协议字段，流程是什么？谁拍板？怎么灰度？
- 追问 3：防腐层具体做了什么？为什么不是让两边直接调？
- 锚点：能画出"谁调谁、什么协议、失败怎么处理"= 4 分；只画方框和箭头、说不清失败路径 = 2 分。

**A2｜决策题（核心题）**
"你的 C 撮合引擎团队提出用 Java 重写、统一技术栈，理由是招人难、维护成本高。你是负责人，批不批？"
- 追问 1：你怎么论证"不重写"？拿什么数据说服老板？
- 追问 2：如果不批，怎么解决"招人难"这个真实问题？
- 追问 3：什么条件下你会同意重写？
- 锚点：只有"GC 不行"= 3 分；能给出**重写悬崖、双跑并行、按模块灰度、退出条件** = 5 分；一味说"技术栈统一是趋势" = 淘汰。

**A3｜边界题**
"12+ 微服务，你怎么划边界？现在有两个服务互相调用、共享同一个库表，你怎么治？"
- 追问：共享库表先拆谁？拆的过程中怎么保证不停机？
- 锚点：能说"按业务能力而非按表拆""先加接口后停直连""用事件替代同步双写" = 4 分以上。

**A4｜集成题**
"9 家外部系统（银行、物流、税务、签章），每家有独立鉴权与报文。新接一家要 2–3 周，你怎么压到 3–5 天？"
- 追问 1：统一适配层抽象哪几段？哪些**不能**统一？
- 追问 2：外部接口超时/返回乱码/重复回调，分别怎么处理？
- 追问 3：可用率 99.95% 怎么算的？分子分母是什么？
- 锚点：能说出"鉴权→请求→重试→熔断→结果转换"五段并指出各家差异只能配置化 = 4 分。

**A5｜多租户题**
"100+ 客户，每家的交易规则、审批流、单据模板都不同。早期靠加开关和改代码，现在怎么收敛？"
- 追问 1：能力集 / 套餐 / 客户参数三层为什么不能直接"参数挂客户"？
- 追问 2：配置错了导致生产事故，怎么回滚？怎么防？
- 追问 3：规则引擎（如 Drools）性能与可测试性怎么保证？规则谁来写？
- 锚点：能讲"代码分支 → 配置"的迁移路径与**测试覆盖难题** = 5 分；只说"用规则引擎" = 3 分。

### B. 资金与数据一致性（20%）

**B1｜长事务题（必考）**
"一笔交易跨 1–3 个月、10+ 状态、每次状态变更同步 4–6 个下游。怎么保证不丢不重、任意时刻可回溯？"
- 追问 1：Saga 的补偿写在哪？补偿失败怎么办？
- 追问 2：状态机怎么防止非法跃迁？谁定义状态？
- 追问 3：事件溯源存全量，数据量和查询怎么处理？
- 锚点：能画出"正向操作 ↔ 对等补偿"并说明**幂等键** = 5 分；只说"用 Saga" = 3 分。

**B2｜原子性题**
"扣款成功、消息没发出去，下游没收到。怎么保证？"
- 锚点：本地消息表 + 同库同事务 + 定时补偿 + 消费幂等，四件齐全 = 5 分；答"加重试" = 2 分。

**B3｜选型题**
"资金扣减为什么不用 Redis 分布式锁？什么场景可以用？"
- 锚点：能说清锁租约过期、主从切换丢锁、业务与锁不在一事务 = 4 分以上；答"Redis 性能好所以用" = 淘汰。

**B4｜自证题**
"你说三年零资金差错，怎么证明不是运气或人工兜底？"
- 追问：对账频率？差异处理流程？有没有做过资金链路演练？
- 锚点：能给出**监控指标 + 日终对账 + 差异工单 + 演练**四层 = 5 分。

### C. 稳定性与排障（15%）

**C1｜容量题**
"大促流量是平时 3 倍，你怎么做容量规划？扩了机器反而更慢，为什么？"
- 追问：压测基线怎么取？瓶颈先看哪几个指标？扩容打穿数据库的根治闭环是什么？
- 锚点：能说"先压测找单机拐点 → 算所需实例 → 找共享瓶颈（DB/连接池/锁）→ 限流兜底" = 4 分以上。

**C2｜限流题**
"接口限流阈值你按什么定？拍 1000 QPS 行不行？"
- 锚点：能按"线程池 × 单请求耗时 × 安全系数"推导，并区分拒绝策略与排队 = 5 分；答"看监控" = 2 分。

**C3｜排障题（给现象，要顺序）**
"线上 CPU 100% / 接口突然从 200ms 变 2s / Java 进程消失，分别怎么查？"
- 锚点：能给出 top → jstack → GC → 日志 → 链路 的具体顺序与判据 = 4 分；只会说"看日志" = 2 分。

**C4｜机制题**
"线上稳定性治理，靠什么？换一个团队你还能做到吗？"
- 锚点：目标线 + 上线评审/压测/监控/On-call + 复盘转检查项，三层齐全 = 5 分；答"大家比较努力" = 2 分。

### D. 技术管理与机制（25%）

**D1｜异构团队题（必考）**
"20 人、三种技能栈、互相读不懂代码。你的周会看什么？怎么防止'C 改一个字段、Java 全崩'？"
- 追问 1：C 团队负责人不服你，你怎么处理？
- 追问 2：核心模块只有一个人会，你怎么解？
- 锚点：能说"契约双方评审 + 我拍板 + 桥接层日志作为第一排查依据 + owner/backup 双人制" = 5 分。

**D2｜流程题**
"你设了六道评审闸门，怎么保证不走过场？举一个被拦下来的真实例子。"
- 追问：闸门会不会拖慢交付？业务绕过评审直接找老板，你怎么办？
- 锚点：有**表单留痕 + 不通过不流转 + 具体拦截案例** = 5 分；只说"我们流程很规范" = 2 分。

**D3｜技术债题**
"技术债怎么分类？怎么排期？业务说没时间还，你怎么说服？"
- 锚点：能分"影响正确性 / 拖交付速度 / 只影响观感"三类，并给出**量化话术**（每新增一页放大多少成本）= 5 分。

**D4｜绩效题**
"团队里有人高薪低产、有人很强但不服管、有人一年没成长，分别怎么处理？"
- 追问：绩效四维怎么配比？技术债偿还怎么计入？你开除过人吗？
- 锚点：有具体动作与谈话记录，不回避"劝退" = 4 分以上；全是"多沟通多鼓励" = 2 分。

**D5｜冲突题（压力题）**
"业务要在 2 周上线一个定制需求，你评估至少 6 周。老板已经答应了客户。你说什么？"
- 锚点：先给边界（哪部分 2 周可上、哪部分不行）→ 再给替代路径与代价 → 最后要决策 = 5 分；直接说"做不了"或直接答应 = 2 分。

### E. 业务与客户价值（10%）

**E1**："讲一个你推动的技术改进，能折算成钱或工期的。分子分母怎么来的？"
**E2**："客户要求私有化部署、监管要求数据不出域，和你的多租户架构冲突，怎么办？"

### F. AI 能力（加分，不计入通过线）

**F1**："Dify、LangChain、自研，你怎么选？数据敏感度怎么分层？"
**F2**："RAG 答不准，你的排查顺序是什么？"（解析质量 → 切片 → 召回 → 重排 → Prompt → 模型）
- 锚点：能区分"工程问题"与"模型问题"，并承认边界 = 4 分；把 RAG 说成万能 = 2 分。

**一票否决**：A < 3 或 D < 3；或发现简历造假；或拒绝回答"你否决过什么"。

## 七、定级与两种编制方案

| 方案 | 编制 | 适用 | 风险 |
|---|---|---|---|
| **A · 1:1 替换** | 技术经理 1 人（带 20 人） | 能招到同能力人 | 市场稀缺，周期长；到位前决策真空 |
| **B · 拆分** | 架构负责人（不带人）+ 研发主管（带人） | 招不到复合型，或预算受限 | 两人边界必须写清，否则互相甩锅；跨栈协调成本上升 |

**方案 B 的边界写法**：架构负责人管"技术决策、契约、评审技术闸门、稳定性"，研发主管管"排期、人力、绩效、跨部门"。**资金链路方案与线上 P0 由架构负责人拍板**，避免双头。

**降级录用规则**：技术强但管理弱 → 按"高级架构师"录用，6 个月内考核是否补上管理；管理强但技术浅 → 不录，本岗技术决策权重太高。

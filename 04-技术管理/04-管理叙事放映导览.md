## 二、逐页骨架

### 22 · 六道评审闸门

- **一句话主张**：质量是设计出来的，不是测出来的；六个关键节点，**不通过不流转**。
- **六道闸门**：
  1. 需求统一收口 —— 业务需求统一入口；原型 + 需求规格说明书先行；**过审才进需求池**
  2. 业务设计评审 —— 领域边界、状态机、异常流程；权限与数据口径对齐；对《通用业务设计规范表》
  3. 技术方案评审 —— 选型与接口契约、数据模型与容量预估、性能与兼容性
  4. QA 验收 —— 验收用例取自原型页；冒烟 + 回归 + 边界异常；不通过不许提测发布
  5. 产品发布评审 —— 上线清单与发布窗口、灰度与回滚预案、值班与监控告警确认
  6. 系统移交 —— 文档 + 部署手册、监控告警 + 运维培训；**移交验收才算交付完成**
- **落地载体（被追问时报得出名字）**：需求 / 技术统一收口评审表、系统需求 / 设计 / 升级评审记录表、产品发布评审记录表、系统移交评审记录表（QA 版）、通用业务设计规范表、产品线研发规范执行制度、UI 与需求评审规范、项目跟踪管控表、早会制度、部门奖惩制度。
- **为什么前置**：返工最大的成本不是改代码，是**在错误的理解上跑了两周**——闸门在前把不确定性挡在开发之前。
- **追问答法**：「规范会不会拖慢交付」→ 规范的目标是减少返工，返工才是最大成本。

### 23 · 多项目并行管控

- **一句话主张**：并行不等于平均用力，而是**保证关键路径不断供**。
- **四态看板**：需求池（收口去重，缺材料不排期）→ 已评审（两道评审过、工作量与依赖明确，按价值与风险排序）→ 开发中（一人负责到底，每日站会只过阻塞点）→ 待发布（QA 验收 + 发布评审双过，回滚预案就绪）。
- **同期并行域（脱敏报类别名）**：供应链平台、仓储监管、竞价交易、商品管理、权限中心、合同中心、发票管理、门户栏目管理、产能预售、天然气报价、跨境商贸通对接、三方仓储对接、缓存优化、视频监控。
- **唯一纪律**：任何时候都答得出「现在有几个在途、卡在谁手上、哪条是关键路径」。
- **加分句**：排期表不是甘特图美术作业，它只服务一个判断——**这个需求插进来会挤掉谁**；答不出来就不插。

### 24 · 年度技术建设规划

- **一句话主张**：一年做四件事，按重要性排——**复用 · 合规 · 稳定 · 智能**。
- **四线**：
  1. 架构重构与低代码 —— 登录 / 开户 / 认证 / 签章模块化组件化，定义模块职责与使用规则；推进配置化与低代码（流程编排、界面装修设计器、表单设计器）
  2. 系统安全与合规 —— 数据库敏感数据加密、漏洞扫描、代码混淆、SQL 注入防御；客户端强密码策略 + 双因子认证；对标等保三级
  3. 稳定性与性能（目标线）—— 重大故障 ≤1 次/年、中等故障 ≤3 次/年、首页打开 <1.5 秒、核心业务并发 ≥1000/秒；手段 = 上线评审 + 压测 + 监控告警 + 故障复盘
  4. AI 创新与智能化 —— 证件 / 卡片 / 单据智能识别；对接第三方大模型；探索火警、预警、防盗、形变、作业行为识别（与仓储监管、视频监控结合）
- **口径护栏**：故障次数与并发是**当时设定的团队目标 / 部门考核指标**，按季度跟踪收敛，不是长期达成值。
- **加分句**：低代码不是炫技，是面对一堆中小客户、每家都要定制——不把定制变成配置，交付成本降不下来。

### 25 · 团队赋能与技术沉淀

- **一句话主张**：周技术分享**只讲真问题，不讲概念**；分享不是目的，沉淀才是。
- **分享主题（全部来自真实问题）**：CPU 突然变高的定位步骤｜POST 请求失败如何定位｜低代码引擎技术白皮书（百度 / 阿里低代码）｜可视化规范 / UI 规范｜对话框与抽屉的使用场景｜工作台应该怎么设计｜采购供应链端到端全景蓝图｜国产化信创改造方案｜从「买软件」到「卖成果」。
- **五类沉淀资产**：
  - 方法资产：采购供应链端到端全景蓝图规划方案、国产化信创改造方案
  - 框架资产：Q-Quick 快速开发框架
  - 原型资产：仓单交易管理端、新版客户端、会员管理、门户（1+N）
  - 产品资产：商城三端（H5 商城 / 店铺管理端 / 平台管理端）、大屏源码
  - 知识资产：性能排查手册、故障复盘库、产品测试标准库
- **收束句**：新人不再从零摸索，团队不依赖任何一个人的记忆——技术管理的关键，是**把个人经验变成团队能力**。
- **心态金句**：从「买软件」转向「卖成果」——不是把功能交付出去，是把客户的经营结果交付出去。

### 26 · 故障管理闭环

- **一句话主张**：故障不可怕，可怕的是同一个问题重复发生。
- **五步**：止损（先恢复业务再定位，回滚 / 降级，动作留痕）→ 定位（日志 / 监控 / 操作记录三件套保全，还原时间线与影响面，区分人为 / 设计 / 流程根因）→ 复盘会（对事不对人，P0 / P1 限时复盘，结论可执行可验证）→ 故障报告（原因 / 措施 / 预防方案 / 责任人，跟踪到改进项全部关闭，入知识库）→ **回灌规范**（写成规范条目或检查项，能自动化的做成告警）。
- **复盘实例（已脱敏）**：某股份制银行客户端无法签到 → 会话与鉴权链路｜待交收账户资金为负 → 清算与账务时点口径｜仓单确权 / 发票红冲 → 单据状态机与冲正逻辑｜某交易中心开户流程中断 → 流程编排与外部依赖｜三方仓储对接数据不一致 → 接口契约与自动对账。
- **结果**：被动响应占比 45% → 15% 以下；线上问题团队独立处理 80%；凌晨被叫起月均 8 次 → 2 次；重复类故障显著下降。
- **讲法**：重点落在「对事不对人」与「回灌规范」——这才是管理成熟度。

### 27 · 团队机制

- **一句话主张**：用机制替代亲力亲为；中小民企资源不冗余，所以**机制轻、落地狠**。
- **20 人四梯队（必须脱口而出）**：3 人 C 撮合内核｜6 人 Java 业务中台｜5 人 Vue 前端｜5 人测试 / 质量保障；向副总汇报。
- **四个机制**：
  - 培养：师徒制（新人配导师，3 个月独立接模块）+ 主链路强制代码评审 + 周技术分享
  - 考核：交付 40% / 质量 30% / 工程贡献 20% / 成长 10%；**技术债偿还计入工程贡献**
  - 梯队：每核心模块 owner + backup 双人制，休假不断线，模块无单点依赖
  - 效率：原型库 + 功能开发 skill，新人照着 skill 可独立交付典型功能
- **结对辅导（按人定向带教）**：Java 服务端、Vue 前端补齐开发语言能力；C++ / Qt 客户端定向攻坚；明确新培养核心储备成员目标。
- **目标线**：评估节省工作量 ≥5 人月（规范建设 + 复用）；自动化测试覆盖率考核线 ≥20%，**核心模块单测**另设 CI 门禁起始线 ≥30%（20% 是「面」、30% 是「点」，两个数都报但别混）。
- **管理三件套**：On-call 轮值（主副双岗 + 四级 SLA）· 技术债台账（20% 带宽原则固定偿还）· 接口契约治理（管连线不管黑盒）。
- **效果**：被动响应 45% → 15% 以下，凌晨被叫起月均 8 次 → 2 次。
- **被问加班**：紧急情况该上就上，但日常靠机制保效率——加班是例外，不是常态。

### 28 · 人才培养与储备

- **一句话主张**：不让任何一块技术成为单点。
- **三条 Track**：Java 服务端（能独立承接业务中台模块）｜Vue 前端（统一组件与交互规范，能独立交付完整页面）｜C++ / Qt（核心储备成员接棒，消除单点依赖）。
- **三条目标线**：

| 目标维度 | 要达成的结果 | 口径（当时设定的团队目标） |
|---|---|---|
| 研发效能 | 完善研发 / 测试标准规范，减少线上 Bug 与返工成本 | 评估节省工作量 ≥5 人月 |
| 测试与自动化 | 建立产品测试标准库，推进程序化测试 | 自动化覆盖率考核线 ≥20% |
| 成果沉淀 | 申报技术专利、取得多项软著，经验沉淀为可复用资产 | 专利 / 软著 / 原型库 |

- **加分句**：中小公司最容易项目做完就散了；专利和软著不只是荣誉，它逼着我们把方案写清楚、能复用——这是团队能力的沉淀方式。

### 29 · 技术整改十一项总览（地图页，只讲主线）

- **一句话主张**：不是十一个孤点，是一条主线——**把「每次定制都要改代码」变成「配置与契约」**。
- **五条腿**：
  1. 对内多变 → 配置化：国际化配置（行业词库 + 多语言层）、功能授权码（一套代码按付费开 capability）、交收场景三元组（顺序 × 付款 × 保证金模板化）
  2. 对外集成 → 开放：统一支付中心（业务与支付解耦、渠道插件化）、DS + MID 网关（破解异构语言通信、星型接入）、统一开放网关（第三方规范 + 自助接入）
  3. 底线信任 → 合规：等保 + 信创（安全与国产化双达标）、数据安全脱敏（一处声明处处生效）
  4. 能力复用 → 提效：统一基础模块工具（五能力公共中台）、规范脚手架 + AI Skill（两套 Skill 库共 12 个）
  5. 数据可信 → 一致：缓存服务改革（CDC 变更总线 + 缓存自动失效）
- **收束句**：技术经理的价值，是把不变的核心收敛进底座，让变化发生在配置层、把重复交给 AI。
- **用法**：这页只给框架，不展开细节；追问细节再翻 30 / 31 / 32 三张明细页，或回本目录 `01-技术整改十一项与落地.html`。

### 30 · 配置化与契约（明细页一）

- **一句话主张**：差异只有两种来源——**客户差异走配置，生态差异走契约**。
- **左栏·对内多变 → 配置化**：01 国际化（两层词典 + 统一取词，名词定制天级 → 小时级）｜02 授权码（签名的能力清单 + 菜单裁剪与接口鉴权双保险，一套代码交付所有版本）｜03 交收三元组（散点参数 → 5 类模板 + 安全覆盖项，测试从"全组合"变"模板 + 增量"）。
- **右栏·对外集成 → 契约**：04 统一支付（业务只发指令收结果、渠道插件化、2PC 预检，接入周级 → 天级）｜05 DS+MID（MID 屏蔽报文/编码/加密，DS 统一契约，网状变星型）｜07 开放网关（统一鉴权 / 标准信封 / 错误码字典 / 重试规范，第三方自助接入）。
- **讲法**：三组只挑一组深入（首选授权码），其余一句带过；被追问数字回 `02A-技术管理补充件.md` 第三部分速查表。

### 31 · 合规与数据可信（明细页二）

- **一句话主张**：合规与数据一致不是成本项，是"敢碰钱、能进国企"的入场券。
- **06 等保 + 信创**：分区分域 / 最小权限 + 双因子 / 全链路审计；信创适配层（MySQL↔GaussDB、Tomcat↔TongWeb、CentOS↔openEuler），L2 / L3 分级，"国产化不降级"成为投标差异化卖点。
- **08 数据脱敏**：元数据分级打标 → 注解式统一脱敏引擎 → 四类场景分治（展示 / 接口按角色 / 日志切面 / 测试出口）+ 动态脱敏视图兜底，明文访问全程留痕。
- **11 缓存改革（本页大杀器，值得深讲）**：谁改库谁删缓存；代码路径**先更 DB 再 DEL（绝不 SET 新值）**；非代码改库走日志监听（MySQL 走 Canal，openGauss 无 binlog 走逻辑解码 / WAL）；删哪些 key 放规则配置表；合并 + 防抖 + 前缀失效 + 全 key 过期兜底。
- **加分句**：换数据库不影响缓存链路，正好呼应等保信创。

### 32 · 复用提效与底层逻辑（明细页三）

- **一句话主张**：把重复建设收敛为公共能力中台、把重复劳动交给 AI——**提效不依赖任何个人**。
- **09 统一基础模块**：文档转换 / 翻译（私有化，数据不出内网）/ 视频（GB28181·RTSP·RTMP）/ 审批流 / OCR，每个能力独立微服务只暴露 API，新项目从"重复选型对接"变"调 API"。
- **10 规范脚手架 + AI Skill**：规范文档化进仓库（规范即系统提示词，人和 AI 读同一份）+ 标准页面骨架 + 两套 Skill 库共 12 个（原型库管"页面怎么长"、开发库管"功能怎么落地"、check 类负责交付前验收）；度量 = 一页标准管理页从 1–2 小时到"几分钟出稿 + 人工校对"。
- **收束句**：技术经理的价值，是把不变的核心收敛进底座，让变化发生在配置层、把重复交给 AI。
- **用法**：三张明细页**只在被追问时翻**；不追问就停在 29，别主动展开成十一项清单。

### 33 · 团队成果总账

- **一句话主张**：不讲单个项目，讲四本账——交付有节奏、质量有底线、机制能自转、能力能传承。
- **四本账**：

| 账 | 内容 |
|---|---|
| 交付 | 12+ 微服务业务中台从 0 到 1 建成；销售端 + 采购端双平台并线交付；9+ 外部系统对接（银行 / 仓储 / 税务 / 监管） |
| 质量 | 3 年+ 零资金差错（交易 / 结算 / 清算）；核心接口 P95 200ms 内；外联接口平均可用率 99.95% |
| 机制 | On-call 轮值 · 技术债台账 · 接口契约治理全部落地；被动响应占比 45% → 15% 以下；故障报告 + 复盘闭环，根因回灌规范 |
| 能力 | 20 人四梯队、核心模块无单点依赖；团队独立处理 80% **线上**问题；沉淀排查手册 / 原型库 / 开发框架 / 专利与软著 |
